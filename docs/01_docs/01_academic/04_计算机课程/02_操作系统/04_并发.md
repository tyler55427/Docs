# 四、并发

## 4.1 并发原理

**并发：** 同一时间段内活动的进程/线程，交替地共享相同的资源

### 并发的基本特征

- **异步性**：执行速度不可预测，多道程序系统的基本特征
- **其他进程的活力**：OS 的处理中断、OS 的调度策略
- **问题**：共享资源危险、OS 对资源分配已难以最优、调试错误困难（不可再现）

### 竞态（Race Condition）

- 并发环境
- 多个进程共享数据
- 多进程读且至少有一个进程写
- 共享数据产生错误结果，取决于进程执行的相对速度

**发生条件：**

- 并发执行
- 共享资源
- 修改操作

### 进程间的相互作用

- **间接作用**：共享
- **直接作用**：通信

## 4.2 互斥

### 基本概念

- **互斥 (mutual exclusion)**：多个进程需要访问一个共享的资源时，任何时候只能有一个访问这个资源
- **临界资源 (critical resource)**：不可同时使用的资源
- **临界区 (critical section)**：访问临界资源的那部分代码
- **死锁 (deadlock)**：一组进程中，每个进程都无限等待该组进程中另一进程所占用的资源
- **饥饿 (starvation)**：一组进程中，某个或某些进程无限等待该组进程中其他进程所占用的资源

### 解决互斥的条件

1. 具有相同资源或共享对象的临界区的所有进程中，一次只允许一个进程进入临界区（强制排它）
2. 在非临界区停止的进程不干扰其他进程（充分并发）
3. 没有进程在临界区中时，任何需要访问临界区的进程必须能够立即进入（空闲让进）
4. 不允许出现一个需要访问临界区的进程被无限延迟（有限等待）防止饥饿
5. 相关进程的执行速度和处理器数目没有任何要求或限制（满足异步）
6. 进程不能进入临界区应该立即释放处理器，防止进程忙等待（让权等待）

## 4.3 软件互斥方法

### Dekker 算法

- 避免"无原则"的礼让（将延时换为轮到自己）
- 规定各进程进入临界区的进入顺序
- 局部变量 flag 表示自己的意愿
- 局部变量 turn 决定顺序

```c
boolean flag[2]; int turn;
void P0() {
    while (true) {
        flag[0] = true;
        while (flag[1]) {
            if (turn == 1) {
                flag[0] = false;
                while (turn == 1) /* do nothing */;
                flag[0] = true;
            }
        }
        /* critical section */
        turn = 1;
        flag[0] = false;
        /* remainder */
    }
}
```

### Peterson 算法

- 简单，无轮流问题
- flag 与 turn 含义一致
- 令 turn = 别人，只有 flag[别人] ∧ turn=别人 时，才循环等待

```c
boolean flag[2]; int turn;
void P0() {
    while (true) {
        flag[0] = true;
        turn = 1;
        while (flag[1] && turn == 1) /* do nothing */;
        /* critical section */
        flag[0] = false;
        /* remainder */
    }
}
```

## 4.4 硬件互斥方法

- **中断禁用**
  - 单 CPU，不能用于多核处理器
  - 进程访问临界资源时，不能被中断，保证互斥
  - 使用开/关中断指令
- **专用机器指令**
  - testset（比较交换指令）：原子比较并交换
  - exchange（交换指令）：原子交换寄存器与内存值

## 4.5 常用并发机制

| 并发机制   | 说明                                               |
| :--------- | :------------------------------------------------- |
| 二元信号量 | 取值只为 0 和 1 的信号量                           |
| 互斥量     | 类似二元信号量，但要求为其加锁和解锁的须是同一进程 |
| 条件变量   | 一种数据类型，用于阻塞进程/线程，直到特定条件为真  |
| 事件标志   | 用于同步机制的内存字，其每个位关联不同的事件       |
| 自旋锁     | 进程在一无条件循环中执行，等待锁变量值变为可用     |

### 信号量

- **信号量组成**
  - 一个整型变量
  - 三个原子操作：
    - 初始化
    - P(down)
      $$
      P/\text{down}: \begin{cases} \text{信号量值}-1 \\ \text{若变为负数，进程阻塞，加入阻塞队列} \end{cases}
      $$
    - V(up)
      $$
      V/\text{up}: \begin{cases} \text{信号量值}+1 \\ \text{若是正数，使 P 阻塞进程解除} \end{cases}
      $$
- **信号量实现互斥**
  - n 个进程访问同一资源
  - 信号量 S 初始值为 1
  - 进程进入临界区前执行 P，离开后执行 V
- **信号量实现同步**
  - 进程间共同合作完成任务
  - 信号量 S 初始值 0 或负值
  - a 后执行 V，b 前执行 P

### 管程

- **主要特点**
  - 本地变量只能由管程过程访问（封装）
  - 进程通过调用管程过程进入管程（调用）
  - 每次只能一个进程执行相关管程的过程（互斥）
- **同步操作**
  - `cwait(c)`：等待发出信号 c，发出信号时无进程等待，则继续
  - `csignal(c)`：发出信号 c

### 消息传递

- **原语**
  - `send(目的, 信息)`
  - `receive(源, 信息)`
- **消息传递组合方式**|            方式            |  send  |   receive   | 适用场景           |
  | :-------------------------: | :----: | :----------: | :----------------- |
  |   阻塞 send，阻塞 receive   |  阻塞  |     阻塞     | 紧密同步（打电话） |
  |  无阻塞 send，阻塞 receive  | 不阻塞 | 阻塞至有消息 | 收发短信（最有用） |
  | 无阻塞 send，无阻塞 receive | 不阻塞 |    不阻塞    | 危险，信息可能丢失 |
- **寻址方式**
  - 直接寻址：指定进程 ID
  - 间接寻址：利用共享邮箱保管

## 4.6 经典同步问题

### 读者-写者问题

- **读者优先（信号量）**
  ```c
  int readcount;
  semaphore x = 1, wsem = 1;

  void reader() {
      while(true) {
          P(x);
          readcount++;
          if (readcount == 1) P(wsem);
          V(x);
          READUNIT();
          P(x);
          readcount--;
          if (readcount == 0) V(wsem);
          V(x);
      }
  }

  void writer() {
      while(true) {
          P(wsem);
          WRITEUNIT();
          V(wsem);
      }
  }
  ```
- **写者优先（信号量）**
  ```c
  int readcount, writecount;
  semaphore x = 1, y = 1, z = 1, rsem = 1, wsem = 1;

  void writer() {
      while(true) {
          P(y);
          writecount++;
          if (writecount == 1) P(rsem); // 第一个写者阻止新读者进入
          V(y);
          P(wsem);
          WRITEUNIT();
          V(wsem);
          P(y);
          writecount--;
          if (writecount == 0) V(rsem); // 最后一个写者恢复读者进入
          V(y);
      }
  }

  void reader() {
      while(true) {
          P(z);
          P(rsem);
          V(z);
          P(x);
          readcount++;
          if (readcount == 1) P(wsem); // 第一个读者阻止写者进入
          V(x);
          V(rsem);
          READUNIT();
          P(x);
          readcount--;
          if (readcount == 0) V(wsem); // 最后一个读者恢复写者进入
          V(x);
      }
  }
  ```

### 生产者-消费者问题

- **信号量解法**
  ```c
  const int sizeofbuffer = /* 缓冲区大小 */;
  semaphore s = 1, n = 0, e = sizeofbuffer;

  void producer() {
      while (true) {
          produce();
          semWait(e);
          semWait(s);
          append();
          semSignal(s);
          semSignal(n);
      }
  }

  void consumer() {
      while (true) {
          semWait(n);
          semWait(s);
          take();
          semSignal(s);
          semSignal(e);
          consume();
      }
  }
  ```
- **消息传递解法**
  ```c
  const int capacity = /* 缓冲区容量 */;
  message null = /* 空消息 */;

  void producer() {
      message pmsg;
      while (true) {
          receive(mayproduce, pmsg);
          pmsg = produce();
          send(mayconsume, pmsg);
      }
  }

  void consumer() {
      message cmsg;
      while (true) {
          receive(mayconsume, cmsg);
          consume(cmsg);
          send(mayproduce, null);
      }
  }
  ```
- **管程解法**
  ```c
  monitor boundedbuffer {
      char buffer[N];
      int nextin, nextout;
      int count;
      cond notfull, notempty;

      void append(char x) {
          if (count == N) cwait(notfull);
          buffer[nextin] = x;
          nextin = (nextin + 1) % N;
          count++;
          csignal(notempty);
      }

      void take(char x) {
          if (count == 0) cwait(notempty);
          x = buffer[nextout];
          nextout = (nextout + 1) % N;
          count--;
          csignal(notfull);
      }
      { nextin = 0; nextout = 0; count = 0; }
  }
  ```
