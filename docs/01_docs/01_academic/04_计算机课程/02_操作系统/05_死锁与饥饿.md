# 五、死锁与饥饿

## 5.1 死锁原理

**定义**

一个进程集合中的每个进程都在等待只能由该组进程中其他进程才能引发的事件（释放占有资源/进行某项操作）

死锁是多个进程因竞争资源且推进顺序不合理而造成的一种僵局，若无外力作用，这些进程将永远不能再向前推进。

- **资源分类**
  - 可重用资源：一次只能一个进程使用，不会耗尽（处理器、内存、磁盘）
  - 可消耗资源：生产并消耗的资源，无数量限制（中断、信号、消息）

## 5.2 资源分配图

- **□**：资源类
- **·**：资源实例（个数）
- **()**：进程

**占用边（分配边）：** 资源实例指向进程的有向边
**请求边（申请边）：** 进程指向资源类的有向边

### 死锁定理

- 没有环路没有死锁
- 有环路不一定死锁
- 若环路时，每个资源类只有一个资源实例 ⇔ 环路有死锁

## 5.3 死锁的必要条件

- **死锁必要条件**
  - 互斥：有资源独立使用
  - 占有且等待：进程已有资源，并提出新的资源要求
  - 不抢占：进程的资源未使用完不会释放
  - 环路等待条件：循环等待
- 四个条件是死锁的必要条件（3+1 为充要条件）

## 5.4 死锁预防

打破产生死锁的条件：

- **打破互斥**：虚拟化资源（如同时读），适用：资源分成多份，操作不影响
- **打破占有且等待**：要求一次性申请全部资源，优：简单、易实现、安全，缺：进程延迟执行、资源严重浪费
- **打破不抢占**：抢占进程占有的资源（优先级），适用：资源容量保存完好，缺点：实现复杂、代价大、频繁申请/释放资源、系统开销大
- **打破环路等待**：每个进程任何时刻只能占有一个资源，对所有资源按类型进行线性排队，进程申请资源必须严格按资源序号递增，缺点：排序困难；资源浪费；可能低效

## 5.5 死锁避免

### 银行家算法

**资源向量：** $R = (R_1, ..., R_n)$，$R_i$ 为第 $i$ 种资源的总数

**可用向量：** $V = (V_1, ..., V_m)$，$V_i$ 为第 $i$ 种资源的可求数

**进程—资源需求矩阵：** $C_{ij}$：进程 $i$ 对资源 $j$ 的请求数

**进程—资源分配矩阵：** $A_{ij}$：已分配给进程 $i$ 的资源 $j$

**模型性质：**

- $R_j = V_j + (A_{1j} + ... + A_{nj})$
- $C_{ij} \le R_j$
- $A_{ij} \le C_{ij}$

**安全状态：** 至少有一个执行时序，使当前所有进程都能运行至结束

**银行家算法实现：**

```c
if (S.alloc[i][*]+request(*) > claim[i,*])
    return ERROR;
else if (request(*) > S.available[*])
    return SUSPEND_PROCESS;
else {
    X.alloc[i][*] = S.alloc[i][*] + request(*);
    X.available[*] = S.available[*] - request(*);
    if safe(X) {
        S.alloc[i][*] = X.alloc[i][*];
        S.available[*] = X.available[*];
    } else return SUSPEND_PROCESS;
}
```

**安全状态判定：**

```c
boolean safe(state s) {
    int curravail[m];
    curravail[*] = s.available[*];
    rest = (all process);
    possible = true;
    while (possible) {
        寻找一进程 Pk 使：claim[k][*]-alloc[k][*] <= curravail[*];
        if (found) {
            curravail[*] = curravail[*] + alloc[k][*];
            rest = rest - {Pk};
        } else possible = false;
    }
    return (rest == null);
}
```

**银行家算法优缺点：**

- 优点：
  - 比死锁预防限制少；
  - 无须死锁检测中的资源剥夺和进程重启
- 不足：
  - 事先声明每个进程请求的最大资源；
  - 仅考虑进程互相无关情况；
  - 分配的资源数目必须是固定的；
  - 在占有资源时进程不能退出

## 5.6 死锁检测

- **检测时机**
  - 资源申请时：尽早检测出死锁
  - 周期性检测
  - CPU 使用率低时（死锁"好像"发生）
- **检测方法**
  - 单个资源实例：死锁定理
  - 多个资源实例：银行家算法
- **恢复方法**
  - 抢占法：连续抢占资源直至死锁消除
  - 回滚法：回滚至检查点，重启
  - 杀死进程法：杀死进程直至死锁消除
  - 取消所有死锁进程：最常用

## 5.7 综合死锁策略

把资源划分为不同类：

- 可交换空间：进程交换所用外存中的存储块
- 进程资源：可分配的设备，如磁带设备和文件
- 内存：可按页或段分配
- 内部资源：I/O 通道

为预防在资源类之间由于循环等待产生死锁，可使用线性排序策略。

## 5.8 哲学家就餐问题

- **问题描述**
  - 5 个人，动作：思考、吃
  - 要求用 2 把叉子吃
  - 餐厅只有 5 个座位和 5 把叉
- **信号量解法（可能死锁）**

```c
semaphore fork[5] = {1,1,1,1,1};
void philosopher(int i) {
    while (true) {
        think();
        P(fork[i]);
        P(fork[(i+1) % 5]);
        eat();
        V(fork[(i+1) % 5]);
        V(fork[i]);
    }
}
```

- **信号量解法（不会死锁，限制4人）**

```c
semaphore fork[5] = {1,1,1,1,1};
semaphore room = 4;
void philosopher(int i) {
    while (true) {
        think();
        P(room);
        P(fork[i]);
        P(fork[(i+1) % 5]);
        eat();
        V(fork[(i+1) % 5]);
        V(fork[i]);
        V(room);
    }
}
```

- **管程解法**

```c
monitor dining_controller;
cond ForkReady[5];
boolean fork[5] = {true};

void get_forks(int pid) {
    int left = pid;
    int right = (pid + 1) % 5;
    if (!fork[left])
        cwait(ForkReady[left]);
    fork[left] = false;
    if (!fork[right])
        cwait(ForkReady[right]);
    fork[right] = false;
}

void release_forks(int pid) {
    int left = pid;
    int right = (pid + 1) % 5;
    if (empty(ForkReady[left]))
        fork[left] = true;
    else
        csignal(ForkReady[left]);
    if (empty(ForkReady[right]))
        fork[right] = true;
    else
        csignal(ForkReady[right]);
}
```
