# 规范标准：

## 常用符号

✅、⚠️、❌

## 目录文件命名

目录文件命名小写，使用下划线分隔单词；项目，使用大写开头分隔单词。

可以使用`00_`

开头，可以自定义排序。

## 知识整理

markdown文件，如果手写多，就AI

- 不使用txt文件
- 每个章节创建一个`md`，用`00_base.md`作为索引
  - 一个一级标题，命名跟文件命名相同
  - 一个一级标题，命名为“目录”，内容为`-`整理的索引，包含链接和简要说明
    - 示例：`- [概述](01_概述.md) —— 操作系统的定义、发展、功能与接口`
  - 如果没有章节，一个md文件，命名为相关内容
- 标题
  - 大标题：一、二、三，跟文件描述使用同样使用一级标题
  - 小标题：1、2、3
  - 三级标题：1.1、1.2、1.3
- 图片使用`image/`而不是`assets/`
- 限制使用的知识整理的条目
  - 多条目分类用表格，简单分类用`-`
  - 杂项用`-`，提醒注意/示例用`>`
  - 方便查找用标题，简单查找用分类
  - 名词加粗，后面正常文字
- 禁止使用特殊字符

python库的使用可以考虑ipynb文件

## 文本文件

冒号后如果只有一行内容，不用换行，否则换行缩进

# python：

在`__main__`中写parser，传入main(args)

函数结果返回字典，异常处理返回空字典（让后续代码正常运行）/None（让后续代码报错）

# 算法：

- 写成md文件，包含三个内容
  - 题目名称
  - 题目描述
  - 解法
  - 备注（可选），使用 '-' 列表
- 尽量使用STL库
- 将解法写成类似leetcode的函数，但不用封装成类
- 不需要主函数，除非输入特殊
- 注释单独一行，不要跟在对应行的后面
