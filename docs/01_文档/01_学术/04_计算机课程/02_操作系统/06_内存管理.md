# 六、内存管理

## 6.1 存储管理要求

|   要求   | 说明                           |
| :------: | :----------------------------- |
|  重定位  | 逻辑地址到物理地址的转换       |
|   保护   | 进程不能对其他进程的非授权访问 |
|   共享   | 不同进程访问内存的同一区域     |
| 逻辑组织 | 模块化用户程序及数据           |
| 物理组织 | 主存与辅存的信息交换           |

### 地址类型

- **逻辑地址**：与数据在内存中的物理分配绝对无关的访问地址
- **相对地址**：逻辑地址的特例，相对当前点
- **物理/绝对地址**：数据在内存中的实际位置

### 重定位类型

- **静态重定位**：仅进程第一次载入时把内存引用全换成绝对地址
- **动态重定位**：程序指令执行时，CPU 内把逻辑地址才转换成物理地址

  - 硬件支持：基址寄存器、界地址寄存器、地址转换（计算物理地址）、安全检查

## 6.2 分区管理

- **固定分区**

  - 等长分区：进程小于分区放入；进程大于分区，覆盖放入
  - 不等长分区：放入最小空闲分区
  - 多队列与单队列：每个区维护一个队列与整体维护一个队列
- **动态分区**

  - 分数与大小均可变
  - 存在外部碎片，消除方式：压缩（需要时对进程要重定位）
- **内碎片**：已分配给进程的内存区域中未被利用的空间（固定分区、分页）
- **外碎片**：内存中空闲的小块空间，无法满足进程分配需求（动态分区、分段）

### 放置算法

|        算法        | 说明                                     | 性能               |
| :-----------------: | :--------------------------------------- | :----------------- |
| 首次适配(First Fit) | 从顶端开始扫描，找到第一个足够大的空闲区 | 简单，通常最好最快 |
| 下次适配(Next Fit) | 从上次分配结束的地方开始扫描             | 稍差于首次适配     |
| 最佳适配(Best Fit) | 扫描整个内存，找出最小的足够大空闲区     | 效果最差           |
| 最坏适配(Worst Fit) | 扫描整个内存，找出最大空闲区             |                    |

- 伙伴系统
  - 可用内存块大小为 $2^k$，$k \in [L, U]$
  - 若请求 $s < 2^U$，对分现有块；若释放，则合并相同大小的块

## 6.3 分页存储管理

### 基本概念

- 将内存划分为等长的小块，称**页框 (frame)**
- 将进程划分为若干页，页大小与页框大小相等
- 进程加载时，所有页载入可用页框（不要求连续）
- OS 维护空闲页框的列表

### 页表

- 一级页表

  - 逻辑地址：页号 + 页内偏移
  - 页表以页号为索引（页号→页框号）
  - CPU 的寄存器记录进程的页表起始物理地址、页表长度
- 二级页表

  - 将页号分成两部分：PT1、PT2（二级页号）
  - PT1 为顶级页表，以 PT1 为索引，表项指向二级页表
  - 除顶级页表外，其他页可与内外存交换
- 反向页表

  - 实际内存的每个页框对应一个页表项
  - 查找：散列映射，根据链表找到进程 ID 匹配项

### 分页地址转换

- 逻辑地址：页号 + 页内偏移
- 页表：页号 → 页框号
- 物理地址：页框号 + 页内偏移

### TLB（转换后旁缓冲区）

- 利用局部性，放入 TLB（硬件）
- 每次内存引用至少要访问两次内存
- 存储少量最常用的页表项

**TLB 使用流程：**

1. 给定逻辑地址，CPU 首先检查 TLB，判断页号是否存在
2. 若存在（命中），则直接从 TLB 中提取页框号并形成物理地址
3. 若不存在（不命中），则按普通访问页表方式工作，形成物理地址，并更新 TLB

## 6.4 分段存储管理

### 基本概念

- 将程序及数据划分为段（可变长）
- 进程载入内存，放入不同段，不要求连续，建立段表

### 段表

- 每个段项包含该段在内存中的起始物理地址、段长等
- 段表以段号为索引

### 分段地址转换

- 逻辑地址：段号 + 段内偏移
- 物理地址：段表[段号]（起始物理地址）+ 段内偏移

## 6.5 分页 vs 分段

|            | 分页           | 分段                     |
| :--------- | :------------- | :----------------------- |
| 出于       | 系统管理的需要 | 用户应用的需要           |
| 大小       | 系统固定       | 通常不固定               |
| 程序员可见 | 否             | 是                       |
| 内碎片     | 有（但小）     | 无（可通过减少段长减轻） |
| 外碎片     | 无             | 有                       |
| 共享和保护 | 不易实现       | 容易实现                 |

## 6.6 虚拟存储管理

### 概述

- **关键基础**
  1. 动态地址转换：进程中的逻辑地址在运行时动态转换成物理地址
  2. 不连续分配：进程可分成几块，这些块可分别存储到内存的不连续区域
  3. 部分加载：运行时进程下一条要执行的指令和下一个要访问的数据在内存里即可
- **虚拟存储特征**
  - 不连续性：物理内存分配的不连续
  - 部分交换：调入和调出是针对部分虚拟地址空间进行的
  - 大空间：总容量不超过物理内存和外存交换区容量之和

### 局部性与抖动

- **局部性原理**
  - 空间局部性：在执行期间的短时间内，访问的地址集合聚集在程序的某个局部区域中
  - 时间局部性：模块在程序运行期间只在某些很短的时间段被调用
- **抖动问题**
  - 内存满时，OS 驱换出某一块，并在新块使用前换入
  - 交换频繁，使 CPU 处于交换/等待
  - 局部性原理能缓解抖动问题

### 虚拟页式存储

- **页表项结构**
  `[ P/M | Other control bits | Frame number ]`
  - P = present bit（存在位）
  - M = modified bit（修改位）
  - Protection（保护码）
  - Referenced（访问位）
  - Cache（缓存位）
- **缺页处理**
  1. 将进程置于阻塞态
  2. 发出一个磁盘 I/O 请求，将逻辑地址访问的块读入内存
  3. 在执行 I/O 操作期间，分派另外一个进程运行
  4. 磁盘 I/O 完成时产生一个中断，操作系统把受影响进程置于就绪队列

### 页面置换算法

- **算法对比**
  | 算法 | 说明 | 特点 |
  | :-----------: | :--------------------------- | :----------------------- |
  | 最优算法(OPT) | 置换未来最长时间不被使用的页 | 理论基准，难以实际应用 |
  | LRU | 置换最近最少使用的页 | 性能接近 OPT，实现开销大 |
  | FIFO | 置换最早调入的页 | 存在 Belady 现象 |
  | Clock | 环形链表，选择 R=0 的页置换 | 近似 LRU，开销小 |
- **Belady 现象**：某进程所需要的页框数增加，而页错误数增加
- **时钟算法细节**：使用位 R：页被访问/页被写回后 R=1；替换时扫描，把使用位置 0，选择 R=0 的页进行置换

### 驻留集与工作集

- **驻留集**：虚拟页式存储管理中给进程分配的物理页框
- **管理策略**：固定分配（开始时确定，从各目中替换）、可变分配（驻留集大小可变，根据缺页率评估）
- **替换范围**：全局替换（内存中任意非锁定页框）、局部替换（仅在驻留集中）
- **工作集**：进程执行某段时间访问页面的集合，用 $W(t, \Delta)$ 表示，$t$ 是执行时刻，$\Delta$ 是窗口大小
- **缺页率(PFF)算法**：设置出缺页率高/低阈值，高于阈值时增加驻留大小，低于阈值时减少

### 虚拟存储软件策略

| 策略 | 问题 |
| :--------: | :------------------------------------------- |
| 读取策略 | 页何时怎么读入内存？（请求调页/预先调页） |
| 放置策略 | 读进来的页放哪？ |
| 置换策略 | 放不进得把谁写回辅存？（OPT/LRU/FIFO/Clock） |
| 清除策略 | 页何时怎么写回辅存？（请求清除/预先清除） |
| 驻留集管理 | 老进程留页问题 |
| 加载控制 | 新进程加载问题 |
