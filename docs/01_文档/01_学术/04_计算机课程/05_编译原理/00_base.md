# 一、词法分析

## 核心缩写

| 缩写 | 全称 | 中文 | 作用 |
| :--- | :--- | :--- | :--- |
| **RE** | Regular Expression | 正则表达式 | 描述单词模式，如 `[0-9]+` 匹配数字串 |
| **FA** | Finite Automaton | 有限自动机 | 词法分析的理论模型，处理字符流 |
| **NFA** | Nondeterministic FA | 非确定性有限自动机 | 带 ε（空）边的自动机，通过**子集构造法**转为 DFA |
| **DFA** | Deterministic FA | 确定性有限自动机 | 无回溯、执行效率高，可进行**最小化**优化 |

### 词法分析阶段的作用

将源代码字符串转换为**单词 token 序列**，去除了空白字符和注释，识别标识符、关键字、常量、运算符等。

# 二、语法分析

## 核心缩写

| 缩写 | 全称 | 中文 | 作用 |
| :--- | :--- | :--- | :--- |
| **CFG** | Context-Free Grammar | 上下文无关文法 | 用产生式描述语言语法，是语法分析的理论基础 |
| **AST** | Abstract Syntax Tree | 抽象语法树 | 语法分析的输出结果，忽略括号等语法细节，保留程序层次结构 |
| **LL** | Left-to-right, Leftmost derivation | 从左到右扫描，最左推导 | **自顶向下**分析方法，递归下降 parser，**LL(1) 文法**判断是考点 |
| **LR** | Left-to-right, Rightmost derivation | 从左到右扫描，最右推导 | **自底向上**分析方法，移入-归约，**LR(0)/SLR(1)** 分析表构造是核心考点 |
| **SLR** | Simple LR | 简单 LR | 最基础的 LR 分析方法，考试中常要求**手工画分析表** |
| **LALR** | Look-Ahead LR | 向前看 LR | Bison/Yacc 默认使用的分析器，比 SLR 能力强且状态数少 |

### 语法分析阶段的作用

将 token 序列组织成**语法树**，检查语法错误，并生成 AST 用于后续语义分析。

### 课程重点

考试 80% 的分数集中在 **FIRST/FOLLOW 集计算**和 **LR(0)/SLR(1) 分析表构造**。LALR 只需知道名字和基本概念。

## 两大分析方法对比

### 1. 自顶向下分析（Top-Down Parsing）

从**根节点（开始符号）**出发，**向下**构造语法树，试图推导出输入串。

- **核心思想**：为输入串寻找最左推导
- **代表方法**：LL(k) 文法、递归下降分析、预测分析
- **实现方式**：
  - **递归下降**：为每个非终结符编写一个递归函数
  - **预测分析表**：用表驱动代替递归
- **优点**：实现简单，易于手工构造，适合手工编写 parser
- **缺点**：**不能处理左递归文法**，回溯时效率低

#### 例子

文法：`E → E + T | T`，输入 `a + b`

```
E
├── E
│   └── T → a
├── +
└── T → b
```

#### LL(1) 判断条件

同一非终结符的任意两个产生式 `A → α | β`，必须满足：

- `FIRST(α) ∩ FIRST(β) = ∅`（不能有公共首符集）
- 若 `ε ∈ FIRST(α)`，则 `FIRST(β) ∩ FOLLOW(A) = ∅`（否则会冲突）

### 2. 自底向上分析（Bottom-Up Parsing）

从**叶子节点（输入 token）**出发，**向上**归约，试图归约到根节点（开始符号）。

- **核心思想**：寻找输入串的最右推导的逆过程（最左归约）
- **代表方法**：LR(0)、SLR(1)、LALR(1)、Canonical LR(1)
- **实现方式**：移入-归约分析器 + 分析表（ACTION 表 + GOTO 表）
- **优点**：能力比 LL 强，**能处理左递归文法**，适用范围广
- **缺点**：分析表大，手工构造复杂，需借助工具生成

#### 工作流程

不断执行两类操作：

- **移入（shift）**：把当前输入符号压入栈
- **归约（reduce）**：把栈顶若干符号替换为对应产生式左部的非终结符

#### 例子

文法：`E → E + T | T`，输入 `a + b`

```
步骤   栈           输入        动作
1      $            a + b $     移入 a
2      $ a          + b $       按 T → a 归约
3      $ T          + b $       按 E → T 归约
4      $ E          + b $       移入 +
5      $ E +        b $         移入 b
6      $ E + b      $           按 T → b 归约
7      $ E + T      $           按 E → E + T 归约
8      $ E          $           接受
```

### 自顶向下 vs 自底向上

| 维度 | 自顶向下（LL） | 自底向上（LR） |
| :--- | :--- | :--- |
| 推导方向 | 最左推导 | 最左归约（最右推导的逆） |
| 构造起点 | 开始符号（根） | 输入符号（叶） |
| 处理左递归 | ❌ 不能直接处理 | ✅ 可以处理 |
| 文法能力 | 较弱 | 较强 |
| 实现难度 | 简单（手写） | 复杂（通常工具生成） |
| 典型应用 | 教学、简单语言 | Yacc/Bison 工业级 parser |

## 左递归与右递归

### 1. 左递归（Left Recursion）

产生式右部**以左部非终结符开头**的形式。设 `A` 是非终结符：

- **直接左递归**：`A → A α`
- **间接左递归**：`A → B α`，`B → A β`（经过几步又回到自己）

#### 问题

自顶向下分析遇到左递归会**无限递归**，必须消除。

#### 例子

```bnf
E → E + T | T        ← 直接左递归
```

用 E 求 E 时，E 又调用 E，无限循环。

#### 消除方法

**直接左递归** `A → A α | β`（其中 `β` 不以 A 开头）改写为：

```bnf
A  → β A'
A' → α A' | ε
```

例如：

```bnf
原：E → E + T | T
改：E → T E'
   E' → + T E' | ε
```

**间接左递归**：先把间接左递归改写为直接左递归，再用上述方法消除。

### 2. 右递归（Right Recursion）

产生式右部**以终结符或别的非终结符结尾**，且自己出现在最右边。

#### 例子

```bnf
E → T + E
E → T          ← 也算右递归（单步终止）
```

#### 特点

- ✅ 自顶向下分析**可以直接处理**（不会无限递归）
- ✅ 符合自然语言的运算顺序（左结合 vs 右结合）
- ⚠️ 但**右递归会消耗大量栈空间**（深度递归）

### 3. 考试中左/右递归的考点

| 考点 | 典型题目 |
| :--- | :--- |
| 识别左递归 | 给出文法，要求判断是否存在左递归 |
| 消除左递归 | 用算法改写文法，**常考** |
| 提左公因子 | `A → α β₁ | α β₂` → `A → α A'`，`A' → β₁ | β₂` |
| 判断文法是否 LL(1) | 看有无左递归、提左公因子后求 FIRST/FOLLOW |
| 左递归 → 右递归 | 改造文法使其能用递归下降分析 |

### 4. 记忆口诀

> **左递归**：自己调自己，越调越深 → **会死循环，必须消除**  
> **右递归**：自己最后出场，依次返回 → **能用但费栈**  
> **自顶向下**：怕左递归、怕回溯 → 用 LL(1)  
> **自底向上**：什么都吃，移入-归约 → 用 LR(0)/SLR(1)

## LL(1) 算法详解

**LL(1)**：第一个 L 表示从左到右扫描输入，第二个 L 表示最左推导，**1** 表示只需向前看 **1 个**符号即可决定选择哪个产生式。

### LL(1) 文法的定义

文法 G 是 LL(1) 的，当且仅当对任意非终结符 A 的任意两个产生式 `A → α | β`，满足：

1. **`FIRST(α) ∩ FIRST(β) = ∅`**（首符集不相交）
2. 若 `ε ∈ FIRST(α)`（即 α 可推出空），则 `FIRST(β) ∩ FOLLOW(A) = ∅`
3. 若 `ε ∈ FIRST(β)`，则 `FIRST(α) ∩ FOLLOW(A) = ∅`

简单说：**只看 1 个输入符号，就能唯一确定用哪个产生式**。

### FIRST 集计算（必考算法）

**定义**：`FIRST(α)` 是从 α 出发，**所有可能推导出的串首终结符的集合**。若 α 能推出 ε，则把 ε 也加入。

#### 规则

1. **终结符**：`FIRST(a) = {a}`
2. **ε**：单独 `FIRST(ε) = {ε}`
3. **非终结符 A**：
   - 若 `A → a...`，则 a ∈ FIRST(A)
   - 若 `A → B...`，则 FIRST(B) ⊆ FIRST(A)
   - 若 `A → B₁B₂...Bₖ` 且 `B₁...Bᵢ₋₁` 都能推出 ε，则 `FIRST(Bᵢ) ⊆ FIRST(A)`
4. **串 α = X₁X₂...Xn**：把 X₁ 的 FIRST 集加入（去掉 ε），若 X₁ 能推出 ε，再看 X₂，以此类推；若所有 Xi 都能推出 ε，则把 ε 加入

#### 例子

文法：

```
E → T E'
E' → + T E' | ε
T → F T'
T' → * F T' | ε
F → ( E ) | id
```

计算：

- `FIRST(F) = {(, id}`
- `FIRST(T) = FIRST(T') = FIRST(F) = {(, id}`
- `FIRST(E) = FIRST(E') = FIRST(T) = {(, id}`

### FOLLOW 集计算（必考算法）

**定义**：`FOLLOW(A)` 是**所有句型中紧跟在 A 后面的终结符的集合**。特殊地，若 A 是某个句型的最右符号，则 `#`（句末标志）∈ FOLLOW(A)。

#### 规则

1. `# ∈ FOLLOW(S)`（S 是开始符号）
2. 若 `A → αBβ`，则 `FIRST(β) \ {ε} ⊆ FOLLOW(B)`
3. 若 `A → αB` 或 `A → αBβ` 且 `ε ∈ FIRST(β)`，则 `FOLLOW(A) ⊆ FOLLOW(B)`

#### 例子（接上文）

- `FOLLOW(E)`：E 是开始符号，先放 `#`。`F → ( E )` 中 E 后面跟 `)`，所以 `) ∈ FOLLOW(E)`。故 `FOLLOW(E) = {#, )}`
- `FOLLOW(E')`：`E → T E'`，E' 在末尾 → `FOLLOW(E) ⊆ FOLLOW(E') = {#, )}`。`E' → + T E'` 中 E' 末尾 → `FOLLOW(E') ⊆ FOLLOW(E')`（自反）。故 `FOLLOW(E') = {#, )}`
- `FOLLOW(T)`：`E' → + T E'`，T 后是 E'，E' 能推出 ε → `FOLLOW(E') ⊆ FOLLOW(T) = {#, )}`
- `FOLLOW(T')`：类似，`= {#, )}`
- `FOLLOW(F)`：`T' → * F T'`，F 后是 T'，能推出 ε → `FOLLOW(T') ⊆ FOLLOW(F) = {#, )}`。`F → ( E )` 中 F 在最左 → `FOLLOW(F) ⊆ FOLLOW(F)`。`T → F T'`，F 后是 T'，能推出 ε → `FOLLOW(T) ⊆ FOLLOW(F) = {#, )}`

### LL(1) 分析表构造

对每条产生式 `A → α`，对每个 `a ∈ FIRST(α)`，在表 `[A, a]` 填 `A → α`；若 `ε ∈ FIRST(α)`，则对每个 `b ∈ FOLLOW(A)`，在表 `[A, b]` 填 `A → ε`。

得到的分析表**无冲突**（每个格子最多一个产生式）即为 LL(1) 文法。

## LR 系列算法详解（自底向上）

LR(k) 中：L 表示从左到右扫描，R 表示构造最右推导的逆过程（最左归约），**k** 表示向前看 k 个符号。

### LR 分析器结构

LR 分析器由四部分组成：

1. **输入缓冲区**：存放待分析符号串
2. **栈**：存放文法符号和状态，形式为 `s₀ X₁ s₁ X₂ s₂ ... Xₙ sₙ`
3. **LR 分析表**：
   - **ACTION 表**：`ACTION[s, a]` 表示在状态 s 看到终结符 a 的动作（移入/归约/接受/报错）
   - **GOTO 表**：`GOTO[s, A]` 表示在状态 s 上把非终结符 A 移入后跳到的状态
4. **输出**：归约时输出产生式

#### ACTION 表的四种动作

- **`shift s`**（移入）：把 a 和状态 s 压栈
- **`reduce A → β`**（归约）：弹出 |β| 个符号，按 GOTO 跳到新状态
- **`accept`**（接受）：分析成功
- **`error`**（报错）

### LR(0) 算法

**核心概念**：只看当前状态，**不向前看任何输入符号**就能决定动作。

#### 项目（Item）

LR(0) 的基本单位是**项目**，即在产生式右部的某个位置加一个点 `.`，表示分析进度。

例：`A → XYZ` 有 4 个项目：

```
A → .XYZ
A → X.YZ
A → XY.Z
A → XYZ.
```

`.` 在末尾表示**归约项目**（可归约），其余是**移入项目**或**待约项目**。

#### 构造识别活前缀的 DFA（项目集族）

**步骤**：

1. 增广文法：加新产生式 `S' → S`
2. 构造初始项目集 `I₀ = CLOSURE({S' → .S})`
3. 对每个项目集 I 和文法符号 X，计算 `GOTO(I, X) = CLOSURE(J)`，其中 J 是 I 中形如 `A → α.Xβ` 的项目
4. 不断重复 3，直到没有新项目集

**CLOSURE 规则**：

- I 中所有项目都在 CLOSURE(I) 中
- 若 `A → α.Bβ` ∈ CLOSURE(I)，则对 B 的每个产生式 `B → γ`，把 `B → .γ` 也加入

#### 例子

文法：

```
S' → E
E → E + T | T
T → T * F | F
F → ( E ) | id
```

构造的项目集族有 12 个状态 I₀ ~ I₁₁（典型课堂例题）。

#### LR(0) 分析表构造

- 若项目 `A → α.aβ` ∈ Iᵢ 且 `GOTO(Iᵢ, a) = Iⱼ`，则 `ACTION[i, a] = shift j`
- 若项目 `A → α.` ∈ Iᵢ（A ≠ S'），则对所有终结符 a，`ACTION[i, a] = reduce A → α`
- 若项目 `S' → S.` ∈ Iᵢ，则 `ACTION[i, #] = accept`
- 若 `GOTO(Iᵢ, A) = Iⱼ`（A 是非终结符），则 `GOTO[i, A] = j`

#### LR(0) 的局限

能力太弱，很多实用文法**构造不出无冲突的 LR(0) 表**（会出现"移入-归约冲突"或"归约-归约冲突"）。

### SLR(1) 算法（Simple LR）

在 LR(0) 基础上**向前看 1 个符号**，但**仅在归约决策时**看，简单地用 FOLLOW 集消解冲突。

#### 改进点

LR(0) 中归约项目 `A → α.` 对**所有终结符**都归约，过于激进。SLR(1) 改为：**只对 FOLLOW(A) 中的终结符**执行归约 `A → α`。

#### 规则

- 若 `A → α.aβ` ∈ Iᵢ 且 `GOTO(Iᵢ, a) = Iⱼ`，则 `ACTION[i, a] = shift j`（同 LR(0)）
- 若 `A → α.` ∈ Iᵢ（A ≠ S'），则对每个 a ∈ **FOLLOW(A)**，`ACTION[i, a] = reduce A → α`
- 若 `S' → S.` ∈ Iᵢ，则 `ACTION[i, #] = accept`

#### SLR(1) 的冲突判定

若同一状态 Iᵢ 出现以下情况，则有冲突：

1. **移入-归约冲突**：`A → α.` 和 `B → β.aγ` 都在 Iᵢ，且 a ∈ FOLLOW(A)
2. **归约-归约冲突**：`A → α.` 和 `B → β.` 都在 Iᵢ，且 FOLLOW(A) ∩ FOLLOW(B) ≠ ∅

若有冲突，该文法**不是 SLR(1) 文法**。

#### 例子（典型考题）

文法：

```
S → L = R | R
L → * R | id
R → L
```

在某个状态中同时有项目 `L → *R.` 和 `S → L.`（FOLLOW(S) 包含 `=`），会出现移入-归约冲突 → **不是 SLR(1) 文法**。

### LR(1) / Canonical LR 算法

**最强但状态数最多**。每个项目带上**向前看符号集**（长度为 1 的终结符串）。

#### LR(1) 项目

形如 `[A → α.β, a]`，其中 a 是**终结符**（或 #），表示归约该项目时，下一个输入符号必须是 a。

#### 构造

CLOSURE 和 GOTO 规则扩展：

- 若 `[A → α.Bβ, a] ∈ I`，则对 B 的每个产生式 `B → γ` 和每个 b ∈ FIRST(βa)，把 `[B → .γ, b]` 加入 CLOSURE(I)
- GOTO 转移时向前看符号不变

#### 能力

能处理**所有**确定性上下文无关文法，但项目集数量大，**实际很少手算**。

### LALR(1) 算法（Look-AAhead LR）

**工业界最常用**（Bison/Yacc 默认），是 LR(1) 的**实用化**。

#### 构造思路

1. 先构造 LR(1) 项目集族
2. **合并**同心项目集（即项目中的产生式和点的位置相同，仅向前看符号不同的项目集）
3. 检查合并后是否有冲突

#### 优缺点

| 维度 | LALR(1) | LR(1) | SLR(1) |
| :--- | :--- | :--- | :--- |
| 能力 | 中等 | 最强 | 最弱 |
| 状态数 | 少（同 LR(0)） | 多 | 少 |
| 冲突可能 | 可能有 | 几乎无 | 经常有 |
| 实际应用 | ✅ 工业主流 | 教学/理论 | 教学演示 |

> LALR(1) 比 SLR(1) 强，但状态数比 LR(1) 少得多，**能力/状态比最佳**。

### LR 系列能力比较

```
LR(0) ⊊ SLR(1) ⊊ LALR(1) ⊊ LR(1)
```

状态数关系：

```
|States(LR(0))| = |States(LALR(1))| ≤ |States(LR(1))|
```

### 算法选择口诀

> **能 LL(1) 就用 LL(1)**，简单手写  
> **不能用 LL(1) 就用 LR 系列**  
> **手算考题**：必画 SLR(1) 分析表  
> **工业实践**：直接用 LALR(1)（Bison/Yacc）  
> **理论最强**：LR(1)，但状态爆炸

# 三、语义分析

## 核心缩写

| 缩写 | 全称 | 中文 | 作用 |
| :--- | :--- | :--- | :--- |
| **SDT** | Syntax-Directed Translation | 语法制导翻译 | 在文法产生式上加语义动作（代码片段），在语法分析过程中完成翻译 |
| **IR** | Intermediate Representation | 中间表示 | 前端与后端的分界，连接语义分析与代码优化 |
| **TAC** | Three-Address Code | 三地址码 | 中间表示的一种形式，形如 `t1 = a + b`，**回填技术**用于处理跳转地址 |

### 语义分析阶段的作用

进行**类型检查**、**作用域分析**，并通过 SDT 将语法树转换为中间代码（如三地址码），为后续优化和代码生成做准备。

# 四、中间代码生成

## 核心缩写

| 缩写 | 全称 | 中文 | 作用 |
| :--- | :--- | :--- | :--- |
| **IR** | Intermediate Representation | 中间表示 | 前端生成的代码表示，与具体机器无关 |
| **TAC** | Three-Address Code | 三地址码 | 每条指令最多三个操作数，如 `t1 = a + b`、`if x > y goto L` |

### 三地址码的常见指令类型

- **赋值指令**：`t1 = a + b`
- **条件跳转**：`if x > y goto L`
- **无条件跳转**：`goto L`
- **函数调用**：`param x`、`call f, 1`
- **数组访问**：`t1 = a[i]`
- **拷贝指令**：`t1 = x`

# 五、代码优化

## 核心缩写

| 缩写 | 全称 | 中文 | 作用 |
| :--- | :--- | :--- | :--- |
| **DAG** | Directed Acyclic Graph | 有向无环图 | 用于**基本块优化**，合并公共子表达式 |
| **CFG** | Control Flow Graph | 控制流图 | 描述程序执行路径，节点为基本块，边为跳转关系 |
| **DCE** | Dead Code Elimination | 死代码消除 | 删除永远不会执行的代码 |
| **CSE** | Common Subexpression Elimination | 公共子表达式删除 | 避免重复计算相同表达式，如 `a = b + c; d = b + c` → 只算一次 |

### 代码优化阶段的作用

改进代码效率，包括**局部优化**（基本块内）、**全局优化**（跨基本块）和**循环优化**等。

### 注意

> **CFG 有两个完全不同的意思**：语法分析里是 **Context-Free Grammar（上下文无关文法）**，代码优化里是 **Control Flow Graph（控制流图）**。考试时务必根据上下文区分！

# 六、目标代码生成

## 核心任务

将中间代码转换为特定机器的**目标代码**（汇编或机器码），涉及：

- **寄存器分配**：将变量映射到寄存器
- **指令选择**：将三地址码映射为机器指令
- **地址分配**：变量在内存中的位置
