# 二、应用层

## 2.1 应用层协议原理

#### 网络程序

- **分布式应用**：在不同端系统上运行，通过网络基础设施相互通信
- 不需考虑网络核心，只在端系统

#### 两大体系结构

##### 客户—服务器体系结构(C-S)

**服务器：**

- 一直运行
- 固定 IP
- 位于数据中心

**客户：**

- 与服务器通信
- 间歇连接
- 动态 IP
- 客户间不能通信

**例：** HTTP, IMAP, FTP

##### 对等体系结构(P2P)

- 没有一直运行的主机
- 端系统之间直接通信
- 自扩展性：新的对等方带来新的服务容量/需求
- 间歇连接，可变 IP

## 2.2 进程通信

- 不同端系统上的网络应用程序通信，本质是不同端系统的进程通信
- **客户进程**：发起通信的进程
- **服务器进程**：等待联系的进程

#### 套接字(Socket)

- 位于应用层与运输层之间的接口
- 进程通过套接字发送/接收报文
- 选择运输层协议（TCP, UDP）
- 设定运输层的协议参数

#### 进程寻址

- 进程标识符 = IP 地址 + 端口号
- 常用端口：HTTP: 80, 邮件: 25

## 2.3 运输层服务模型

应用对运输服务的需求

| 应用              | 数据丢失 |               带宽               | 时间敏感？ |
| :---------------- | :------: | :-------------------------------: | :--------: |
| 文件传输/下载     | 不能丢失 |               弹性               |     不     |
| 电子邮件          | 不能丢失 |               弹性               |     不     |
| Web文档           | 不能丢失 |               弹性               |     不     |
| 实时电话/视频会议 | 容忍丢失 | 音频5Kbps-1Mbps，视频10Kbps-5Mbps | 是，100ms |
| 流式存储音频/视频 | 容忍丢失 |               同上               |  是，几秒  |
| 交互式游戏        | 容忍丢失 |           几kbps-10kbps           | 是，100ms |
| 智能手机讯息      | 不能丢失 |               弹性               |  是和不是  |

#### TCP 服务

- 可靠传输
- 流量控制：发送方不会"淹没"接收方
- 拥塞控制：网络拥挤时抑制发送方
- 面向连接
- **缺点**：定时、最小吞吐量、安全性（不提供）

#### UDP 服务

- 不可靠传输
- 最小进程通信
- **缺点**：所有
- **应用**：DNS 基于 UDP（高效，不建立连接）

## 2.4 Web 和 HTTP

- HTTP 概述

  - 超文本传输协议
  - Web 页面包含多个对象，每个对象可在不同 Web 服务器
  - 使用 TCP，客户发起与服务器的 TCP 连接
  - **HTTP 是无状态的**
- HTTP 连接

  - 非持久型HTTP(HTTP 1.0)
    - TCP 连接打开，发送一个对象，TCP 连接关闭
    - 响应时间 = 2RTT + 传输时间 t
  - 持久HTTP(HTTP 1.1)
    - TCP 连接打开，发送多个对象，TCP 连接关闭

**HTTP 请求报文格式**

```
请求行 (GET, POST, HEAD)
首部行
空行（表示报文结束）
实体体（可选）
```

**请求方法：**

|  方法  | 说明                                        |
| :----: | :------------------------------------------ |
|  GET  | 用来给服务器发送数据，在 URL 中包含用户输入 |
|  POST  | 表单输入，包含在实体中，数据量大，安全      |
|  HEAD  | 用一个报文进行响应，但不返回请求对象        |
|  PUT  | 实体中的文件上传到 URL 的路径               |
| DELETE | 删除 URL 的文件                             |

**HTTP 响应状态码**

|             状态码             | 说明                     |
| :----------------------------: | :----------------------- |
|             200 OK             | 请求成功                 |
|     301 Moved Permanently     | 请求文档被永久转移       |
|        400 Bad Request        | 请求报文不能被服务器理解 |
|         404 Not Found         | 请求的文本不在服务器上   |
| 505 HTTP Version Not Supported |                          |

#### Cookies

维护用户/服务器状态的机制：

- HTTP 响应报文中的 cookie 首部行
- HTTP 请求报文中的 cookie 首部行
- 用户端系统的 cookie 文件
- Web 站点的后端数据库

#### Web 缓存器（代理服务器）

不访问初始服务器即可满足客户的需求，优先通过缓存器访问，服务器在响应字段有对应的标识。缓存器**既是客户又是服务器**。

**作用：**

- 降低请求/响应时间（更近，减少主干路低速率链路时间）
- 减少机构内部网络与 Internet 接入链路上的流量
- "较弱" 的内容提供商更有效地提供内容

**条件 GET**：更新缓存器的内容。

- 缓存器请求报文添加首部行，记录日期
- 响应：
  - `304 Not Modified`：未修改
  - `200 OK`：最新内容

## 2.5 电子邮件

#### 三个组件

- **用户代理**：邮件阅读器，编辑、阅读邮件报文
- **邮件服务器**：管理、维护发送给用户的报文
- **SMTP**：邮件服务器之间发送报文
  - TCP 连接，可靠传输
  - 传输三个阶段：SMTP 握手 → 报文传输 → SMTP 关闭

## 2.6 DNS

#### 功能

- 主机名到 IP 地址的转换
- 主机别名
- 邮件服务器别名
- 负载分配（冗余服务器：多 IP 地址对应一个域名）

#### 分布式层次数据库

- **根 DNS 服务器**：13 个根服务器
- **顶级域(TLD)**：.com, .org, .net, .edu, 国家域名
- **权威 DNS 服务器**：组织机构自己的 DNS 服务器
- **本地 DNS 服务器**：代理转发层级结构

#### 查询方式

|   方式   | 说明                         |
| :------: | :--------------------------- |
| 递归查询 | 传给下层结构，最后返回结果   |
| 迭代查询 | 返回下一个可联系的服务器地址 |

#### DNS 记录格式

`(Name, Value, Type, TTL)`

| Type | 说明                               |
| :---: | :--------------------------------- |
|   A   | 主机名 → IP 地址                  |
|  NS  | 域名 → 上级/权威 DNS 服务器主机名 |
| CNAME | 别名 → 规范主机名                 |
|  MX  | 邮件服务器别名                     |

## 2.7 P2P 文件分发

#### P2P 特点

- 没有一直运行的主机
- 端系统之间直接通信
- 自扩展性

#### BitTorrent

- 将文件划分为文件块（每块 256KB）
- 洪流：参与一个文件分发的对等方集合
- 追踪器：跟踪洪流中的对等方
- **最优块优先**：下载列表中数量最少的文件块
- **一报还一报**：对最高速率的 top 4 提供方发送文件块

## 2.8 视频流和内容分发网

#### 视频流挑战

- **规模性**：CDN
- **异构性**：DASH

#### DASH(经 HTTP 的动态适应性流)

- 服务器将视频分割成多个块，每个块以多种比特率编码
- 客户周期性测量带宽，请求不同比特率块

#### CDN

- "深入"：CDN 到接入网中
- "邀请放客"：CDN 在关键位置

## 2.9 Socket 编程

#### UDP(无连接)

```python
# 客户端
clientSocket = socket(AF_INET, SOCK_DGRAM)
clientSocket.sendto(message.encode(), (serverName, serverPort))
modifiedMessage, serverAddress = clientSocket.recvfrom(2048)
```

```python
# 服务器端
serverSocket = socket(AF_INET, SOCK_DGRAM)
serverSocket.bind(("", serverPort))
message, clientAddress = serverSocket.recvfrom(2048)
serverSocket.sendto(modifiedMessage.encode(), clientAddress)
```

#### TCP(面向连接)

```python
# 客户端
clientSocket = socket(AF_INET, SOCK_STREAM)
clientSocket.connect((serverName, serverPort))
clientSocket.send(sentence.encode())
modifiedSentence = clientSocket.recv(1024)
```

```python
# 服务器端
serverSocket = socket(AF_INET, SOCK_STREAM)
serverSocket.bind(('', serverPort))
serverSocket.listen(1)
connectionSocket, addr = serverSocket.accept()
capitalizedSentence = sentence.upper()
connectionSocket.send(capitalizedSentence.encode())
```
