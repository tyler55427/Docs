# 目标代码生成

> 对应教材：第 8 章「代码生成」（PDF p331–p389）。术语沿用笔记原文：**目标语言**、**指令选择**、**寄存器分配和指派**、**指令排序**、**基本块**、**流图**、**寄存器描述符**、**地址描述符**、**窥孔优化**。
>
> ⚠ 本章使用**流图（flow graph）**一词，与 [`05_代码优化`](05_代码优化.md) 一致。

## 核心缩写

| 缩写 | 全称 | 中文 | 作用 |
| :--- | :--- | :--- | :--- |
| **IR** | Intermediate Representation | 中间表示 | 代码生成器的输入，本章为三地址代码 |
| | Basic Block | 基本块 | 满足①控制流只从首指令进入、②离开前不停机不跳转的**最大**连续三地址指令序列 |
| | Flow Graph | 流图 | 结点为基本块、边表示基本块间控制流向的图 |
| | Register/Address Descriptor | 寄存器/地址描述符 | 代码生成器维护的数据结构，跟踪哪个值在哪个寄存器、变量的值在哪些位置 |
| | Peephole Optimization | 窥孔优化 | 检查目标指令的滑动窗口，用更快/更短的指令替换窗口内序列 |

## 8.1 代码生成器设计中的问题

代码生成器把 IR 翻译成目标机器指令序列。**三个主要任务**：

1. **指令选择**：选择适当目标机器指令实现 IR 语句（如为每种三地址语句生成代码骨架）。
2. **寄存器分配和指派**：决定哪个值放在哪个寄存器。**分配**=选哪些变量入寄存器；**指派**=指定具体寄存器。**最优指派是 NP 完全的**。
3. **指令排序**：按什么顺序安排指令执行。

### 8.1.1–8.1.2 输入与目标程序

- **输入**：IR + 符号表信息。IR 可以是抽象语法树、三地址代码等。
- **目标程序**：可能包含不可重定位代码（绝对地址代码，可直接执行）、可重定位目标模块（需链接/加载器）、汇编代码（需汇编后再链接）。绝对地址代码最快执行但不可独立编译。

### 8.1.3 指令选择

为每条 IR 语句选择目标指令。需考虑正确性（语义一致）、效率（避免冗余指令）。若目标机有高效指令（如 `INC` 自增），应优先使用。指令选择可用**树模式匹配**建模（§8.9），用动态规划生成最优代码序列（§8.11）。

### 8.1.4 寄存器分配

寄存器的四种用途：

1. 运算时部分/全部运算分量必须在寄存器。
2. 临时变量（基本块内使用的值）。
3. 跨基本块使用的全局值（如循环下标）。
4. 运行时刻存储管理（栈指针 SP）。

可用寄存器有限，需求相互竞争。

### 8.1.5 求值顺序

求值顺序影响寄存器使用效率。最优顺序可最小化寄存器需求（§8.10）。

## 8.2 目标语言

### 8.2.1 简单目标机模型

三地址机器模型，字节寻址，$n$ 个通用寄存器 R0, R1, ..., Rn-1。指令种类：

- **加载** `LD dst, addr`：把 addr 的值加载到 dst（`dst = addr`）。`LD r1, r2` 是寄存器间拷贝。
- **保存** `ST x, r`：把寄存器 r 的值保存到位置 x（`x = r`）。
- **计算** `OP dst, src1, src2`：如 `ADD`、`SUB`，把 OP 作用于 src1、src2 的值放到 dst。单目运算符无 src2。
- **无条件跳转** `BR L`：控制流向标号 L。
- **条件跳转** `Bcond r, L`：如 `BLTZ r, L`（r 中值小于 0 时跳转）。

**寻址模式**：

| 模式 | 形式 | 含义 |
| :--- | :--- | :--- |
| 变量名 | $x$ | $x$ 的左值（内存位置） |
| 带下标 | $a(r)$ | $\text{contents}(a + \text{contents}(r))$，数组访问用 |
| 常数下标 | $c(r)$ | $\text{contents}(c + \text{contents}(r))$，沿指针取值用 |
| 间接 | $*r$ | $\text{contents}(\text{contents}(r))$ |
| 双重间接 | $*c(r)$ | $\text{contents}(\text{contents}(c + \text{contents}(r)))$ |
| 直接常数 | $\#c$ | 常数 $c$ |

**例 8.2** 三地址语句 $x = y - z$：

```
LD  R1, y      // R1 = y
LD  R2, z      // R2 = z
SUB R1, R1, R2 // R1 = R1 - R2
ST  x, R1      // x = R1
```

数组访问 $b = a[i]$（元素 8 字节）：

```
LD  R1, i       // R1 = i
MUL R1, R1, 8   // R1 = i * 8
LD  R2, a(R1)   // R2 = contents(a + R1)
ST  b, R2       // b = R2
```

指针间接 $x = *p$：

```
LD  R1, p       // R1 = p
LD  R2, 0(R1)   // R2 = contents(0 + R1)
ST  x, R2       // x = R2
```

条件跳转 `if x < y goto L`：

```
LD   R1, x
LD   R2, y
SUB  R1, R1, R2  // R1 = x - y
BLTZ R1, M       // if R1 < 0 goto M
```

### 8.2.2 指令的代价

每条指令代价 = 1 + 与运算分量寻址模式相关的代价。寄存器寻址附加代价 0，涉及内存/常数附加代价 1（对应指令中字的长度）。

- `LD R0, R1` 代价 1
- `LD R0, M` 代价 2
- `LD R1, *100(R2)` 代价 2

程序代价 = 执行的所有指令代价总和。

## 8.3 目标代码中的地址

### 8.3.1 静态分配

逻辑地址空间四区：代码区、静态区、堆区、栈区（见 [`07_运行时刻环境`](07_运行时刻环境.md) §7.1）。活动记录大小和布局由符号表确定。

`call callee` 的静态分配代码：

```
ST callee.staticArea, #here + 20  // 保存返回地址
BR callee.codeArea                // 转移到 callee
```

`return`：

```
BR *callee.staticArea  // 跳到活动记录首字保存的地址
```

无调用者的第一个过程用 `HALT` 结束。`#here + 20` 是 BR 之后的指令地址（调用序列 3 常量 + 2 指令 = 5 字 = 20 字节）。

### 8.3.2 栈分配

用相对地址，活动记录位置运行时刻才知。SP 指向栈顶活动记录开始处，偏移量均为正。

栈初始化：

```
LD SP, #stackStart  // 初始化栈
```

调用指令序列（增加 SP、保存返回地址、转移）：

```
ADD SP, SP, #caller.recordSize  // 增加栈指针
ST  0(SP), #here + 16            // 保存返回地址
BR  callee.codeArea              // 转移到被调用过程
```

返回指令序列（被调用者转移 + 调用者恢复 SP）：

```
BR *0(SP)                        // 返回（两层间接寻址）
SUB SP, SP, #caller.recordSize   // 调用者恢复 SP
```

`*0(SP)` 用两层间接寻址：`0(SP)` 是活动记录首字位置，`*0(SP)` 是那里存放的返回地址。

### 8.3.3 名字的运行时刻地址

名字最终必须替代为访问存储位置的代码。若 $x$ 的符号表相对地址为 12，分配在地址 $\text{static}$ 起的静态区，则运行时刻地址是 $\text{static} + 12$。赋值 $x = 0$ 翻译成 `static[12] = 0`，静态区从 100 开始时目标代码为 `LD 112, #0`。

> 生成中间代码时用指向符号表条目的指针使编译器易移植（前端不需因运行时刻组织变化而改）；但生成特定访问步骤可让优化器利用更多细节。

## 8.4 基本块和流图

### 8.4.1 基本块

**基本块**：满足下列条件的**最大**连续三地址指令序列：

1. 控制流只能从首指令进入（无跳转到块中间的指令）。
2. 离开前不停机不跳转（末尾除外）。

**算法 8.5** 划分基本块：

1. 确定首指令（leader）：① 第一条指令；② 任何条件/无条件跳转的目标；③ 跳转指令的下一条指令。
2. 每个首指令到下一首指令之前构成一个基本块。

### 8.4.2 流图

基本块是流图结点，边表示控制流向。$B_1 \to B_2$ 当且仅当：① $B_1$ 末尾有跳转到 $B_2$ 首指令的指令；或② $B_1$ 末尾不是无条件跳转/停机，且 $B_2$ 在序列中紧随 $B_1$。

## 8.5 基本块的优化

### 基本块的 DAG

为基本块构造 DAG（见 [`04_中间代码生成`](04_中间代码生成.md) §6.1）：叶子是变量/常量，内部结点是运算符。DAG 可发现：

- **公共子表达式**：相同子表达式共享结点。
- **死代码**：无父结点的结点对应的赋值可删。
- **代数化简**：如 $x + 0 = x$、$x * 1 = x$、$x * 2 = x + x$（强度消减）。

**数组引用**：$a[i]$ 的 DAG 结点标号需特殊处理——对 $a$ 的赋值可能杀死之前 $a[j]$ 的引用（因 $i$ 可能等于 $j$）。DAG 中为对数组元素的定值建立独立结点。

### 从 DAG 重组基本块

从 DAG 重写三地址代码：按结点生成顺序输出，先算出的先输出。可省略不必要的复制指令。

## 8.6 一个简单的代码生成器

为单个基本块生成代码，依次处理各三地址指令，跟踪哪个值在哪个寄存器，避免不必要的加载/保存。

### 8.6.1 寄存器和地址描述符

- **寄存器描述符（register descriptor）**：每个可用寄存器一个，跟踪有哪些变量的当前值存于此寄存器。开始时所有寄存器描述符为空。
- **地址描述符（address descriptor）**：每个程序变量一个，跟踪在哪些位置可找到该变量当前值（寄存器、内存地址、栈位置或它们的集合）。存于符号表条目。

### 8.6.2 代码生成算法

函数 `getReg(I)` 为三地址指令 $I$ 的各位置选择寄存器，可访问所有寄存器/地址描述符和数据流信息（如哪些变量在块出口活跃）。

**运算 `x = y + z` 的机器指令**：

1. 用 `getReg` 为 $x$、$y$、$z$ 选 $R_x$、$R_y$、$R_z$。
2. 若 $y$ 不在 $R_y$（查寄存器描述符）：生成 `LD Ry, y'`（$y'$ 由地址描述符得到）。
3. 若 $z$ 不在 $R_z$：生成 `LD Rz, z'`。
4. 生成 `ADD Rx, Ry, Rz`。

**复制语句 `x = y`**：假设 `getReg` 总为 $x$、$y$ 选同一寄存器。若 $y$ 不在 $R_y$：生成 `LD Ry, y`。若已在 $R_y$：不做事，只修改 $R_y$ 的寄存器描述符表明也存放 $x$。

**基本块收尾**：临时变量值可丢弃（假设寄存器空）；在出口活跃的变量，若地址描述符表明其值不在自己的内存位置，须生成 `ST x, R`。

**描述符更新规则**：

- `LD R, x`：① R 的寄存器描述符只含 $x$；② $x$ 的地址描述符加入 R；③ 其他变量的地址描述符删除 R。
- `ST x, R`：$x$ 的地址描述符加入自己的内存位置。
- `ADD Rx, Ry, Rz`（实现 $x = y + z$）：① $R_x$ 的寄存器描述符只含 $x$；② $x$ 的地址描述符只含 $R_x$（不含内存位置）；③ 其他变量的地址描述符删除 $R_x$。
- 复制 $x = y$（必要时先 `LD` 再按 `LD` 规则处理，然后）：① $R_y$ 的寄存器描述符加入 $x$；② $x$ 的地址描述符只含 $R_y$。

### 8.6.3 getReg 的设计

`getReg` 为结果 $x$ 选寄存器的优先级：

1. 若某寄存器已含 $x$ 的值，用它。
2. 若有空闲寄存器，用空闲的。
3. 否则选一个被占用的寄存器释放——优先选其值不再需要（如临时变量已用完）或值也在内存中的变量。若该变量在块出口活跃，生成 `ST` 保存后再复用。

## 8.7 窥孔优化

**窥孔优化**：检查目标指令的滑动窗口（窥孔），用更快/更短的指令替换窗口内序列。可对目标代码或中间代码进行。每次改进可能产生新的优化机会，需多次扫描。

### 8.7.1 消除冗余加载和保存

```
LD R0, a
ST a, R0    // 可删除（a 的值已在 R0）
```

需两条指令在同一基本块内（否则保存指令有标号时不能保证顺序）。§8.6 的算法不会生成这种冗余，但原始代码生成器可能。

### 8.7.2 消除不可达代码

紧跟在无条件跳转后的不带标号指令可删除。`debug` 代码示例：常量传播把 `debug` 替换为 0 后，`if 0 != 1 goto L2` 恒为真，可替换为 `goto L2`，其后的打印代码变为不可达，可逐一消除。也可消除级联跳转。

### 8.7.3 控制流优化

消除不必要的跳转：

- `goto L1; ...; L1: goto L2` → `goto L2`（直接跳到 L2）
- `if a < b goto L1; ...; L1: goto L2` → `if a < b goto L2`
- 若只有一个到达 L1 的跳转且 L1 前是无条件跳转：`goto L1; ...; L1: if a < b goto L2; L3:` → 把条件跳转上移到 goto 处，并调整标号。

### 8.7.4 代数化简和强度消减

窥孔优化器可用代数恒等式：`x = x + 0`、`x = x * 1` 可删；`x * 2` → `x + x`（加法比乘法快）。

### 8.7.5 使用机器特有指令

如目标机有 `INC`（自增）指令，`ADD R0, R0, #1` 可替换为 `INC R0`。

## 8.8 寄存器分配和指派图着色

**图着色**：构造**冲突图**——结点是变量，边连接在同时活跃的变量对。为图着色（相邻不同色），颜色数 = 可用寄存器数。若可着色则分配成功；否则需把一些变量溢出到内存。

- **简化**：反复删除度数 < $k$ 的结点（必可着色）入栈。
- **溢出**：度数 $\ge k$ 的结点标记为溢出，从图中删除后继续简化。
- **选色**：按出栈顺序为每个结点选色（不同于已着色的邻居）。

## 8.9–8.11 树模式匹配与动态规划

**指令选择的树重写**：把 IR 和机器指令表示为树，用对应于机器指令的子树覆盖 IR 树。每棵子树关联代价，用**动态规划**生成最优代码序列。Sethi-Ullman 算法（§8.10）可为某些机器生成使用最少寄存器的表达式求值代码。

## 第 8 章总结

- **三个主要任务**：指令选择、寄存器分配和指派、指令排序。
- **目标机模型**：LD/ST/OP/BR/Bcond 指令；六种寻址模式（变量名、$a(r)$、$c(r)$、$*r$、$*c(r)$、$\#c$）；指令代价 = 1 + 寻址附加代价。
- **地址映射**：四区存储（代码/静态/堆/栈）；静态分配 `ST`+`BR` 调用、`BR *` 返回；栈分配用 SP，`ADD SP`+`ST 0(SP)`+`BR` 调用、`BR *0(SP)`+`SUB SP` 返回。
- **基本块与流图**：算法 8.5 划分基本块（首指令）；流图结点为基本块。
- **基本块优化**：DAG 发现公共子表达式/死代码/代数化简。
- **简单代码生成器**：寄存器/地址描述符跟踪值的位置；`getReg` 选寄存器；块收尾对活跃变量生成 `ST`。
- **窥孔优化**：消除冗余加载/保存、不可达代码、控制流跳转；代数化简与强度消减；机器特有指令。
- **寄存器分配**：冲突图着色，简化-溢出-选色。

> **口诀**：**三任务：选指令、分配寄存器、排顺序**；**基本块首指令入口，流图结点是基本块**；**寄存器描述符管值在何处，地址描述符管变量在哪**；**getReg 选寄存器三优先：已含值、空闲、可释放**；**窥孔优化四招：删冗余存取、删不可达、理控制流、代数化简**；**寄存器分配图着色，简化溢出再选色**。
