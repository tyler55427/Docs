>
> ⚠ 教材在代码优化部分使用的正式术语是**流图（flow graph）**，不是"控制流图"。本文件一律采用笔记原文的"流图"。

## 核心缩写

| 缩写 | 全称 | 中文 | 作用 |
| :--- | :--- | :--- | :--- |
| **DAG** | Directed Acyclic Graph | 有向无环图 | 用于基本块优化，合并公共子表达式（见 [`04_中间代码生成`](04_中间代码生成.md) §6.1） |
| **CFG** | Control Flow Graph | 流图 | 描述程序执行路径，结点为基本块，边为跳转关系。⚠ **教材正式术语是流图 / flow graph**，与 [`02_语法分析`](02_语法分析.md) 的 CFG（Context-Free Grammar，上下文无关文法）**同名不同义** |
| **DCE** | Dead Code Elimination | 死代码消除 | 删除计算结果永远不会被使用的指令 |
| **CSE** | Common Subexpression Elimination | 公共子表达式删除 | 避免重复计算相同表达式 |
| **PRE** | Partial Redundancy Elimination | 部分冗余消除 | 消除部分路径上的冗余表达式（CSE 与循环不变外提是其特例） |

> **CFG 两个意思**：语法分析里是 **Context-Free Grammar（上下文无关文法）**，代码优化里是 **Control Flow Graph（流图）**。教材在优化部分用"流图 / flow graph"。

## 9.1 优化的主要来源

编译器的优化必须**保持源程序的语义**。编译器不可能把一个程序替换为完全不同且更高效的算法，只能应用低层语义转换（如 $i + 0 = i$ 的代数恒等式、相同运算得到相同结果）。

### 9.1.1 冗余的原因

程序中的冗余多半是使用高级语言编程的副产品：每次访问 $A[i][j]$ 或 $X \rightarrow f$ 都被扩展成多个低层算术运算（如计算偏移量），对同一数据结构的访问共享很多公共低层运算。程序员不知道这些低层运算，无法自行消除；让编译器消除冗余使程序既高效又易维护。

### 9.1.2 贯穿本章的例子：快速排序

图 9-1 的快速排序片段被翻译成三地址代码（图 9-2，30 条语句），再组成流图（图 9-3，基本块 $B_1$–$B_6$）。$B_1$ 是入口结点。有三个循环：$B_2$ 自身、$B_3$ 自身、$B_2$+$B_3$+$B_4$+$B_5$ 组成的外层循环（$B_2$ 是唯一入口）。

### 9.1.3 保持语义不变的转换

**语义不变（函数不变）转换**：公共子表达式消除、复制传播、死代码消除、常量折叠。图 9-4a 中 $B_5$ 重复计算 $4*i$ 和 $4*j$——这些不是程序员显式要求的。

### 9.1.4 全局公共子表达式

如果表达式 $E$ 在某次出现前已被计算，且 $E$ 中变量的值从那次计算后未被改变，则 $E$ 的该次出现是**公共子表达式**。

**例 9.1** 图 9-4a 中 $t_7$、$t_{10}$ 分别计算了公共子表达式 $4*i$、$4*j$，在图 9-4b 中被消除（用 $t_6$ 替 $t_7$，$t_8$ 替 $t_{10}$）。

**例 9.2** 图 9-5 消除了 $B_5$、$B_6$ 的全局和局部公共子表达式。$B_3$ 中计算的 $t_4 = 4*j$ 到达 $B_5$ 时 $j$、$t_4$ 值未变，故 $B_5$ 中 $t_8 = 4*j$ 可用 $t_4$ 替代，进而 $a[t_4]$ 可用 $t_5$ 替代。但 $a[t_1]$ 在 $B_1$ 和 $B_6$ 中不是公共子表达式——控制流离开 $B_1$ 到 $B_6$ 前可能经过 $B_5$（对 $a$ 赋值），值可能改变。

### 9.1.5 复制传播

形如 $u = v$ 的赋值称为**复制语句（copy statement）**。公共子表达式消除会引入复制语句。**复制传播**：在 $u = v$ 之后尽可能用 $v$ 替代 $u$。

**例 9.3** 消除 $c = d + e$ 时用新变量 $t$ 存 $d+e$，$c$ 得到的是 $t$ 的值而非 $d+e$。因控制流可能经 $a$ 或 $b$ 的赋值到达 $c = b + e$，把 $c = d+e$ 替换为 $c = a$ 或 $c = b$ 都不正确。

### 9.1.6 死代码消除

变量在某程序点的值以后可能被使用则**活跃（live）**，否则**死（dead）**。**死代码**是计算结果永远不会被使用的语句。

**例 9.4** 若编译器推导出 `debug` 每次都为 `FALSE`，复制传播把 `debug` 替换为 `FALSE` 后，`if (debug) print ...` 成为死代码可消除。在编译时刻推导出表达式值为常量并用常量替代，称为**常量折叠**。

复制传播常把复制语句变成死代码——先复制传播再死代码消除可去掉对 $x$ 的赋值。

### 9.1.7 代码移动

减少循环内部代码的重要手段是**代码移动（code motion）**：处理循环不变计算（不管循环执行多少次都得相同结果的表达式），在进入循环前求值。**循环入口**是所有循环外部到循环的跳转都以它为目标的基本块。

**例 9.5** `while (i <= limit-2)` 中 `limit-2` 是循环不变计算，代码移动后：`t = limit-2; while (i <= t)`，把 $n+1$ 次计算减为 1 次。

### 9.1.8 归纳变量和强度消减

**归纳变量**：若变量 $x$ 每次被赋值时值总增加常数 $c$，则 $x$ 是归纳变量。**强度消减（strength reduction）**：把高代价运算（如乘法）替换为低代价运算（如加法）。

**例 9.6** 图 9-5 中 $t_4 = 4*j$ 在 $j = j-1$ 后仍成立，故 $t_4 = 4*j$ 可替换为 $t_4 = t_4 - 4$。需在初始化 $j$ 的 $B_1$ 尾部加 $t_4 = 4*j$ 的初始化（图 9-8 虚线框）。

**例 9.7** 强度消减后 $i$、$j$ 唯一用途是 $B_4$ 的测试 $i \ge j$。因 $t_2 = 4*i$、$t_4 = 4*j$，测试可替换为 $t_2 \ge t_4$。替换后 $i$、$j$ 变成死变量，对它们的赋值变成死代码可删除（图 9-9）。$B_5$ 指令数从 9 减到 3，$B_6$ 从 8 减到 3。

## 9.2 流图上的数据流分析

**数据流分析**：沿着执行路径收集信息。每个程序点关联一个**数据流值**，传递函数 $f_B$ 描述基本块 $B$ 对值的影响：

- 前向：$\text{OUT}[B] = f_B(\text{IN}[B])$，$\text{IN}[B] = \bigcup_{P \in \text{pred}(B)} \text{OUT}[P]$
- 逆向：$\text{IN}[B] = f_B(\text{OUT}[B])$，$\text{OUT}[B] = \bigcup_{S \in \text{succ}(B)} \text{IN}[S]$

数据流方程通常无唯一解，目标是寻找**最精确**的解——支持代码改进但不导致不安全转换。程序分析必须**保守**：不知道一个语句是否给 $x$ 赋值时，必须假设它可能赋值。

### 9.2.4 到达定值

若存在一条从紧随定值 $d$ 后的程序点到达 $p$ 的路径，且路径上 $d$ 未被杀死（无对同一变量的其他定值），则定值 $d$ **到达**程序点 $p$。用途：判断 $x$ 在 $p$ 是否为常量、是否未定值先使用（在流图入口为每个变量引入哑定值）。

**传递函数**（生成-杀死形式）：

$$f_d(x) = gen_d \cup (x - kill_d) \tag{9.1}$$

$gen_d = \{d\}$，$kill_d$ 是程序中其他对 $u$ 的定值。基本块的传递函数 $f_B(x) = gen_B \cup (x - kill_B)$，$gen_B$ 是**向下可见**的定值（未被同一块中较后的同变量定值杀死）。

**方程**（前向，交汇运算 $\cup$）：

$$\text{OUT}[\text{ENTRY}] = \emptyset;\quad \text{OUT}[B] = gen_B \cup (\text{IN}[B] - kill_B);\quad \text{IN}[B] = \bigcup_{P \in \text{pred}(B)} \text{OUT}[P]$$

**算法 9.11 到达定值**（求最小不动点）：

```
1) OUT[ENTRY] = ∅;
2) for (除 ENTRY 之外的每个基本块 B) OUT[B] = ∅;
3) while (某个 OUT 值发生了改变)
4)    for (除 ENTRY 之外的每个基本块 B) {
5)       IN[B] = ∪_{P ∈ pred(B)} OUT[P];
6)       OUT[B] = gen_B ∪ (IN[B] - kill_B);
7)    }
```

$\text{OUT}[B]$ 只增不减，定值集合有限，算法必然终止。流图结点数是迭代次数上限（定值可沿无环路径到达）。定值集合可用位向量表示，运算用位向量逻辑运算实现，实际高效。适当安排访问顺序时平均迭代次数 <5（§9.6.7）。

### 9.2.5 活跃变量分析

变量 $x$ 在点 $p$ 的值是否会在某条从 $p$ 出发的路径中使用——是则**活跃**，否则**死**。用途：寄存器分配（值在块尾死则不必保存；所有寄存器占用时优先用存放死值的寄存器）。

**定义**：$def_B$ = 在 $B$ 中先于任何使用被定值的变量集；$use_B$ = 在 $B$ 中先于任何定值被使用的变量集。

**方程**（逆向，交汇运算 $\cup$）：

$$\text{IN}[\text{EXIT}] = \emptyset;\quad \text{IN}[B] = use_B \cup (\text{OUT}[B] - def_B);\quad \text{OUT}[B] = \bigcup_{S \in \text{succ}(B)} \text{IN}[S]$$

**算法 9.14 活跃变量**（算法 9.11 的逆向版本）：

```
IN[EXIT] = ∅;
for (除 EXIT 之外的每个基本块 B) IN[B] = ∅;
while (某个 IN 值发生了改变)
    for (除 EXIT 之外的每个基本块 B) {
        OUT[B] = ∪_{S ∈ succ(B)} IN[S];
        IN[B] = use_B ∪ (OUT[B] - def_B);
    }
```

与到达定值的异同：都用 $\cup$（只关心是否存在某路径）；但活跃性是**逆向**的——保证 $p$ 点对 $x$ 的使用能传递到 $p$ 之前的程序点。

### 9.2.6 可用表达式

若从入口到 $p$ 的**每条路径**都对 $x+y$ 求值，且最后一次求值后未对 $x$ 或 $y$ 赋值，则 $x+y$ 在 $p$ **可用**。基本块对 $x$ 或 $y$ 赋值后未重算 $x+y$ 则**杀死**它；一定对 $x+y$ 求值后未对 $x$、$y$ 赋值则**生成**它。用途：寻找全局公共子表达式。

计算块内生成集：语句 $x = y + z$ 后，① 把 $y+z$ 加入 $S$；② 删除 $S$ 中涉及 $x$ 的表达式（顺序很重要，$x$ 可能等于 $y$ 或 $z$）。

**方程**（前向，交汇运算 $\cap$）：

$$\text{OUT}[\text{ENTRY}] = \emptyset;\quad \text{OUT}[B] = e\text{-}gen_B \cup (\text{IN}[B] - e\text{-}kill_B);\quad \text{IN}[B] = \bigcap_{P \in \text{pred}(B)} \text{OUT}[P]$$

关键是 $\cap$：只有表达式在**所有**前驱块尾可用，才在块首可用。内部结点初始化为全集 $U$（先给大近似值再消减，求最大解）；到达定值初始化为 $\emptyset$（先给小近似值再增大，求最小解）。把不可用表达式当可用会改变程序计算结果（不安全）；把可用当不可用只会失去改进机会（保守）。

### 9.2.7 小结

三个数据流问题对比（图 9-21）：

| | 到达定值 | 活跃变量 | 可用表达式 |
| :--- | :--- | :--- | :--- |
| 方向 | 前向 | 逆向 | 前向 |
| 交汇运算 $\wedge$ | $\cup$ | $\cup$ | $\cap$ |
| 边界条件 | $\text{OUT}[\text{ENTRY}] = \emptyset$ | $\text{IN}[\text{EXIT}] = \emptyset$ | $\text{OUT}[\text{ENTRY}] = \emptyset$ |
| 初始值（内部点） | $\emptyset$ | $\emptyset$ | $U$（全集） |
| 性质 | 最小不动点 | 最小不动点 | 最大不动点 |

## 9.3 数据流分析框架

一个数据流分析框架由五部分组成：

1. 一个**值域 $V$**；
2. 一个**半格**（$V$ + 交汇运算 $\wedge$）；
3. 一个从 $V$ 到 $V$ 的**传递函数族 $F$**；
4. 一个**边界条件**；
5. 一组**方程式**。

### 9.3.1 半格

**半格（semilattice）**：集合 $V$ 和二元交汇运算 $\wedge$，满足：

- **幂等**：$x \wedge x = x$
- **交换**：$x \wedge y = y \wedge x$
- **结合**：$(x \wedge y) \wedge z = x \wedge (y \wedge z)$

**顶元素** $\top$：$\top \wedge x = x$（对所有 $x$）。**底元素** $\bot$：$\bot \wedge x = \bot$。

**偏序** $\le$：$x \le y$ 当且仅当 $x \wedge y = x$。$\wedge$ 给出**最大下界（glb）**。

**例 9.18** 到达定值的半格：值域是定值集合的幂集 $2^U$，$\wedge = \cup$，$\top = \emptyset$，$\bot = U$。可用表达式：$\wedge = \cap$，$\top = U$，$\bot = \emptyset$。

### 9.3.2 传递函数

传递函数族 $F$ 是从 $V$ 到 $V$ 的函数集合，封闭于函数复合（$f, g \in F \Rightarrow g \circ f \in F$）且含幺函数 $f_I$。函数族**单调**：若 $x \le y$ 则 $f(x) \le f(y)$。函数族**可分配**：$f(x \wedge y) = f(x) \wedge f(y)$（可分配 $\Rightarrow$ 单调）。

### 9.3.3 通用框架的迭代算法

**算法 9.25**：初始化边界条件和内部点（前向问题初始化 $\text{OUT}$，逆向初始化 $\text{IN}$），然后反复迭代直到值不再改变。

- 若框架半格**单调**且**高度有穷**，迭代算法**必然收敛**。
- 若框架**可分配**，迭代算法收敛到**MOP（所有路径交汇）解**——最精确的解。

**半格的高度** = 所有上升链 $x_1 < x_2 < \dots < x_n$ 中 $<$ 关系个数的最大值。$n$ 个定值的到达定值半格高度为 $n$。

## 9.4 常量传播框架

常量传播是前向数据流问题。每个变量的半格（图 9-25）：顶元素 UNDEF（未定值），底元素 NAC（非常量），其他常量值无序但都比 UNDEF 小、比 NAC 大。

- $\wedge$：对任意 $v$，UNDEF $\wedge v = v$，NAC $\wedge v = \text{NAC}$，$c_1 \wedge c_2 = c_1$（若 $c_1 = c_2$）否则 NAC。
- 数据流值是变量到该半格某值的映射 $m$，$m \le m'$ 当且仅当对所有变量 $v$ 有 $m(v) \le m'(v)$。

**不可分配性**（例 9.26）：$x$、$y$ 在 $B_1$ 中为 2、3，在 $B_2$ 中为 3、2，$B_3$ 出口 $z = x + y = 5$。但算法在 $B_3$ 入口把 $x$、$y$ 都设为 NAC（未跟踪 $x$、$y$ 间的相关性），得 $z = \text{NAC}$——安全但不精确。

## 9.5 部分冗余消除

冗余的多种形式：公共子表达式（完全冗余）、循环不变表达式、**部分冗余**（只在部分路径上冗余）。CSE 和循环不变外提都是 PRE 的特例。

**完全冗余**：表达式 $b+c$ 在点 $p$ 是可用表达式（所有到达 $p$ 的路径都已求值且运算分量未变）。

**部分冗余**：表达式在某些但非全部路径上被冗余求值。

### 懒惰代码移动问题

四个条件：① 不能引入新的运算（不在原路径上计算的表达式不能被消除）；② 消除所有非预期执行的冗余；③ 计算保持不变；④ 优化后计算 $b+c$ 的次数不超过原程序。

### 懒惰代码移动算法

四个数据流分析：

| 分析 | 方向 | 交汇运算 | 作用 |
| :--- | :--- | :--- | :--- |
| 预期执行（很忙） | 逆向 | $\cap$ | 表达式在该点之后所有路径被使用 |
| 可用表达式 | 前向 | $\cap$ | 表达式在该点之前所有路径已求值 |
| 可后延表达式 | 前向 | $\cap$ | 表达式可推迟到何处 |
| 被使用表达式 | 逆向 | $\cup$ | 临时赋值是否被后续路径使用 |

- **最前放置** = 预期执行但不可用的程序点。
- **最后放置** = 不可再后延的程序点。
- 临时赋值若不被使用则可消除。

> 这四个分析填满了数据流分析的 $2 \times 2$ 方阵（前向/逆向 × $\cup$/$\cap$）。使用 $\cup$ 的分析关心"是否存在一条路径使某事为真"；使用 $\cap$ 的分析关心"是否对所有路径都为真"。

## 9.6 流图中的循环

### 9.6.1 支配结点

$d\ \text{dom}\ n$（$d$ 支配 $n$）：从入口结点到 $n$ 的每条路径都经过 $d$。

**直接支配结点（immediate dominator）**：除 $n$ 自身外，在从入口到 $n$ 的任何无环路径中离 $n$ 最近的支配结点。每个结点有唯一直接支配结点，故存在**支配结点树**。

**性质**：$\text{dom}$ 是传递的、反对称的；$a$、$b$ 同为 $n$ 的支配结点则 $a\ \text{dom}\ b$ 或 $b\ \text{dom}\ a$ 必有一个成立。

**算法 9.38**（前向数据流问题，交汇 $\cap$）：

| | |
| :--- | :--- |
| 域 | $N$ 的幂集 |
| 方向 | 前向 |
| 传递函数 | $f_B(x) = x \cup \{B\}$ |
| 边界条件 | $\text{OUT}[\text{ENTRY}] = \{\text{ENTRY}\}$ |
| 交汇运算 $\wedge$ | $\cap$ |
| 方程式 | $\text{OUT}[B] = f_B(\text{IN}[B])$；$\text{IN}[B] = \bigcap_{P \in \text{pred}(B)} \text{OUT}[P]$ |
| 初始化 | $\text{OUT}[B] = N$（全集） |

$d \ne n$ 时 $d\ \text{dom}\ n$ 当且仅当 $d$ 支配 $n$ 的所有前驱。

### 9.6.2 深度优先排序

从入口结点开始的深度优先搜索形成**深度优先生成树（DFST）**。**深度优先排序**是后序遍历的逆序。

**算法 9.41** $\text{search}(n)$：标记 visited，遍历后继，未访问则加入树并递归，最后赋 $\text{dfn}[n] = c$（$c$ 从结点总数倒数到 1）。

### 9.6.3 DFST 中的边分类

DFST 构造后，流图的边分三类：

1. **前进边（advancing edge）**：从结点到其真后代（DFST 中的边都是前进边）。
2. **后退边（retreating edge）**：从结点到其祖先（含自身）。
3. **交叉边（cross edge）**：两者互不为祖先。交叉边从右到左（按子结点加入顺序排列）。

**判据**：边 $m \to n$ 是后退边当且仅当 $\text{dfn}[m] \ge \text{dfn}[n]$。

### 9.6.4 回边和可归约性

**回边（back edge）** $a \to b$：头 $b$ 支配尾 $a$。

- 每条回边都是后退边，但后退边不一定是回边。
- **可归约流图（reducible）**：任何 DFST 中所有后退边都是回边。等价地，删除所有回边后流图无环。
- **不可归约流图**：回边在任何 DFST 中都是后退边，但每个 DFST 可能有额外的非回边后退边（集合随 DFST 不同）。

实践中流图几乎都可归约——只用 `if-then-else`、`while-do`、`continue`、`break` 等结构化控制流语句的程序，流图总是可归约的。

**例 9.44** 图 9-45 的不可归约流图：结点 1 指向 2、3，2 与 3 间有双向边。1 支配 2、3，但 2 不支配 3、3 不支配 2，故无回边。根据先访问 2 还是 3，边 $3 \to 2$ 或 $2 \to 3$ 是后退边但不是回边——环 2-3 可从两个不同地方进入。

### 9.6.5 流图的深度

流图的**深度** = 各无环路径上后退边数目的最大值。可归约流图中"后退边"即"回边"，深度独立于 DFST。深度不超过循环嵌套深度。

### 9.6.6 自然循环

**自然循环**的两个性质：

1. 唯一入口结点（**循环头 header**），支配循环中所有结点。
2. 存在进入循环头的回边。

给定回边 $n \to d$，其自然循环 = $d$ 加上不经过 $d$ 能到达 $n$ 的结点集。

**算法 9.46**：$\text{loop} = \{n, d\}$，标记 $d$ 为 visited，从 $n$ 对反向流图深度优先搜索，访问到的结点加入 loop。

- 可归约流图中所有后退边都是回边，每条后退边关联一个自然循环。
- 若两个自然循环有相同循环头且互不包含，则合并为一个。
- 最内层循环 = 不包含其他循环的循环。

### 9.6.7 迭代数据流算法的收敛速度

前向问题按**深度优先顺序**访问结点，逆向问题按**深度优先排序的逆序**。迭代轮次上限 = **流图深度 + 1**（到达定值沿无环路径传播，深度优先排序使一次迭代沿路径前进多个结点）。常见流图平均深度约 2.75，收敛快。可归约流图的支配结点问题第一轮迭代即可得到解。

## 9.7 基于区域的分析

**区域（region）**：流图中由一个结点 $n$（区域头）和所有能不经过 $n$ 到达 $n$ 的结点组成的集合，$n$ 支配区域中所有结点。

可归约流图中自然循环要么不相交要么嵌套。区域层次结构构造：① 每个基本块是叶子区域；② 从最内层循环开始，把自然循环从内到外塌缩成结点。

基于区域的框架除半格外还需要传递函数的半格（含交汇运算、组合运算符、闭包运算符）。

## 9.8 归纳变量消除

在可归约流图的循环层次结构上，基于区域分析识别归纳变量并消除。强度消减后若一组归纳变量步调一致，可删剩一个。例 9.7 中 $i$、$j$ 经强度消减后唯一用途是测试 $i \ge j$，用 $t_2 \ge t_4$ 替换后 $i$、$j$ 变成死变量，其赋值成为死代码。

## 9.9 第 9 章总结

- **优化的主要来源**：公共子表达式消除、复制传播、死代码消除、常量折叠、代码移动、归纳变量与强度消减——都是语义不变转换。
- **数据流分析三例**：到达定值（前向 $\cup$，最小不动点）、活跃变量（逆向 $\cup$，最小不动点）、可用表达式（前向 $\cap$，最大不动点）。
- **数据流框架**：值域 + 半格 + 传递函数族 + 边界条件 + 方程式。单调 + 有穷高度 $\Rightarrow$ 迭代收敛；可分配 $\Rightarrow$ 收敛到 MOP 解。
- **常量传播**：UNDEF/NAC/常量 半格，不可分配（不跟踪变量间相关性）。
- **部分冗余消除**：四个数据流分析填满 $2 \times 2$ 方阵，CSE 与循环不变外提是其特例。
- **支配结点**：前向 $\cap$，传递函数 $f_B(x) = x \cup \{B\}$，存在支配结点树。
- **回边 / 自然循环 / 可归约流图**：回边的头支配尾；自然循环有唯一循环头且支配所有结点；可归约流图所有后退边都是回边，删除回边后无环。结构化控制流的程序流图总是可归约的。
- **深度优先排序**：后序的逆序。前向问题按此序访问，逆向问题按逆序访问，迭代轮次上限 = 深度 + 1。

> **口诀**：**到达定值前向并集求最小，活跃变量逆向并集求最小，可用表达式前向交集求最大**；**回边头支配尾，自然循环唯一入口支配全部，可归约删回边无环**；**深度优先排前向，逆序访问走逆向，深度加一必收敛**；**CSE+复制传播+DCE 三连，强度消减换乘为加**。
