# 运行时刻环境

> 对应教材：第 7 章「运行时刻环境」（PDF p285–p330）。术语沿用笔记原文：**活动记录（activation record）**、**控制栈**、**访问链（access link）**、**显示表（display）**、**嵌套深度**、**存储管理器**、**垃圾回收**、**可达性**。

## 核心缩写

| 缩写 | 全称 | 中文 | 作用 |
| :--- | :--- | :--- | :--- |
| **AR** | Activation Record | 活动记录 | 过程每次调用在栈上创建的记录，存放返回地址、局部数据、访问链等 |
| | Access Link | 访问链 | 活动记录中的指针，指向直接外围过程的最近活动记录，用于访问非局部数据 |
| | Display | 显示表 | 辅助数组 $d[i]$，为每个嵌套深度保存指向最高活动记录的指针，替代访问链的链式查找 |
| | Garbage Collection | 垃圾回收 | 自动找出堆区中不再被程序使用的空间并重新分配 |

## 7.1 存储组织

每个正在执行的程序在逻辑地址空间上运行，划分为四个区域：

1. **代码区 Code**：静态确定，存放可执行目标代码，大小可在编译时刻确定。
2. **静态数据区 Static**：静态确定，存放全局常量和编译器生成的数据。
3. **堆区 Heap**：动态管理，存放运行时刻分配/释放的数据对象，大小编译时刻不可确定。
4. **栈区 Stack**：动态管理，存放过程活动记录，随调用/返回创建/删除，大小编译时刻不可确定。

堆和栈共用剩余空间，相互动态增长。

## 7.2 静态与栈式存储分配

- **静态分配**：名字在编译时刻绑定到存储位置。限制：不能递归调用（只有一个活动记录）、不能动态创建数据对象、名字类型不能随调用改变。
- **栈式分配**：活动记录在运行时刻压入/弹出栈。**活动记录的相对地址**用相对于记录中某已知位置的偏移量表示。寄存器 SP 指向栈顶活动记录的开始处。

**活动记录的典型内容**（从顶端到底端）：

1. 临时变量值
2. 局部数据
3. 保存的机器状态（返回地址、程序计数器、寄存器）
4. 访问链（若语言支持嵌套过程）
5. 控制链（指向调用者的活动记录，即动态链）
6. 实在参数

> **控制链（动态链）**指向调用者活动记录，用于过程返回时恢复 SP；**访问链（静态链）**指向直接外围过程的最近活动记录，用于按静态作用域访问非局部数据。

## 7.3 访问非局部数据

### 7.3.3–7.3.4 嵌套过程与嵌套深度

C 系列语言不支持嵌套过程（所有函数嵌套深度为 1）。ML、Pascal、Algol 60 等支持。**嵌套深度**：不内嵌在任何过程中的过程深度为 1；在深度 $i$ 的过程中定义的过程深度为 $i+1$。

### 7.3.5 访问链

在每个活动记录中加**访问链**：若 $p$ 直接嵌套在 $q$ 中，$p$ 的活动的访问链指向最近的 $q$ 的活动。访问链形成从栈顶出发、嵌套深度逐步递减的链路。

若栈顶过程 $p$（深度 $n_p$）需访问在包围它的深度 $n_q$ 的过程 $q$ 中定义的 $x$（$n_q \le n_p$）：从 $p$ 的活动记录沿访问链前进 $n_p - n_q$ 步，找到栈中最高的 $q$ 的活动记录，其中包含 $x$。

### 7.3.6 处理访问链（三种情况）

$q$ 显式调用 $p$ 时，设 $p$ 的访问链：

1. **$n_p > n_q$**（$p$ 嵌套较深）：$p$ 直接在 $q$ 中定义，$n_p = n_q + 1$，$p$ 的访问链指向 $q$ 的活动记录。
2. **$p = q$（递归）**：新活动记录的访问链与下面那条相同。
3. **$n_p < n_q$（$p$ 嵌套较浅）**：$q$ 必嵌套在某过程 $r$ 中，$p$ 直接在 $r$ 中定义。从 $q$ 的活动记录沿访问链前进 $n_q - n_p + 1$ 步找到最高的 $r$ 的活动记录，$p$ 的访问链指向它。等价方法：沿访问链前进 $n_q - n_p$ 步并拷贝该处的访问链。

### 7.3.7 过程型参数的访问链

过程 $p$ 作为参数传递给 $q$ 时，$q$ 可能不知 $p$ 的上下文。解决办法：调用者除传递 $p$ 的名字外，还传递 $p$ 对应的**正确访问链**。调用者总知道这个链（因为 $p$ 必在被调用者可访问的名字中）。

### 7.3.8 显示表

访问链的缺点：嵌套深度大时需沿长链查找。**显示表（display）**是辅助数组 $d$，为每个嵌套深度保存一个指向栈中最高活动记录的指针：$d[i]$ 指向最高的深度为 $i$ 的过程活动记录。

- 访问深度 $i$ 的过程 $q$ 的元素 $x$：直接查 $d[i]$ 找到 $q$ 的活动记录，按已知偏移量访问 $x$。编译器知道 $i$，生成直接访问代码，无需链式查找。
- **维护显示表**：深度 $n_p$ 的过程 $p$ 被调用时，若不是栈中第一个深度 $n_p$ 的活动记录，则在 $p$ 的活动记录中保存 $d[n_p]$ 的原值，令 $d[n_p]$ 指向 $p$；$p$ 返回时恢复 $d[n_p]$。可能出现 $d[i]$ 指向比 $d[j]$（$i<j$）更低的栈位置（交叉），这是正常的。

## 7.4 堆管理

**存储管理器**：分配和回收堆区空间的子系统，是应用程序与操作系统间的接口。对 C/C++（手动 `free`/`delete`）还负责实现空间回收；对 Java，内存回收由**垃圾回收器**完成。

存储管理器的两个基本功能：① 分配：接收分配请求，在空闲空间中找足够大的窗口放置对象；② 回收：接收释放请求，把存储块加入空闲空间表。

三个设计目标：

- **空间效率**：使程序所需堆空间总量最小（使碎片最少）。
- **程序效率**：充分利用存储子系统使程序更快（利用局部性）。
- **低开销**：分配和回收操作不应成为瓶颈。

### 7.4.2 存储层次结构

现代机器有多层存储：寄存器（纳秒级）→ L1/L2/L3 缓存 → 主存 → 磁盘（毫秒级）。访问不同存储区域耗时差异可达 $10^6$ 倍。数据密集型程序可从利用存储子系统的优化中获益。

### 7.4.3 局部性

程序访问内存的非随机聚集特性：

- **时间局部性**：刚被访问的存储位置很可能很快再次被访问。
- **空间局部性**：访问某地址后很可能很快访问其邻近地址。

利用局部性：把频繁访问的数据放寄存器/缓存；把相关数据放邻近位置。块分配（一次分配一大块连续空间给多个对象）可提高空间局部性。

### 7.4.4 碎片整理

堆区随分配/回收被分割成空闲块（窗口）和已用块。除非窗口大小恰好，否则切分窗口产生更小窗口。

- **Best-fit 策略**：把请求放入满足请求的最小可用窗口——保留大窗口给后续大请求，实践效果好。
- **First-fit 策略**：放入地址最低的能容纳请求的窗口——放置快但总体性能差。
- **碎片整理**：合并相邻空闲块成较大块。垃圾回收时移动所有已分配块到连续存储可消除碎片。

### 7.4.5 人工回收

C/C++ 中 `free`/`delete` 可能出错：① 未释放已不可达的对象（内存泄漏）；② 释放仍可达的对象（悬挂指针，后续引用造成错误）；③ 重复释放同一对象。工具如 Purify 可在运行时检测这些错误。

## 7.5–7.6 垃圾回收

**垃圾回收**：在堆区中找到不再被程序使用、可重新分配的空间。**可达性**：从**根集**（寄存器、栈、全局变量中的指针）出发能到达的对象是可达的，不可达的对象是垃圾。

### 7.6.1 基本技术

- **标记-清扫式**：标记阶段从根集出发标记所有可达对象；清扫阶段扫描整个堆区释放未标记对象。
- **标记并压缩**：标记后把所有可达对象移动到堆区一端，消除碎片。
- **拷贝回收器**：把对象从一个区域（From-space）复制到另一个区域（To-space），复制时压缩；From-space 剩余部分整体回收。Cheney 算法用广度优先复制。

### 7.6.2–7.6.3 标记-清扫的优化

Baker 算法用四个列表 Free、Unreached、Unscanned、Scanned 管理对象状态。对象从 Unreached → Unscanned（被发现可达）→ Scanned（已扫描子对象）→ Free（不可达，回收）。

### 7.6.4 标记并压缩

标记后进行多次扫描：① 计算每个可达对象的新地址（向前压缩）；② 更新指向这些对象的指针；③ 移动对象。消除碎片。

### 7.6.5 拷贝回收器

Cheney 算法：维护一个指向 To-space 中已复制对象队列的指针 Unscanned。从根集开始，遇到未复制的可达对象就复制到 To-space 尾部并加入队列；处理队列中每个对象时扫描其指针，对指向的对象重复。队列空时结束，From-space 整体回收。

### 7.6.6 开销比较

- 标记-清扫：开销与堆大小成正比（清扫扫描整个堆）。
- 标记并压缩：多趟扫描，开销与堆大小成正比。
- 拷贝回收：开销与可达对象数量成正比（不扫描垃圾），但需要双倍空间。

## 7.7 短停顿垃圾回收

- **增量式回收**：把可达性分析分成小单元，与增变者（mutator，即用户程序）交错运行。需要记录写操作以处理运行中变化的可达集合。三色抽象：白（未访问）、灰（待扫描）、黑（已扫描）。
- **世代垃圾回收**：根据对象已分配时间长短划分对象，较频繁回收新创建的对象（生命周期往往短）。区域 0 到 $i$ 组成目标集，序号大于 $i$ 的组成稳定集。为每个区域维护**被记忆集**（指向该区域对象且位于更高区域的稳定对象）。
- **列车算法**：每次只回收一部分垃圾，适合回收较成熟的对象。堆区分成列车，列车分成车厢，按车厢回收。

## 7.8 并行回收与保守回收

- **并行回收**：增量式和部分回收的思想经修改可用于多处理器并行回收。
- **保守回收器**：不要求精确知道哪些字是指针，把任何看起来像指针的值当作指针。可能漏报垃圾（把非指针误当指针指向的对象不回收），但不会误回收可达对象。

## 第 7 章总结

- **存储四区**：代码区、静态区、堆区、栈区。
- **活动记录**：过程每次调用在栈上创建，存放返回地址、局部数据、访问链/控制链、参数。静态分配不能递归；栈式分配支持递归。
- **访问非局部数据**：访问链（静态链）指向直接外围过程的最近活动记录；显示表 $d[i]$ 直接指向深度 $i$ 的最高活动记录，避免链式查找。
- **访问链三情况**：$n_p > n_q$ 指向 $q$；递归拷贝下方链；$n_p < n_q$ 前进 $n_q - n_p + 1$ 步找到 $r$。
- **堆管理**：存储管理器分配/回收；best-fit/first-fit 策略；碎片整理；局部性（时间/空间）。
- **垃圾回收**：标记-清扫、标记并压缩、拷贝回收（Cheney）；增量式、世代、列车；保守回收器。

> **口诀**：**代码静态堆栈四区**；**活动记录栈上创建，控制链回调用者，访问链找外围**；**访问链三步：深一指调用者，递归拷下方，浅一走差加一步**；**显示表 $d[i]$ 直接定位免链走**；**垃圾回收三法：标记清扫扫全堆、标记压缩消碎片、拷贝回收扫可达**；**世代回收新短老长，列车算法分车厢**。
