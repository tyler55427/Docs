## 5.1 语法制导的翻译

语法制导翻译的输入是源程序，输出可以是**翻译后的程序**（如中间代码）或**源程序的某种表示**（如注释语法分析树）。翻译过程通过**属性（attribute）**来描述：属性是与文法符号关联的**数据值**，可为编译过程的任意部分提供输入或产生输出。

### 5.1.1 属性的分类

用 $X.a$ 记号表示：$X$ 是文法符号，$a$ 是该符号的一个属性。

- **综合属性（synthesized attribute）**：若某个非终结符号 $X$ 的某个属性 $X.a$ 的值**仅依赖于** $X$ 本身或 $X$ 的**子结点**的属性值，则称 $X.a$ 是 $X$ 的一个综合属性。
- **继承属性（inherited attribute）**：若某个非终结符号 $X$ 的某个属性 $X.a$ 的值依赖于 $X$ 本身、$X$ 的**父结点**或 $X$ 的某个**兄弟结点**的属性值，则称 $X.a$ 是 $X$ 的一个继承属性。

> 注意：对于**终结符号**（如 $\text{digit}$），教材不区分综合/继承属性。终结符号的属性（如 $\text{digit.lexval}$）来自输入，不需要从其他结点传递。

**例 5.1（图 5-1）** 带求值功能的桌上计算器文法，属性 `val` 存放表达式的数值，`lexval` 是终结符号 $\text{digit}$ 的词法值：

| 产生式 | 语义规则 |
| :--- | :--- |
| 1) $L \rightarrow En$ | $L.\text{val} = E.\text{val}$ |
| 2) $E \rightarrow E_1 + T$ | $E.\text{val} = E_1.\text{val} + T.\text{val}$ |
| 3) $E \rightarrow T$ | $E.\text{val} = T.\text{val}$ |
| 4) $T \rightarrow T_1 * F$ | $T.\text{val} = T_1.\text{val} \times F.\text{val}$ |
| 5) $T \rightarrow F$ | $T.\text{val} = F.\text{val}$ |
| 6) $F \rightarrow (E)$ | $F.\text{val} = E.\text{val}$ |
| 7) $F \rightarrow \text{digit}$ | $F.\text{val} = \text{digit}.\text{lexval}$ |

这个 SDD 中所有属性都是**综合属性**：

> **S 属性的 SDD**：如果一个 SDD 的所有属性都是综合属性，则称该 SDD 是 **S 属性的（S-attributed）**。

### 5.1.2 注释语法分析树

**注释语法分析树（annotated parse tree）**：一棵带有属性值的语法分析树，且结点的属性值满足该文法中所有语义规则。

求值时**必须**按拓扑顺序处理：对任一结点 $N$，只有在 $N$ 的子结点的属性值全部求完之后，才可以计算 $N$ 上的属性。

> **循环依赖反例**：$A \rightarrow B$，配规则 $A.s = B.i$；$B.i = A.s + 1$。此时 $A.s = B.i = A.s + 1$，无解——依赖图有环。**循环定义**的 SDD 无注释语法分析树。

> ⚠ **复杂性脚注**：判断一个 SDD 是否存在循环依赖是**可判定**的，但所需时间是**指数级**的——即使在 $P = NP$ 的前提下亦然。因此实践中不靠算法判定，而是靠人的构造习惯。

**例 5.2（图 5-3）** 输入 `3*5+4n` 的注释语法分析树，根结点 $L.\text{val} = 19$：

```
        L
       / \
      E   n
      |
      +
     / | \
    E  +  T
    |       |
    *       4
   / | \
  T  *  F
  |      |
  T      5
  |
  F
  |
  3
```

### 5.1.3 继承属性

有些翻译无法只靠综合属性完成——当**产生式体中位置较右的符号需要用到位置较左的符号的信息**时。

**例 5.3（图 5-4）** 用 $T \rightarrow FT'$ 代替左递归的 $T \rightarrow T_1 * F$，以便能计算 $3 * 5$ 这类乘法串：

| 产生式 | 语义规则 |
| :--- | :--- |
| $T \rightarrow FT'$ | $T'.\text{inh} = F.\text{val}$<br>$T.\text{val} = T'.\text{syn}$ |
| $T' \rightarrow * FT'_1$ | $T'_1.\text{inh} = T'.\text{inh} \times F.\text{val}$<br>$T'_1.\text{syn} = T'_1.\text{syn}$ |
| $T' \rightarrow \epsilon$ | $T'.\text{syn} = T'.\text{inh}$ |
| $F \rightarrow \text{digit}$ | $F.\text{val} = \text{digit}.\text{lexval}$ |

这里 $T'.\text{inh}$ 是**继承属性**：它把左边的 $F.\text{val}$ 沿递归串向下传递；$T'.\text{syn}$ 是综合属性，把累计结果向上传回 $T.\text{val}$。

**例 5.5（图 5-7）** 输入 $3 * 5$ 的依赖图中，虚线是语法分析树的边，实线是依赖边——可以看到 $F.\text{val} = 3$ 沿 `inh` 边向下流动，再乘上 $5$。

## 5.2 语义规则求值

### 5.2.1 依赖图

一个 SDD 的语义规则决定了属性值之间的**依赖关系**。构造依赖图的三条规则：

1. **结点**：为每一个文法符号实例关联的每一个属性（含叶子结点的属性、以及语义规则的哑属性）建一个结点。
2. **综合属性的边**：对于一条用子结点属性定义综合属性的规则，从每个子结点属性指向该综合属性。
3. **继承属性的边**：对于一条计算继承属性的规则，从该规则中出现的**所有属性**指向这个继承属性。

**例 5.4（图 5-6）** 桌上计算器 SDD 中 $L \rightarrow En$：$L.\text{val} \leftarrow E.\text{val}$。

### 5.2.2 拓扑排序与存在性

**存在性定理**：如果一个 SDD 的依赖图**没有环**，则它一定存在拓扑排序。

**证明思路（构造性）**：从一个**没有前驱**的结点 $n$ 开始，把它从图中删除；此时可能有新的结点没有前驱，继续删除；反复进行直到图变空。如此删除的顺序即拓扑排序。若图有环，则环上所有结点永远都有前驱，算法终止时图中仍剩结点。

**例 5.6** 图 5-3 的依赖图有拓扑排序 $6, 12, 5, 3, 11, 4, 2, 1$ 等（非唯一）。

### 5.2.3 S 属性 SDD 的求值

**S 属性 SDD 可以在语法分析树的**后序遍历（postorder）**中求值**：

```
postorder(N)
    for (从左边开始，对 N 的每个子结点 C) postorder(C);
    对 N 关联的各个属性求值;
```

> **关键联系**：自底向上的语法分析过程本身就是在对语法分析树做**后序遍历**——这正是 S 属性 SDD 能与自底向上分析器无缝结合的原因（§5.4.1）。

### 5.2.4 L 属性 SDD

**L 属性 SDD（L-attributed）**：如果一个 SDD 的所有继承属性都来自**下面三类**之一，则称它是 L 属性的：

1. **产生式头 $A$ 的继承属性**；
2. 位于 $X_i$ **左边**的文法符号实例 $X_1, X_2, \dots, X_{i-1}$ 相关的**继承属性或综合属性**；
3. 和 $X_i$ 的实例本身相关的继承属性或综合属性，**但由 $X_i$ 的全部属性组成的依赖图中不存在环**。

从语法分析树的角度看：L 属性 SDD 中的每个继承属性只使用「**来自于上边或左边**」的结点信息。

**例 5.8** 图 5-4 的 SDD 是 L 属性的：规则 $T'.\text{inh} = F.\text{val}$ 中的 $F$ 出现在 $T'$ 的左边；规则 $T'_1.\text{inh} = T'.\text{inh} \times F.\text{val}$ 中使用的是产生式头的继承属性 $T'.\text{inh}$ 以及 $T'_1$ 左边的 $F.\text{val}$。其余属性都是综合属性。

**例 5.9** 任何包含下列产生式和规则的 SDD **既非 S 属性也非 L 属性**：

$$
\begin{array}{cc}
\text{产生式} & \text{语义规则} \\
A \rightarrow BC & A.s = B.b;\ B.i = f(C.c, A.s)
\end{array}
$$

第一条规则合法（综合属性用子结点定义）。第二条定义继承属性 $B.i$，所以不可能是 S 属性的；而且 $C.c$ 用来定义 $B.i$，而 $C$ 位于 $B$ 的**右边**，故也不是 L 属性的。

### 5.2.5 具有受控副作用的语义规则

实践中翻译会有副作用（打印机打印结果、符号表添加类型）。两种控制方法：

1. **允许附带副作用**：只要按依赖图的**任何拓扑顺序**求值都能产生"正确"的翻译结果，就允许副作用存在。
2. **约束求值顺序**：添加约束使得任何允许的求值顺序都产生相同结果。这些约束可看作隐含加入依赖图的边。

**例（例 5.1 的修改）**：
$$L \rightarrow En \qquad print(E.\text{val})$$

`print(E.val)` 这样的规则被视为**与产生式头相关的哑综合属性（dummy attribute）的定义**。该 SDD 在任何拓扑顺序下都产生相同的打印结果，因为打印语句总是在 $E.\text{val}$ 计算完之后才执行。

### 5.2.6 例 5.10：类型声明的 SDD

**图 5-8** 处理简单声明 $D$ 的 SDD，其中 $T$ 是基本类型，$L$ 是标识符列表：

| 产生式 | 语义规则 |
| :--- | :--- |
| 1) $D \rightarrow TL$ | $L.\text{inh} = T.\text{type}$ |
| 2) $T \rightarrow \text{int}$ | $T.\text{type} = \text{integer}$ |
| 3) $T \rightarrow \text{float}$ | $T.\text{type} = \text{float}$ |
| 4) $L \rightarrow L_1,\ id$ | $L_1.\text{inh} = L.\text{inh}$<br>$addType(id.\text{entry}, L.\text{inh})$ |
| 5) $L \rightarrow id$ | $addType(id.\text{entry}, L.\text{inh})$ |

- $L.\text{inh}$ 的作用是将声明的类型沿标识符列表**向下传递**，使它能被加入相应的符号表条目。
- `addType` 的两个参数：`id.entry`（词法分析时得到的指向符号表对象的值）与 $L.\text{inh}$（要赋予的类型值）。
- **例 5.10（图 5-9）**：输入 `float id₁, id₂, id₃` 的依赖图，结点 1、2、3 是各 `id` 叶子的 `entry` 属性，结点 6、8、10 是 `addType` 的**哑属性**，结点 4 是 $T.\text{type}$（求值起点），结点 5、7、9 是 $L.\text{inh}$ 的三次拷贝。
- 该 SDD **不检查**一个标识符是否被重复声明；可通过增加检查修改。

## 5.3 语法制导翻译的应用

### 5.3.1 抽象语法树的构造

一棵语法树的每个结点代表一个程序构造，其子结点代表该构造的有意义组成部分。表达式的抽象语法树用**带适当数量字段的对象**实现：

- **叶子结点**：对象有 `op` 字段 + 存放词法值的附加字段。构造函数 `Leaf(op, val)`。
- **内部结点**：`op` 字段 + 与子结点个数相同的附加字段。构造函数 `Node(op, c_1, c_2, \dots, c_k)`。

**例 5.11（图 5-10）** 为只含 $+$、$-$ 的表达式构造抽象语法树的 S 属性 SDD（$+$、$-$ 同优先级、左结合）：

| 产生式 | 语义规则 |
| :--- | :--- |
| 1) $E \rightarrow E_1 + T$ | $E.\text{node} = \text{new Node}('+', E_1.\text{node}, T.\text{node})$ |
| 2) $E \rightarrow E_1 - T$ | $E.\text{node} = \text{new Node}('-', E_1.\text{node}, T.\text{node})$ |
| 3) $E \rightarrow T$ | $E.\text{node} = T.\text{node}$ |
| 4) $T \rightarrow (E)$ | $T.\text{node} = E.\text{node}$ |
| 5) $T \rightarrow \text{id}$ | $T.\text{node} = \text{new Leaf}(\text{id}, \text{id}.\text{entry})$ |
| 6) $T \rightarrow \text{num}$ | $T.\text{node} = \text{new Leaf}(\text{num}, \text{num}.\text{val})$ |

**构造原则**：只有在**使用非平凡产生式**（不是单产生式、不是括号产生式）时才创建结点。产生式 3、4 属于"平凡"的传递性产生式，只拷贝子结点的 `node`。

**图 5-12** 输入 $a - 4 + c$ 的构造步骤：

```
1) p1 = new Leaf(id, entry-a);
2) p2 = new Leaf(num, 4);
3) p3 = new Node('-', p1, p2);
4) p4 = new Leaf(id, entry-c);
5) p5 = new Node('+', p3, p4);
```

**例 5.12（图 5-13）** 用 L 属性 SDD 完成相同工作（自顶向下场景）：

| 产生式 | 语义规则 |
| :--- | :--- |
| 1) $E \rightarrow TE'$ | $E.\text{node} = E'.\text{syn}$<br>$E'.\text{inh} = T.\text{node}$ |
| 2) $E' \rightarrow +TE'_1$ | $E'_1.\text{inh} = \text{new Node}('+', E'.\text{inh}, T.\text{node})$<br>$E'.\text{syn} = E'_1.\text{syn}$ |
| 3) $E' \rightarrow -TE'_1$ | $E'_1.\text{inh} = \text{new Node}('-', E'.\text{inh}, T.\text{node})$<br>$E'.\text{syn} = E'_1.\text{syn}$ |
| 4) $E' \rightarrow \epsilon$ | $E'.\text{syn} = E'.\text{inh}$ |
| 5) $T \rightarrow (E)$ | $T.\text{node} = E.\text{node}$ |
| 6) $T \rightarrow \text{id}$ | $T.\text{node} = \text{new Leaf}(\text{id}, \text{id}.\text{entry})$ |
| 7) $T \rightarrow \text{num}$ | $T.\text{node} = \text{new Leaf}(\text{num}, \text{num}.\text{val})$ |

$E'.\text{inh}$ 表示**至今为止构造得到的部分抽象语法树的根**：结点 5 处对应 $a$，结点 6 处对应 $a - 4$，结点 9 处对应 $a - 4 + c$。$syn$ 沿语法分析树向上把根结点传回 $E.\text{node}$。图 5-14 的依赖图与图 5-7 高度相似——两者都体现了「继承属性沿递归串向下传递部分结果」。

### 5.3.2 类型的结构

**例 5.13（经典例题）** C 语言中 `int[2][3]` 可读作"由两个数组组成的数组，子数组中有三个整数"。对应的类型表达式为 $\text{array}(2, \text{array}(3, \text{integer}))$，用图 5-15 的树表示：运算符 `array` 有两个参数——一个数字、一个类型；返回一个标号为 `array` 的结点，其两个子结点分别表示数字和类型。

**图 5-16** 用 SDD 生成基本类型或数组类型：

| 产生式 | 语义规则 |
| :--- | :--- |
| $T \rightarrow BC$ | $T.t = C.t$<br>$C.b = B.t$ |
| $B \rightarrow \text{int}$ | $B.t = \text{integer}$ |
| $B \rightarrow \text{float}$ | $B.t = \text{float}$ |
| $C \rightarrow [\text{num}]C_1$ | $C.t = \text{array}(\text{num}.\text{val}, C_1.t)$<br>$C_1.b = C.b$ |
| $C \rightarrow \epsilon$ | $C.t = C.b$ |

- $B$ 与 $T$ 有综合属性 $t$（表示类型）；$C$ 有**继承属性 $b$** 与**综合属性 $t$**。
- $b$ 把一个基本类型**沿树向下传递**，$t$ 则收集最终结果**向上综合**。
- **例 5.13（图 5-17）** 输入 `int[2][3]`：`integer` 从 $B$ 出发沿 $C$ 的链通过 `b` 向下传递；最后的数组类型沿 $C$ 的链通过 `t` 向上综合。根结点处 $C$ 通过 $C.b$ 从 $B$ 继承类型；最右边的 $C$ 用 $C \rightarrow \epsilon$ 得 $C.t = C.b$；$C \rightarrow [\text{num}]C_1$ 把运算符 `array` 作用于 `num.val` 与 $C_1.t$。

> **为什么用继承属性**：当语法分析树的结构与输入的抽象语法树的结构**不同**时，继承属性可将信息从语法分析树的一部分传递到另一部分。此处结构不匹配是**语言设计本身**引起的，而非语法分析方法的约束。

## 5.4 语法制导的翻译方案

### SDT 的定义与实现

**SDT**：在其产生式体中**嵌入了程序片段**的上下文无关文法。这些程序片段称为**语义动作**，可出现在产生式体中的任何地方，惯例是加花括号。若花括号本身作为文法符号出现，需加引号。

**通用实现方法**：① 建立语法分析树；② 按**前序遍历**（从左到右深度优先）执行语义动作。§5.4.3 给出这样的例子。

通常 SDT 在语法分析过程中实现，**不真的构造语法分析树**。本节的两种可实现组合：

1. 基础文法可用 **LR** 技术分析，且 SDD 是 **S 属性**的；
2. 基础文法可用 **LL** 技术分析，且 SDD 是 **L 属性**的。

**判据**：把每个内嵌语义动作替换为一个独有的**标记非终结符号（marker nonterminal）** $M$，其中 $M$ 只有一个产生式 $M \rightarrow \epsilon$。若带标记的文法可被某个方法分析，则该 SDT 可在语法分析过程中实现。

> 在语法分析过程中，产生式体中的一个动作在它**左边的所有文法符号**都被匹配之后**立刻**执行。

### 5.4.1 后缀翻译方案

文法可自底向上分析且 SDD 是 S 属性时：SDT 中**每个动作都放在产生式的最后**，在按该产生式归约时执行。这样的 SDT 称**后缀翻译方案（postfix translation scheme）**。

**例 5.14（图 5-18）** 后缀 SDT 实现桌上计算器，唯一改动是第一个产生式的动作改为打印结果：

```
L    ->  E  n          { print(E.val); }
E    ->  E1 + T        { E.val = E1.val + T.val; }
E    ->  T             { E.val = T.val; }
T    ->  T1 * F        { T.val = T1.val * F.val; }
T    ->  F             { T.val = F.val; }
F    ->  (E)           { F.val = E.val; }
F    ->  digit         { F.val = digit.lexval; }
```

因为基础文法是 LR 的且 SDD 是 S 属性的，这些动作可以和归约步骤一起正确执行。

### 5.4.2 后缀 SDT 的语法分析栈实现

**图 5-19** 语法分析栈的每个记录包含两个字段——**状态/文法符号**字段在上、**属性**字段在下。归约 $A \rightarrow XYZ$ 时，$X.x$、$Y.y$、$Z.z$ 都位于已知位置，计算完属性后 $A$ 和它的属性被放到栈顶（即原来 $X$ 记录的位置）。

```
        +-----+-----+-----+
        |  X  |  Y  |  Z  |   状态 / 文法符号
        +-----+-----+-----+
        | X.x | Y.y | Z.z |   综合属性
        +-----+-----+-----+
                      ^
                      | 栈顶
```

对于小型属性把记录变得足够大即可；若属性无大小限制（如字符串），则**在栈记录中放指针**，把实际值放在栈外的共享存储中。

**例 5.15（图 5-20）** 显式操作栈的桌上计算器（`stack[top]` 是栈顶，`stack[top-1]` 是栈顶之下）：

| 产生式 | 语义动作 |
| :--- | :--- |
| $L \rightarrow En$ | `{ print(stack[top - 1].val); top = top - 1; }` |
| $E \rightarrow E_1 + T$ | `{ stack[top - 2].val = stack[top - 2].val + stack[top].val; top = top - 2; }` |
| $E \rightarrow T$ | *(空)* |
| $T \rightarrow T_1 * F$ | `{ stack[top - 2].val = stack[top - 2].val * stack[top].val; top = top - 2; }` |
| $T \rightarrow F$ | *(空)* |
| $F \rightarrow (E)$ | `{ stack[top - 2].val = stack[top - 1].val; top = top - 2; }` |
| $F \rightarrow \text{digit}$ | *(空)* |

**要点**：

- $E \rightarrow T$、$T \rightarrow F$、$F \rightarrow \text{digit}$ 无动作——栈长度未变，栈顶属性直接提升为产生式头的属性。
- $F \rightarrow (E)$ 值不变但**归约消除了两个栈位置**，需把值移到归约后的位置。
- $L \rightarrow En$ 中 $E$ 的属性在栈顶下两个位置，归约后弹出一个符号，即 `top = top - 1`。
- 省略了对记录第一字段（LR 状态或文法符号）的操作：LR 语法分析表给出每次归约后的新状态（见算法 4.44），直接放到新的栈顶记录即可。

### 5.4.3 产生式内部带有语义动作的 SDT

动作可放在产生式体中的**任何位置**。当动作左边的所有符号都被处理后立刻执行：

- 自底向上：当 $X$ 的本次出现位于**语法分析栈的栈顶**时，立刻执行动作 $a$。
- 自顶向下：在试图展开 $Y$ 的本次出现（$Y$ 为非终结符号）或检测 $Y$（$Y$ 为终结符号）**之前**执行动作 $a$。

**例 5.16（图 5-21）** 有问题的 SDT——把桌上计算器改成打印**前缀表示**：

| | |
| :--- | :--- |
| 1) | $L \rightarrow En$ |
| 2) | $E \rightarrow \{ print('+'); \} E_1 + T$ |
| 3) | $E \rightarrow T$ |
| 4) | $T \rightarrow \{ print('*'); \} T_1 * F$ |
| 5) | $T \rightarrow F$ |
| 6) | $F \rightarrow (E)$ |
| 7) | $F \rightarrow \text{digit}\ \{ print(\text{digit}.\text{lexval}); \}$ |

**这个 SDT 无法在自顶向下或自底向上的语法分析过程中实现**：语法分析程序必须在还**不知道**输入中运算符是 $*$ 还是 $+$ 的时候，就执行打印符号的操作。用标记非终结符号 $M_2$、$M_4$ 代替这两个动作，移入-归约分析器在处理输入 $\text{digit}$（如 3）时会产生冲突——无法确定是按 $M_2 \rightarrow \epsilon$ 归约、按 $M_4 \rightarrow \epsilon$ 归约，还是移入数字。

**任何 SDT 都可以按下面方法实现**：

1. 忽略语义动作，对输入进行语法分析并产生一棵语法分析树。
2. 检查每个内部结点 $N$（其产生式为 $A \rightarrow \alpha$），将 $\alpha$ 中的各个动作当作 $N$ 的附加子结点加入，使 $N$ 的子结点从左到右与 $\alpha$ 中的符号及动作完全一致。
3. 对这棵语法树进行**前序遍历**，访问到以某个动作为标号的结点时立刻执行该动作。

**图 5-22** 对 $3 * 5 + 4$ 执行前序遍历即得到前缀形式 $+ * 354$。

### 5.4.4 从 SDT 中消除左递归

**原则**：**当转换文法的时候，将动作当成终结符号处理。** 因为文法转换保持了符号串中终结符号的顺序，所以动作在任何从左到右的语法分析过程中都按相同顺序执行。

对
$$A \rightarrow A\alpha \mid \beta$$
应用标准消除技巧（引入 $R$ 生成"其余部分"）：
$$A \rightarrow \beta R;\qquad R \rightarrow \alpha R \mid \epsilon$$

**例 5.17** 中缀转后缀 SDT 的左递归消除：$\alpha = +T\{print('+');\}$、$\beta = T$，得

```
E  ->  T R
R  ->  + T { print('+'); } R
R  ->  epsilon
```

#### 通用方案：带综合属性的左递归消除

假设
$$A \rightarrow A_1Y \{ A.a = g(A_1.a, Y.y) \}\qquad A \rightarrow X \{ A.a = f(X.x) \}$$

其中 $A.a$ 是综合属性。基础文法改为 $A \rightarrow XR$、$R \rightarrow YR \mid \epsilon$。此时：

- 引入**继承属性 $R.i$** 累计从 $A.a$ 起不断应用 $g$ 的结果；
- 引入**综合属性 $R.s$**：当 $R$ 不再生成 $Y$（即 $R \rightarrow \epsilon$ 出现）时开始计算，然后沿树向上拷贝，最终成为 $A.a$。

**图 5-23** 消除后缀 SDD 中的左递归：

```
A -> X  { R.i = f(X.x) }  R  { A.a = R.s }
R -> Y  { R1.i = g(R.i, Y.y) }  R1  { R.s = R1.s }
R -> epsilon  { R.s = R.i }
```

继承属性 $R.i$ 在产生式体中 $R$ 的一次使用**之前**完成求值；综合属性 $A.a$ 和 $R.s$ 在产生式的**结尾**完成求值——计算所需值都已在左边算好。

### 5.4.5 L 属性定义的 SDT

**转换规则**（两条）：

1. 把计算某个非终结符号 $A$ 的**继承属性**的动作插入到产生式中**紧靠在 $A$ 的本次出现之前**的位置。若 $A$ 的多个继承属性以无环方式相互依赖，需对这些属性的求值动作排序，先计算被需要的属性。
2. 将计算一个产生式头的**综合属性**的动作放置在**产生式的最右端**。

**例 5.18（图 5-24–5-26）** 数学公式排版语言 Eqn 的 `a sub i sub j` 表示 $a_{ij}$。文法
$$B \rightarrow B_1B_2 \mid B_1\ \text{sub}\ B_2 \mid (B_1) \mid \text{text}$$

四种方框：① 并列；② 方框 + 下标；③ 圆括号分组；④ 文本串。

**四个几何量**：

| 属性 | 类型 | 含义 |
| :--- | :--- | :--- |
| $B.ps$ | 继承属性 | 字体大小（point size）；不在下标中默认 10 点，下标为其父方框的 70% |
| $B.ht$ | 综合属性 | 高度（height）：从方框顶部到基线的距离 |
| $B.dp$ | 综合属性 | 深度（depth）：从基线到方框底部的距离 |
| 基线 baseline | — | 对应文本行底部的垂直位置（不考虑 $g$ 等下伸字符） |

**图 5-25** 方框排版的 SDD：

| 产生式 | 语义规则 |
| :--- | :--- |
| 1) $S \rightarrow B$ | $B.ps = 10$ |
| 2) $B \rightarrow B_1B_2$ | $B_1.ps = B.ps$<br>$B_2.ps = B.ps$<br>$B.ht = \max(B_1.ht, B_2.ht)$<br>$B.dp = \max(B_1.dp, B_2.dp)$ |
| 3) $B \rightarrow B_1\ \text{sub}\ B_2$ | $B_1.ps = B.ps$<br>$B_2.ps = 0.7 \times B.ps$<br>$B.ht = \max(B_1.ht, B_2.ht - 0.25 \times B.ps)$<br>$B.dp = \max(B_1.dp, B_2.dp + 0.25 \times B.ps)$ |
| 4) $B \rightarrow (B_1)$ | $B_1.ps = B.ps$<br>$B.ht = B_1.ht$<br>$B.dp = B_1.dp$ |
| 5) $B \rightarrow \text{text}$ | $B.ht = \text{getHt}(B.ps, \text{text}.\text{lexval})$<br>$B.dp = \text{getDp}(B.ps, \text{text}.\text{lexval})$ |

- 产生式 2（并列）：字体大小沿语法分析树**向下拷贝**，高度深度沿树**向上取最大值**。
- 产生式 3（下标）：下标字体为父方框的 70%；基线向下移动父字体点数大小的 25%——所以 $B.ht$ 里是 $B_2.ht - 0.25 \times B.ps$、$B.dp$ 里是 $B_2.dp + 0.25 \times B.ps$。
- 产生式 5：`getHt`/`getDp` 查字体表格确定文本串中全部字符的最大高度和最大深度。
- **图 5-26** 是按上述两条规则转换得到的 SDT（动作分布在产生式体中相应位置）。

**例 5.19（图 5-27）** 为 while 语句生成中间代码的 L 属性 SDD：
$$S \rightarrow \text{while}(C)S_1$$

**属性定义**：

| 属性 | 类型 | 含义 |
| :--- | :--- | :--- |
| $S.\text{next}$ | 继承 | $S$ 执行完必须执行的代码的开始处的标号 |
| $S.\text{code}$ | 综合 | 实现 $S$ 的中间代码序列，末尾有一条跳转到 $S.\text{next}$ 的指令 |
| $C.\text{true}$ | 继承 | $C$ 为真时执行的代码开始处的标号 |
| $C.\text{false}$ | 继承 | $C$ 为假时执行的代码开始处的标号 |
| $C.\text{code}$ | 综合 | 实现 $C$ 的代码，根据值为真/假跳转到 $C.\text{true}$ 或 $C.\text{false}$ |

**图 5-27** SDD：

```
S -> while ( C ) S1
    L1 = new();
    L2 = new();
    S1.next = L1;
    C.false = S.next;
    C.true  = L2;
    S.code  = label L1 || C.code || label L2 || S1.code
```

- `new()` 生成新的标号；$L1$ 是 while 代码的开始（$S_1.\text{next}$ 指向它，即 $S_1$ 执行完跳回这里）；$L2$ 是 $S_1$ 代码的开始（$C$ 为真时跳向它）。
- $C.\text{false} = S.\text{next}$，因为条件为假时执行 $S$ 代码之后的代码。
- `||` 是连接中间代码片段的符号。
- 该 SDD 是 L 属性的。

**图 5-28** 转换后的 SDT：

```
S -> while (
        { L1 = new();  L2 = new();
          C.false = S.next;  C.true = L2; }
      C
        { S1.next = L1; }
      S1
        { S.code = label L1 || C.code || label L2 || S1.code; }
    )
```

$L1$、$L2$ 是变量而非属性——若把语义动作当作**哑非终结符号**处理，则这样的变量可当作哑非终结符号的综合属性。因为它们不依赖其他属性，可分配到产生式的第一个语义动作中。

## 5.5 实现 L 属性的 SDD

有六种方法：

1. 建立语法分析树并注释（对任何非循环 SDD 都有效，§5.1.2）；
2. 构造语法分析树，加入动作，按前序执行（对任何 L 属性定义有效，§5.4.5）；
3. **递归下降语法分析器**：为每个非终结符号建立一个函数，**继承属性作为参数**接收，**综合属性作为返回值**（§5.5.1）；
4. **递归下降 + 边扫描边生成代码**（§5.5.2）；
5. **与 LL 语法分析器结合**：属性值放在语法分析栈中，规则从栈中已知位置取值（§5.5.3）；
6. **与 LR 语法分析器结合**：若基础文法是 LL 的，则总是可以自底向上处理（§5.5.4）。

### 5.5.1 递归下降语法分析中的翻译

函数 $A$ 的参数是 $A$ 的继承属性，返回值是 $A$ 的综合属性集合。函数体中：① 决定用哪个产生式展开 $A$；② 在输入中检查终结符号；③ 在局部变量中保存所有必要的属性值；④ 调用产生式体中非终结符号对应的函数，提供正确的参数（L 属性保证这些属性已在局部变量中算好）。

**例 5.20（图 5-29）** 用递归下降实现 while 语句的翻译：

```cpp
string S(label next) {
    string Scode, Ccode; /* 存放代码片段的局部变量 */
    label L1, L2;        /* 局部标号 */
    if (当前输入 == 词法单元 while) {
        读取输入;
        检查 '(' 是下一个输入符号，并读取输入;
        L1 = new();
        L2 = new();
        Ccode = C(next, L2);
        检查 ')' 是下一个输入符号，并读取输入;
        Scode = S(L1);
        return("label" || L1 || Ccode || "label" || L2 || Scode);
    } else /* 其他语句类型 */ {
        // ...
    }
}
```

> 实践中更高效的做法是让 $S$、$C$ 这样的函数返回**指向字符串记录的指针**，返回语句不真的把各组成部分连接起来，而是构造出一个**记录或记录树**，表示最终串的连接方式。

### 5.5.2 边扫描边生成代码

用属性表示代码并构造长串不能满足要求（拷贝、移动串字符耗时）。**主属性（primary attribute）** 的三个前提：

1. 存在一个（或几个）非终结符号的**主属性**（假设以字符串为值）；
2. 主属性是**综合属性**；
3. 对主属性求值的规则保证：① 主属性是将相关产生式体中的**非终结符号的主属性值连接**起来得到的（连接时可能包括其他非主属性的元素，如字符串 `label` 和标号 $L_1, L_2$ 的值）；② 各非终结符号的主属性值在连接运算中出现的**顺序**和这些符号在产生式体中的出现顺序**相同**。

**例 5.22（图 5-31）** 修改图 5-29 的函数，边扫描边生成 $S.\text{code}$ 的各个元素：

```c
void S(label next) {
    label L1, L2; /* 局部标号 */
    if (当前输入 == 词法单元 while) {
        读取输入;
        检查 '(' 是下一个输入符号，并读取输入;
        L1 = new();
        L2 = new();
        print("label", L1);
        C(next, L2);
        检查 ')' 是下一个输入符号，并读取输入;
        print("label", L2);
        S(L1);
    } else /* 其他语句类型 */
}
```

打印顺序：先 `label L1`，然后 $C$ 的代码，然后 `label L2`，最后 $S$ 递归调用的代码——与图 5-29 中返回的 $Scode$ 值完全相同。

> **主属性的类型**：字符串的限制太严格。**真实要求是所有主属性的类型的值必须能通过连接各个元素构造得到**。比如任何类型的**对象列表**都可以作为主属性的类型，只要列表的表示方法允许高效地在尾部加入元素。

**图 5-32** 是修改后的 SDT，把一个主属性的构造转变为发出这个属性的元素的语义动作：

```
S -> while ( { L1 = new();  L2 = new();
               C.false = S.next;  C.true = L2;
               print("label", L1); }
             C
             { S1.next = L1;
               print("label", L2); }
             S1
```

### 5.5.3 L 属性的 SDD 与 LL 语法分析

语法分析栈需扩展以存放**动作记录（action-record）**和**综合记录（synthesize-record）**：动作记录表示即将执行的语义动作，综合记录保存非终结符号的综合属性值。

**两条原则**：

- 非终结符号 $A$ 的**继承属性**放在表示 $A$ 的栈记录中。求值代码通常用**紧靠在 $A$ 的栈记录之上**的动作记录表示（L 属性→SDT 的转换方法保证了这一点）。
- 非终结符号 $A$ 的**综合属性**放在一个**单独的综合记录**中，位于栈中**紧靠 $A$ 记录之下**。

实践中可把几个记录组合成一个；但为解释基本思想，最好把不同目的的数据分别存放在不同记录中。动作记录包含指向将被执行的动作代码的指针。动作也可能出现在综合记录中，把其他记录中的综合属性**拷贝到栈中更低的位置**上——这样在综合属性所在记录被弹出栈之后，语法分析程序仍能在较低位置找到该属性的值。

**为什么需要属性临时拷贝**：LL 分析模拟最左推导。若 $u$ 是已匹配完成的输入，栈中包含文法符号序列 $\alpha$，使得 $S \Rightarrow^* u\alpha$。当分析器按 $A \rightarrow BC$ 展开时把栈顶的 $A$ 替换为 $BC$。若 $C$ 有继承属性 $C.i$，它可能不仅依赖 $A$ 的继承属性，还依赖 $B$ 的**所有**属性。因此必须在计算 $C.i$ 之前完成对 $B$ 的处理——若 $A$ 被弹出栈，其继承属性就随栈记录一起消失了。所有拷贝都发生在**对某个非终结符号的一次展开时创建的不同记录之间**，故每个记录都知道其他记录离它有多远，可以安全地写到下方的记录中。

**例 5.23（图 5-33、5-34）** 用 LL 分析实现图 5-32 的边扫描边生成 SDT。展开 $S$ 后栈中有 `while`、`(`、Action、$C$、Action、$S_1$（自顶向下分析惯例把栈顶显示在左边）。第一个动作执行时：

```
L1 = new();
L2 = new();
stack[top-1].false = snext;
stack[top-1].true  = L2;
stack[top-3].al1   = L1;
stack[top-3].al2   = L2;
print("label", L1);
```

`snext` 字段存放 $S.\text{next}$ 的拷贝（$S$ 被弹出时拷贝到该字段，稍后用于求 $C$ 的继承属性）；$L1$、$L2$ 的新值生成后写入 $C.\text{true}$，同时把 $L1$、$L2$ 拷贝到第二个动作记录的 `al1`、`al2` 字段供后续使用。$C$ 的记录字段是 `false`、`true`，$S_1$ 的记录字段是 `next`。

**例 5.24（图 5-35）** 把 $S.\text{code}$ 作为综合属性时的情况。归纳不变式：**每个具有代码的非终结符号都把它（字符串形式的）代码存放在栈中该符号的记录下方的综合记录中**。

- $S$ 的记录下有 $S$ 的综合记录（含 $S.\text{code}$ 字段）。
- 展开后栈中有 `while`、`(`、Action、$C$、Synthesize $C.\text{code}$、`)`、$S_1$、Synthesize $S_1.\text{code}$、Synthesize $S.\text{code}$。
- 第一个 Action 生成 $L1$、$L2$ 并拷贝到需要它们的继承属性（$S_1.\text{next}$ 和 $C.\text{true}$）中；最后两步把 $L1$、$L2$ 拷贝到 Synthesize $S_1.\text{code}$ 的记录中。
- $C.\text{code}$ 的综合记录成为栈顶时，其动作把 $C.\text{code}$ **拷贝到** $S_1.\text{code}$ 的综合记录中，为后续连接做准备。
- Synthesize $S_1.\text{code}$ 到达栈顶时执行动作：

```
stack[top-1].code = "label" || l1 || C.code || "label" || l2 || S1.code;
```

- 最终结果放在栈中更低的 Synthesize $S.\text{code}$ 记录中。

> **处理 LR 文法上的 L 属性 SDD 是否可行？** 若 $B.i$ 依赖 $A$ 的继承属性且我们已归约到 $B$，此时尚未看到 $C$ 生成的输入，无法确定会扫描到 $A \rightarrow BC$ 的体，故此时还不能计算 $B.i$。等到归约得到 $C$ 后仍无法确定包含这个 $A$ 的是哪个产生式的体——决定被推迟到最后，实质就是"先构造语法分析树，再执行翻译"。

### 5.5.4 L 属性的 SDD 的自底向上语法分析

**给定一个以 LL 文法为基础的 L 属性 SDD，可以修改该文法并在 LR 语法分析过程中计算这个新文法之上的 SDD。** 三步骤：

1. 以 §5.4.5 的方法构造得到的 SDT 为起点（继承属性动作在非终结符号**之前**，综合属性动作在产生式**末端**）。
2. 对每个内嵌语义动作，引入**标记非终结符号** $M$ 替换它，每个位置不同的标记，都有产生式 $M \rightarrow \epsilon$。
3. 若 $M$ 在 $A \rightarrow \alpha\ a\ \beta$ 中替换了动作 $a$，对 $a$ 修改得到 $a'$，关联到 $M \rightarrow \epsilon$ 上。$a'$ 需要：
   - ① 将动作 $a$ 需要的 $A$ 或 $\alpha$ 中符号的任何属性作为 **$M$ 的继承属性**进行拷贝；
   - ② 按 $a$ 中的方法计算各属性，但将计算得到的这些属性作为 **$M$ 的综合属性**。

这个变换看似非法（动作访问未出现在 $M \rightarrow \epsilon$ 中的文法符号的属性），但实际上在 LR 语法分析树上实现动作时必要的属性总是可用——它们位于栈顶之下的**已知位置**上。

**例 5.25** LL 文法中存在 $A \rightarrow BC$，且 $B.i = f(A.i)$，SDT 片段
$$A \rightarrow \{ B.i = f(A.i); \} BC$$

引入标记 $M$（有继承属性 $M.i$ 与综合属性 $M.s$，前者是 $A.i$ 的拷贝、后者将成为 $B.i$）：

```
A  ->  M B C
M  ->  epsilon  { M.i = A.i;  M.s = f(M.i); }
```

$M$ 的规则中不可直接使用 $A.i$——但会设法安排分析栈：若即将进行到 $A$ 的归约，则 $A$ 的每个继承属性都出现在栈中该归约位置**下方**，从该处即可读取。归约 $\epsilon$ 到 $M$ 时直接在下方找到 $A.i$。

## 5.6 第 5 章总结

- **属性**：与文法符号关联的数据值。$X.a$ 表示文法符号 $X$ 的属性 $a$。
- **综合属性**：仅依赖 $X$ 本身或其子结点的属性。**继承属性**：依赖 $X$ 本身、$X$ 的父结点或兄弟结点的属性。
- **S 属性 SDD**：所有属性都是综合属性的 SDD，可在**语法分析树的后序遍历**中求值（自底向上分析等价）。
- **L 属性 SDD**：所有继承属性只使用「上边或左边」信息的 SDD，可由自顶向下分析或（配合转换）自底向上分析实现。
- **注释语法分析树**：满足所有语义规则的带属性值的语法分析树。**循环定义**的 SDD 无注释语法分析树。
- **依赖图 + 拓扑排序**：无环 ⇒ 存在拓扑排序（反复删除无前驱结点）。S 属性 SDD 的求值顺序即依赖图的拓扑序。
- **受控副作用**：如 `print(E.val)` 可视为**与产生式头相关的哑综合属性**。
- **AST 构造**：`Leaf(op, val)`、`Node(op, c_1..c_k)`；只在**非平凡产生式**上建结点。
- **SDT**：产生式体中嵌入语义动作的文法。**后缀 SDT** 的动作全在产生式末端（LR + S 属性）。**内嵌动作 SDT** 需按前序遍历执行。
- **消除左递归时的动作处理**：把动作当作终结符号；带综合属性时用 $R.i$（继承）+ $R.s$（综合）组合。
- **L 属性 → SDT**：继承属性动作放在 $A$ **出现之前**，综合属性动作放在**产生式最右端**。
- **边扫描边生成代码**：主属性是综合属性、按产生式体中符号顺序连接 → 可打印代替构造长串。
- **实现能力包含关系**：$\text{LR} \supset \text{LL}$，$\text{L 属性} \supset \text{S 属性}$。

> **口诀**：**S 属性下传后序遍历，L 属性上左前序处理**；**综合拷贝靠栈顶，继承拷贝靠父栈**；**消除左递归，把动作当终结符号**；**边扫描边生成，主属性必为综合**。
