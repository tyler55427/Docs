# 二、ER 模型
## 2.1 实体与属性

### 实体
- **实体**：用属性描述区分相同实体的不同实例
- **实体集**：包含相同类型的实体（相同属性，不同属性集）

### 属性类型

| 类型 | 说明 |
|:---:|:---|
| 简单属性 | 单值 |
| 复合属性 | 属性由子属性组成 |
| 多值属性 | 有多个属性值 |
| 派生属性 | 根据其他属性计算出来 |

## 2.2 键

- **键(Key)**：唯一指引一个实体实例，可以是一个属性或属性集合
- **复合键**：key 包含多属性
- **候选键**：最短的 key（包含最少的必要属性，任意删去就不再是主键）
- **主键(Primary Key)**：候选键的一个

## 2.3 弱实体与强实体

- **强实体**：能由自带的属性唯一索引
- **弱实体**：不能由自带的属性唯一索引，一定有一个依赖的强实体
  - 与强实体 key 组合为 key
  - 弱实体对应的属性为 partial key
  - 强实体 own 弱实体

## 2.4 关系

- **关系**：描述多个实体之间的联系
- **关系的度**：关系连接的实体个数（一般为 2）
- **二元关系**：连接两个实体集合
- **递归关系**：相同类型实体的关系，用角色标识区分

## 2.5 约束

### ① 基数约束
最多可以关联多少对方实体：
- **1-1**：都行
- **1-多**：选多为候选键
- **多-1**
- **多-多**：只能组合

### ② 参与约束
至少关联一个实体：
- **全部参与**：实体集中的每个实体至少有一种关联关系
- **部分参与**：实体集中的每个实体可能存在关系

## 2.6 层次/继承

- 将实体分成多个类，一个类的属性对另一个没有
- 子类继承父类的属性
- **重叠约束(overlap)**：实体可以同时作为两种子类
- **不相交约束(disjoint)**：实体只能作为子类的一种

## 2.7 ER 设计流程

1. 确定实体
2. 确定属性
3. 找到主键
4. 确定关系
5. n 对 m 确定
6. 完全参与确定
