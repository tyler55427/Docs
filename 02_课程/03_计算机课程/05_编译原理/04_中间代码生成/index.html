    6.1 语法树的变体¶

    6.1.1 表达式的有向无环图¶

    和语法树类似，DAG 的叶子对应原子运算分量、内部结点对应运算符。与语法树的区别：如果结点 \(N\) 表示一个公共子表达式，则 \(N\) 可能有多个父结点。语法树中公共子表达式每出现一次就复制一次子树；DAG 更简洁，且为高效代码生成提供信息。

    例 6.1 表达式 \(a + a * (b - c) + (b - c) * d\) 的 DAG（图 6-3）：叶子 \(a\) 有两个父结点；结点 \(-\) 代表 \(b - c\) 的两次出现，也有两个父结点。\(b\)、\(c\) 虽出现两次但只有一个父结点——因为对它们的使用都出现在同一个 \(b - c\) 中。

    图 6-4 构造语法树或 DAG 的 SDD（同例 5.11）：

    产生式 语义规则
    1) \(E \rightarrow E_1 + T\) E.node = new Node('+', E_1.node, T.node)
    2) \(E \rightarrow E_1 - T\) E.node = new Node('-', E_1.node, T.node)
    3) \(E \rightarrow T\) / \(T \rightarrow T_1 * F\) E.node = T.node / T.node = new Node('*', T_1.node, F.node)
    4) \(T \rightarrow (E)\) T.node = E.node
    5) \(T \rightarrow id\) T.node = new Leaf(id, id.entry)
    6) \(T \rightarrow num\) T.node = new Leaf(num, num.val)

    构造 DAG 时，Leaf 和 Node 在每次构造前先检查是否已存在相同结点，存在则返回已有结点。

    6.1.2 构造 DAG 的值编码方法¶

    结点存放在记录数组中（图 6-6）。每行是一个结点：第一字段是运算符代码（标号），叶子有附加字段存放标识符词法值，内部结点有两个字段指明左右子结点。用整数下标引用结点，该整数称为值编码（value number）。

    算法 6.3 构造 DAG 的结点的值编码方法：

    • 输入：标号 \(op\)、结点 \(l\) 和 \(r\)。
    • 输出：具有三元组 \(\langle op, l, r \rangle\) 形式的结点的值编码。
    • 方法：在数组中搜索标号为 \(op\)、左子为 \(l\)、右子为 \(r\) 的结点 \(M\)。存在则返回 \(M\) 的值编码；不存在则添加新结点 \(N\) 并返回其值编码。

    算法 6.3 每次搜索整个数组开销大。高效方法：散列表。建立散列函数 \(h(op, l, r)\) 把三元组分配到各"桶"中。桶用链表实现，散列值索引的数组保存桶头。给定 \(\langle op, l, r \rangle\)：① 计算桶索引 \(h(op,l,r)\)；② 在桶链表中搜索匹配结点；③ 找到则返回其值编码，未找到则创建新单元加入该桶并返回新值编码。散列表支持词典（插入/删除/查询）操作，接近常数时间。

    6.2 三地址代码¶

    三地址代码中一条指令的右侧最多有一个运算符。\(x + y * z\) 被翻译成：

    t1 = y * z
t2 = x + t1

    其中 \(t_1\)、\(t_2\) 是编译器产生的临时名字。三地址代码拆分了多运算符表达式与控制流嵌套，适用于目标代码生成与优化（第 8、9 章）。

    6.2.1 地址和指令¶

    地址有三种形式：

    • 名字：源程序名字作为地址（实现中替换为指向符号表条目的指针）
    • 常量：编译器处理不同类型的常量
    • 编译器生成的临时变量：每次需要时产生新名字

    常见的三地址指令形式：

    序号 形式 说明
    1) \(x = y\ op\ z\) 双目算术或逻辑运算
    2) \(x = op\ y\) 单目运算（单目减、逻辑非、类型转换）
    3) \(x = y\) 复制指令
    4) \(\text{goto}\ L\) 无条件转移
    5) \(\text{if } x\ \text{goto } L\) / \(\text{ifFalse } x\ \text{goto } L\) 条件转移
    6) \(\text{if } x\ \text{relop } y\ \text{goto } L\) 关系运算条件转移
    7) \(\text{param } x_1 \dots \text{param } x_n\) / \(\text{call } p, n\) / \(y = \text{call } p, n\) / \(\text{return } y\) 过程调用与返回
    8) \(x = y[i]\) / \(x[i] = y\) 数组下标赋值
    9) \(x = \&y\) / \(x = *y\) / \(*x = y\) 指针赋值

    改变控制流的指令使用符号化标号，每个标号表示指令序列中某条三地址指令的序号。通过一次扫描或回填技术把符号化标号替换为实际指令位置（§6.7）。

    例 6.5 do i = i+1; while (a[i] < v); 的两种翻译（图 6-9，符号标号 a / 位置号 b）：

    L: t1 = i + 1        100: t1 = i + 1
   i = t1            101: i = t1
   t2 = i * 8        102: t2 = i * 8
   t3 = a[t2]        103: t3 = a[t2]
   if t3 < v goto L  104: if t3 < v goto 100

    6.2.2 四元式表示¶

    四元式（quadruple）有四个字段 \(op\)、\(arg_1\)、\(arg_2\)、\(result\)。\(x = y + z\) 的四元式中 \(op\) 为 \(+\)、\(arg_1\) 为 \(y\)、\(arg_2\) 为 \(z\)、\(result\) 为 \(x\)。特例：

    • \(x = \text{minus } y\) 与 \(x = y\) 不使用 \(arg_2\)；赋值 \(x = y\) 的 \(op\) 是 \(=\)
    • param 不使用 \(arg_2\) 也不使用 \(result\)
    • 条件/非条件转移将目标标号放入 \(result\)

    例 6.6 \(a = b * -c + b * -c\) 的三地址代码与四元式（图 6-10）：

    三地址代码              四元式
t1 = minus c            0: minus  c     -     t1
t2 = b * t1             1:   *    b     t1    t2
t3 = minus c            2: minus  c     -     t3
t4 = b * t3             3:   *    b     t3    t4
t5 = t2 + t4            4:   +    t2    t4    t5
a = t5                  5:   =    t5    -     a

    用 minus 表示单目减以区别于双目减 \(-\)。单目减与复制语句 \(a = t_5\) 都只有两个地址。

    6.2.3 三元式表示¶

    三元式（triple）只有三个字段 \(op\)、\(arg_1\)、\(arg_2\)，没有 \(result\) 字段。用运算 \(x\ op\ y\) 的位置表示其结果，而非显式临时名字。例如用位置 (0) 而非 \(t_1\) 引用结果。带括号的数字表示指向相应三元式的指针（即值编码）。

    三元式与 DAG 等价：三元式基本上和算法 6.3 中的结点范型等价，因此表达式的 DAG 表示和三元式表示等价（仅对表达式成立，因控制流表示方式不同）。

    例 6.7（图 6-11）：

    序号 op \(arg_1\) \(arg_2\)
    0 minus c
    1 * b (0)
    2 minus c
    3 * b (2)
    4 + (1) (3)
    5 = a (4)

    复制 \(a = t_5\) 在三元式中：\(arg_1\) 放 \(a\)、\(arg_2\) 放位置值编码 (4)。

    为什么需要复制指令：简单的翻译算法为赋值运算生成复制指令（如 \(t_5 \to a\) 而非直接 \(t_2 + t_4 \to a\)）。每个子表达式都有它自己的新临时变量存放结果，只有处理 \(=\) 时才知道结果赋到哪里。优化阶段会发现 \(t_5\) 可替换为 \(a\)（用 DAG 作为 IR）。

    四元式 vs 三元式：优化编译器中指令位置常变化。四元式移动一条计算 \(t\) 的指令时，使用 \(t\) 的指令无需改变。三元式通过位置引用结果，改变位置则引用它的所有指令都要修改。间接三元式解决了这个问题。

    间接三元式（indirect triple）：包含一个指向三元式的指针列表（instruction 数组），而非直接列出三元式序列。优化编译器可通过对 instruction 列表重新排序来移动指令，不影响三元式本身。

    6.2.4 静态单赋值形式¶

    SSA 和三地址代码的区别：

    1. SSA 中所有赋值都针对具有不同名字的变量（"静态单赋值"的由来）——对变量 \(p\)、\(q\) 的每次定值用不同下标区分。
    2. 同一变量可能在两个不同控制流路径中被定值。SSA 用 \(\phi\) 函数合并：
    if (flag) x1 = -1; else x2 = 1;
x3 = phi(x1, x2);

    控制流经过真分支时 \(\phi(x_1, x_2)\) 值为 \(x_1\)；经过假分支时为 \(x_2\)。

    6.4 表达式的翻译¶

    6.4.3 数组元素的寻址¶

    数组元素存储在连续存储空间中。C/Java 中 \(n\) 个元素编号 \(0, 1, \dots, n-1\)，每个元素宽度 \(w\)。\(A[i]\) 的地址：

    \[base + i \times w \qquad (6.2)\]

    二维数组 \(A[i_1][i_2]\)（按行存放，一行宽度 \(w_1\)，元素宽度 \(w_2\)）：

    \[base + i_1 \times w_1 + i_2 \times w_2 \qquad (6.3)\]

    \(k\) 维数组：

    \[base + i_1 \times w_1 + i_2 \times w_2 + \cdots + i_k \times w_k \qquad (6.4)\]

    另一种计算方式（用第 \(j\) 维元素个数 \(n_j\) 与元素宽度 \(w = w_k\)）。二维：

    \[base + (i_1 \times n_2 + i_2) \times w \qquad (6.5)\]

    \(k\) 维（与式 6.4 结果相同）：

    \[base + ((\cdots((i_1 \times n_2 + i_2) \times n_3 + i_3)\cdots) \times n_k + i_k) \times w \qquad (6.6)\]

    下标不从 0 开始时（\(low, low+1, \dots, high\)，\(base\) 是 \(A[low]\) 的相对地址）：

    \[base + (i - low) \times w \qquad (6.7)\]

    式 (6.2) 和 (6.7) 都可改写成 \(i \times w + c\)，其中 \(c = base - low \times w\) 可在编译时刻预先计算并存入 \(A\) 的符号表条目。当数组大小动态变化时无法预先计算，需运行时按公式求值。

    按行存放 vs 按列存放：C 系列按行存放（扫描时最右下标变化最频繁，如里程表数字）；Fortran 系列按列存放（最左下标变化最频繁）。

    6.4.4 数组引用的翻译¶

    非终结符号 \(L\) 生成数组名加下标表达式序列：\(L \rightarrow L[E] \mid id[E]\)。使用式 (6.4) 基于宽度计算相对地址。

    图 6-22 处理数组引用的语义动作（关键产生式）：

    S -> id = E ;       { gen(top.get(id.lexeme) '=' E.addr); }
S -> L = E ;        { gen(L.array.base '[' L.addr ']' '=' E.addr); }
E -> E1 + E2        { E.addr = new Temp();
                      gen(E.addr '=' E1.addr '+' E2.addr); }
E -> id             { E.addr = top.get(id.lexeme); }
E -> L              { E.addr = newTemp();
                      gen(E.addr '=' L.array.base '[' L.addr ']'); }
L -> id [ E ]       { L.array = top.get(id.lexeme);
                      L.type  = L.array.type.elem;
                      L.addr  = newTemp();
                      gen(L.addr '=' E.addr '*' L.type.width); }
L -> L1 [ E ]       { L.array = L1.array;
                      L.type  = L1.type.elem;
                      t = newTemp();
                      L.addr  = newTemp();
                      gen(t '=' E.addr '*' L.type.width);
                      gen(L.addr '=' L1.addr '+' t); }

    非终结符号 \(L\) 的三个综合属性：

    1. \(L.\text{addr}\)：临时变量，用于累加公式 (6.4) 中的 \(i_j \times w_j\) 项（偏移量）。
    2. \(L.\text{array}\)：指向数组名对应符号表条目的指针。基地址 \(L.\text{array.base}\) 用于确定数组引用的实际左值。
    3. \(L.\text{type}\)：\(L\) 生成的子数组的类型。对类型 \(t\)，\(t.\text{width}\) 给出宽度；对数组类型 \(t\)，\(t.\text{elem}\) 给出元素类型。

    例 6.12 \(a\) 是 \(2 \times 3\) 整数数组（类型 \(\text{array}(2, \text{array}(3, \text{integer}))\)），整数宽 4，\(a\) 的宽度 24。\(a[i]\) 类型 \(\text{array}(3, \text{integer})\)，宽度 \(w_1 = 12\)。表达式 \(c + a[i][j]\) 翻译为三地址代码（图 6-24）。

    符号化表示的类型宽度：中间代码应相对独立于目标机器。用符号常量代替整数类型宽度 4 即可使翻译方案不依赖机器字长（如 Pascal 的 P-code 让代码生成器填写元素大小）。

    6.5 类型检查¶

    编译器给源程序每个组成部分赋予类型表达式，确定是否满足一组逻辑规则（类型系统）。健全的类型系统可消除动态类型检查的需要；若编译器能保证程序运行时不会发生类型错误，则该语言实现是强类型的。

    6.5.1 类型检查规则¶

    类型检查有两种形式：

    • 类型综合（type synthesis）：根据子表达式的类型构造表达式的类型，要求名字先声明再使用。典型规则：
    \[\text{if } f \text{ 的类型为 } s \to t \text{ 且 } x \text{ 的类型为 } s\text{，then 表达式 } f(x) \text{ 的类型为 } t \tag{6.8}\]

    \(s \to t\) 表示从 \(s\) 到 \(t\) 的函数。可推广到多参数函数；\(E_1 + E_2\) 可看作 \(\text{add}(E_1, E_2)\)。

    • 类型推导（type inference）：根据使用方式确定类型。用希腊字母 \(\alpha\)、\(\beta\) 等作为类型变量表示未知类型。典型规则：
    \[\text{if } f(x) \text{ 是表达式，then 对某些 } \alpha \text{ 和 } \beta\text{，} f \text{ 的类型为 } \alpha \to \beta \text{ 且 } x \text{ 的类型为 } \alpha \tag{6.9}\]

    ML 这样的语言需要类型推导（检查类型但不要求声明名字）。

    6.5.2 类型转换¶

    \(x + i\) 中 \(x\) 为 float、\(i\) 为 int 时，编译器要把某个运算分量转换成相同类型。用单目运算符 (float) 将整数转换成浮点数：

    t1 = (float) 2
t2 = t1 * 3.14

    引入属性 \(E.\text{type}\)（值为 integer 或 float），\(E \rightarrow E_1 + E_2\) 的规则（图 6-27）：

    E -> E1 + E2 {
    E.type = max(E1.type, E2.type);
    a1 = widen(E1.addr, E1.type, E.type);
    a2 = widen(E2.addr, E2.type, E.type);
    E.addr = new Temp();
    gen(E.addr = a1 + a2);
}

    两个函数：

    • \(\max(t_1, t_2)\)：返回拓宽层次结构中两个类型的最大者（最小上界）。某类型不在层次结构中（如数组、指针）则返回错误。
    • \(\text{widen}(a, t, w)\)：若 \(t = w\) 返回 \(a\) 本身；否则生成转换指令把类型 \(t\) 的地址 \(a\) 转成 \(w\) 类型，结果放临时变量返回。

    图 6-26 widen 函数：

    Addr widen(Addr a, Type t, Type w) {
    if (t == w) return a;
    else if (t == integer and w == float) {
        temp = new Temp();
        gen(temp = '(float)' a);
        return temp;
    }
    else error;
}
    • 拓宽转换：保持原有信息（char → int → long → float → double）。
    • 窄化转换：可能丢失信息。如果存在从 \(s\) 到 \(t\) 的路径则可窄化。
    • 隐式转换（自动类型转换 coercion）：编译器自动完成，很多语言仅限拓宽转换。
    • 显式转换（强制类型转换 cast）：程序员写代码引发。

    6.5.3 函数和运算符的重载¶

    被重载的符号依据上下文有不同含义。若仅查看函数参数就能确定唯一含义，则重载问题可解决（如 Java）。例 6.13：Java 的 + 既是字符串连接也是加法；err() 与 err(String s) 是重载函数。

    值编码方法可用于类型表达式，根据参数类型高效解决重载：在类型表达式的 DAG 上给每个结点赋值编码，函数的范围由函数名和参数类型组成，基于范围解决重载。若仅看参数类型不能解决（如 Ada 子表达式有一组可能类型），需上下文缩小范围。

    6.5.4 类型推导和多态函数¶

    例 6.14 函数 length 用 fun 引入，null 测试列表是否为空，tl 返回列表余下部分。\(\text{length}([\text{"sun"}, \text{"mon"}, \text{"tue"}]) + \text{length}([10, 9, 8, 7]) = 3 + 4 = 7\)。

    length 的多态类型：

    \[\forall \alpha.\ \text{list}(\alpha) \to \text{integer} \tag{6.12}\]

    \(\forall\) 是全称量词，所作用的类型变量称为受限的，可任意重命名。带 \(\forall\) 的类型表达式称为多态类型。

    6.6 控制流¶

    6.6.1 布尔表达式¶

    文法 \(B \to B \| B \mid B\ \&\&\ B \mid !\ B \mid (B) \mid E\ \text{rel}\ E \mid \text{true} \mid \text{false}\)。\(\|\) 和 \(\&\&\) 左结合，\(\|\) 优先级最低，其次 \(\&\&\)，再其次 \(!\)。关系表达式 \(E_1\ \text{rel}\ E_2\) 中 rel.op 指明 6 种比较运算之一。

    给定 \(B_1 \| B_2\)，若 \(B_1\) 为真则不用计算 \(B_2\) 即可断定整个表达式为真；\(B_1\ \&\&\ B_2\) 中若 \(B_1\) 为假则整个为假。

    6.6.2 短路代码¶

    短路（跳转）代码中布尔运算符 \(\&\&\)、\(\|\)、\(!\) 被翻译成跳转指令，运算符本身不出现在代码中，布尔表达式的值通过代码序列中的位置表示。

    例 6.21 if (x < 100 || x > 200 && x != y) x = 0;（图 6-34）：

    if x < 100 goto L2
ifFalse x > 200 goto L1
ifFalse x != y goto L1
L2: x = 0
L1:

    \(P.\text{code} = S.\text{code} \;\|\; \text{label}(S.\text{next})\)

    \(B.\text{false} = \text{newlabel}()\)
    \(S_1.\text{next} = S_2.\text{next} = S.\text{next}\)

    6.6.4 布尔表达式的控制流翻译¶

    图 6-37 为布尔表达式生成三地址代码：

    产生式 语义规则
    \(B \rightarrow B_1 \| B_2\) \(B_1.\text{true} = B.\text{true}\)
    \(B_1.\text{false} = \text{newlabel}()\)
    \(B_2.\text{true} = B.\text{true}\)
    \(B_2.\text{false} = B.\text{false}\)
    \(B.\text{code} = B_1.\text{code} \;\|\; \text{label}(B_1.\text{false}) \;\|\; B_2.\text{code}\)
    \(B \rightarrow B_1\ \&\&\ B_2\) \(B_1.\text{true} = \text{newlabel}()\)
    \(B_1.\text{false} = B.\text{false}\)
    \(B_2.\text{true} = B.\text{true}\)
    \(B_2.\text{false} = B.\text{false}\)
    \(B.\text{code} = B_1.\text{code} \;\|\; \text{label}(B_1.\text{true}) \;\|\; B_2.\text{code}\)
    \(B \rightarrow !\ B_1\) \(B_1.\text{true} = B.\text{false}\)
    \(B_1.\text{false} = B.\text{true}\)
    \(B.\text{code} = B_1.\text{code}\)
    \(B \rightarrow E_1\ \text{rel}\ E_2\) \(B.\text{code} = E_1.\text{code} \;\|\; E_2.\text{code} \;\|\; \text{gen}(\text{'if'}\ E_1.\text{addr}\ \text{rel.op}\ E_2.\text{addr}\ \text{'goto'}\ B.\text{true}) \;\|\; \text{gen}(\text{'goto'}\ B.\text{false})\)
    \(B \rightarrow \text{true}\) \(B.\text{code} = \text{gen}(\text{'goto'}\ B.\text{true})\)
    \(B \rightarrow \text{false}\) \(B.\text{code} = \text{gen}(\text{'goto'}\ B.\text{false})\)
    • \(B_1 \| B_2\)：\(B_1\) 为真则 \(B\) 为真（\(B_1.\text{true} = B.\text{true}\)）；\(B_1\) 为假则计算 \(B_2\)（\(B_1.\text{false}\) 为 \(B_2\) 代码首条指令标号）。
    • \(B_1\ \&\&\ B_2\)：\(B_1\) 为假则 \(B\) 为假；\(B_1\) 为真则计算 \(B_2\)。
    • \(!\ B_1\)：对换真假出口。
    • \(E_1\ \text{rel}\ E_2\)：翻译成 if E1.addr rel.op E2.addr goto B.true 加 goto B.false。
    • true/false：直接 goto B.true/goto B.false。

    例 6.22 if (x < 100 || x > 200 && x != y) x = 0; 用图 6-36/6-37 翻译（图 6-38）：

        if x < 100 goto L2
    goto L3
L3: if x > 200 goto L4
    goto L1
L4: if x != y goto L2
    goto L1
L2: x = 0

    生成的代码不是最优的——比短路代码多 3 条 goto。goto L3 冗余（L3 是下一条指令），用 ifFalse 可消除两条 goto L1。

    6.6.5 避免生成多余的 goto 指令¶

    利用控制流在指令序列中自然流动的性质，用特殊标号 fall（"不要生成跳转指令"）修改语义规则。\(S \rightarrow \text{if}(B)S_1\) 中令 \(B.\text{true} = \text{fall}\)，控制流从 \(B\) 代码直接穿越到 \(S_1\) 代码。

    \(B \rightarrow E_1\ \text{rel}\ E_2\) 的修改：若 \(B.\text{true}\)、\(B.\text{false}\) 都是显式标号则产生两条指令；若 \(B.\text{true}\) 是显式、\(B.\text{false}\) 是 fall 则产生一条 if 指令（条件为假时穿越）；若 \(B.\text{false}\) 是显式、\(B.\text{true}\) 是 fall 则产生一条 ifFalse 指令；若都是 fall 则不产生跳转指令。

    6.7 回填¶

    6.7.1 使用回填技术的一趟式目标代码生成¶

    为布尔表达式和控制流语句生成代码的关键问题：把跳转指令和目标匹配。如 if (B) S 中 \(B\) 的翻译包含一条跳转指令——当 \(B\) 为假时跳到 \(S\) 代码之后。但一趟式翻译中 \(B\) 必须在 \(S\) 之前翻译完，此时跳过 \(S\) 的 goto 目标是什么？

    §6.6 的方法把标号作为继承属性传递，但要求再进行一趟处理把标号和地址绑定。回填技术在一趟扫描中完成：先生成跳转指令但目标留空，记录这些指令到列表中，等目标确定后回填。

    三个关键函数：

    • makelist(i)：创建一个仅含 \(i\)（指令序号）的新列表，返回指向它的指针。
    • merge(p1, p2)：合并两个列表，返回合并后的指针。
    • backpatch(p, i)：把列表 \(p\) 中每条指令的目标填为 \(i\)。

    6.7.2 布尔表达式的回填¶

    非终结符号 \(B\) 有综合属性 \(B.\text{truelist}\) 和 \(B.\text{falselist}\)——分别指向 \(B\) 代码中需要回填真/假出口的跳转指令列表。标记非终结符号 \(M\) 记录下一条指令序号 \(M.\text{instr}\)（\(M \rightarrow \epsilon\ \{ M.\text{instr} = \text{nextinstr}; \}\)）。

    图 6-43 布尔表达式的回填翻译方案：

    序号 产生式 语义动作
    (1) \(B \rightarrow B_1\ \|\ M\ B_2\) { backpatch(B1.falselist, M.instr); B.truelist = merge(B1.truelist, B2.truelist); B.falselist = B2.falselist; }
    (2) \(B \rightarrow B_1\ \&\&\ M\ B_2\) { backpatch(B1.truelist, M.instr); B.truelist = B2.truelist; B.falselist = merge(B1.falselist, B2.falselist); }
    (3) \(B \rightarrow !\ B_1\) { B.truelist = B1.falselist; B.falselist = B1.truelist; }
    (4) \(B \rightarrow (B_1)\) { B.truelist = B1.truelist; B.falselist = B1.falselist; }
    (5) \(B \rightarrow E_1\ \text{rel}\ E_2\) { B.truelist = makelist(nextinstr); B.falselist = makelist(nextinstr+1); gen('if' E1.addr rel.op E2.addr 'goto' _); gen('goto' _); }
    \(M \rightarrow \epsilon\) { M.instr = nextinstr; }
    • (1) \(B_1 \| B_2\)：\(B_1\) 为假时跳到 \(B_2\) 开始处，故 backpatch(B1.falselist, M.instr)；\(B\) 的真出口 = \(B_1\) 真出口 ∪ \(B_2\) 真出口。
    • (2) \(B_1\ \&\&\ B_2\)：\(B_1\) 为真时跳到 \(B_2\) 开始处，故 backpatch(B1.truelist, M.instr)；\(B\) 的假出口 = \(B_1\) 假出口 ∪ \(B_2\) 假出口。
    • (5) 关系表达式生成两条目标为空的指令，分别放入 truelist 和 falselist。

    例 6.24 \(x < 100\ \|\ x > 200\ \&\&\ x \neq y\)（图 6-44、6-45）。从 100 开始编号：

    100: if x < 100 goto -       (归约 x<100 为 B)
101: goto -
102: if x > 200 goto -       (归约 x>200 为 B)
103: goto -
104: if x != y goto -         (归约 x!=y 为 B)
105: goto -

    归约 \(B \rightarrow B_1\ \&\&\ M\ B_2\)（\(B_1 = x > 200\)，\(M.\text{instr} = 104\)）：backpatch({102}, 104) → 指令 102 填入 104。归约 \(B \rightarrow B_1\ \|\ M\ B_2\)（\(B_1 = x < 100\)，\(M.\text{instr} = 102\)）：backpatch({101}, 102) → 指令 101 填入 102。最终 \(B.\text{truelist} = \{100, 104\}\)、\(B.\text{falselist} = \{103, 105\}\)。

    6.7.3 控制转移语句¶

    语句 \(S\) 和语句列表 \(L\) 有属性 \(\text{nextlist}\)——所有跳转到紧跟其后的指令的跳转指令列表。

    图 6-46 语句的回填翻译方案：

    序号 产生式 语义动作
    (1) \(S \rightarrow \text{if}(B)\ M\ S_1\) { backpatch(B.truelist, M.instr); S.nextlist = merge(B.falselist, S1.nextlist); }
    (2) \(S \rightarrow \text{if}(B)\ M_1\ S_1\ N\ \text{else}\ M_2\ S_2\) { backpatch(B.truelist, M1.instr); backpatch(B.falselist, M2.instr); temp = merge(S1.nextlist, N.nextlist); S.nextlist = merge(temp, S2.nextlist); }
    (3) \(S \rightarrow \text{while}\ M_1(B)\ M_2\ S_1\) { backpatch(S1.nextlist, M1.instr); backpatch(B.truelist, M2.instr); S.nextlist = B.falselist; gen('goto' M1.instr); }
    (4) \(S \rightarrow \{L\}\) { S.nextlist = L.nextlist; }
    (5) \(S \rightarrow A;\) { S.nextlist = null; }
    (6) \(M \rightarrow \epsilon\) { M.instr = nextinstr; }
    (7) \(N \rightarrow \epsilon\) { N.nextlist = makelist(nextinstr); gen('goto' _); }
    (8) \(L \rightarrow L_1\ M\ S\) { backpatch(L1.nextlist, M.instr); L.nextlist = S.nextlist; }
    (9) \(L \rightarrow S\) { L.nextlist = S.nextlist; }
    • (2) if-else：\(B\) 为真跳到 \(S_1\) 开始（\(M_1.\text{instr}\)），\(B\) 为假跳到 \(S_2\) 开始（\(M_2.\text{instr}\)）。\(N\) 产生 goto _ 跳过 \(S_2\)（\(S_1\) 执行完后越过 \(S_2\)）。\(S.\text{nextlist}\) = \(S_1\)、\(N\)、\(S_2\) 的所有跳出指令。
    • (3) while：\(S_1.\text{nextlist}\) 回填为循环开始 \(M_1.\text{instr}\)；\(B.\text{truelist}\) 回填为 \(S_1\) 开始 \(M_2.\text{instr}\)；生成 goto M1.instr 跳回循环头；\(S.\text{nextlist} = B.\text{falselist}\)（\(B\) 为假时跳出）。
    • (8) 语句序列：\(L_1.\text{nextlist}\) 回填为 \(S\) 开始 \(M.\text{instr}\)。

    关键点：除 (3) 和 (7) 外，这些语义规则不产生新指令——所有代码都由赋值和表达式相关动作产生。回填正确连接了控制流。

    6.7.4 break 语句、continue 语句和 goto 语句¶

    • goto L：将标号 \(L\) 和具体位置绑定，通常用符号表实现。
    • break：跳转到外围循环语句 \(S\) 代码之后第一条指令。步骤：① 跟踪外围循环语句 \(S\)；② 为 break 生成未完成的跳转指令；③ 放入 \(S.\text{nextlist}\) 中，最终回填。可在符号表中设指向 \(S.\text{nextlist}\) 的指针。
    • continue：类似 break，跳转到循环条件判断处。

    6.8 switch 语句¶

    语法（图 6-48）：

    switch (E) {
  case V1: S1
  case V2: S2
  ...
  case Vn-1: Sn-1
  default: Sn
}

    6.8.1 switch 语句的翻译¶

    预期翻译结果：① 计算 \(E\) 值；② 在 case 列表中找匹配值 \(V_j\)；③ 执行 \(S_j\)。步骤②是 \(n\) 路分支：

    • case 数目少（≤10）：用条件跳转指令序列，每个测试一个常量值并跳转。
    • 用对照关系表：每个条目含常量值和语句代码标号，表达式值与默认标号放末端，生成循环逐个比较。
    • 值超过 10 个：构造散列表，条目是分支语句标号。
    • 特殊情况：值在小范围内（\(\min\) 到 \(\max\)，且不同值总数接近 \(\max - \min\)）时构造 \(\max - \min\) 个"桶"的数组，桶 \(j - \min\) 含对应值 \(j\) 的标号，空桶含默认标号。表达式为字符型时可创建 128 个条目的表不进行范围检查。

    图 6-49（测试在代码末端，便于代码生成器识别多路分支）：

        goto test

        goto next

        ...

    图 6-50（分支在开始位置，需更深入分析，一趟式编译器不便生成）：

        if t != V1 goto L1
        code for S1
        goto next

    翻译过程：看到 switch 时生成标号 test、next 和临时变量 \(t\)；处理 \(E\) 时生成计算代码并存入 \(t\)；之后产生 goto test。看到 case 时创建标号 \(L_i\) 并在 case 队列放入值-标号对，处理 \(S_i\) 生成代码并加 goto next。到达 switch 末端时读取队列生成 \(n\) 路分支。

    6.9 过程的中间代码¶

    在三地址代码中，函数调用被拆分为参数求值和调用本身（假定值传递）。

    例 6.25 \(n = f(a[i])\)（\(a\) 是整数数组，\(f\) 从整数到整数）：

    1) t1 = i * 4
2) t2 = a[t1]
3) param t2
4) t3 = call f, 1
5) n = t3

    call p, n 中的 \(n\) 是实在参数个数（非冗余，因存在嵌套调用——前面 param 可能属于 \(p\) 返回后才执行的调用）。函数调用的文法（图 6-52）：define 关键字引入函数定义，形参由 \(F\) 生成，实参由 \(A\) 生成。

    类型检查：函数和运算符处理方法相同，§6.5.2 的类型检查规则（含自动类型转换）仍可用。如 \(f\) 是带一个实型参数的函数，调用 \(f(2)\) 时整数 2 被转换成实型。

    6.10 第 6 章总结¶

    • DAG：语法树的变体，公共子表达式只建一个结点。Leaf/Node 先检查已有结点再创建。值编码是结点的整数下标，可用散列表高效查找。
    • 三地址代码：右侧最多一个运算符。地址有名字、常量、临时变量三种。9 种常见指令形式。
    • 四元式（\(op, arg_1, arg_2, result\)）/ 三元式（无 \(result\)，用位置表示结果，与 DAG 等价）/ 间接三元式（指针列表，可重排不影响三元式）。
    • SSA：所有赋值针对不同名字的变量，用 \(\phi\) 函数合并不同控制流路径的定值。
    • 数组寻址：式 (6.2)–(6.7)，\(c = base - low \times w\) 可编译时刻预先计算。按行存放（C）/按列存放（Fortran）。
    • 类型检查：类型综合（先声明后使用）与类型推导（用类型变量，不需声明）。\(\max\) 与 \(\text{widen}\) 处理类型转换；拓宽 vs 窄化；隐式 vs 显式。重载用值编码解决。
    • 控制流：短路代码把布尔运算符翻译成跳转。\(B.\text{true}\)/\(B.\text{false}\) 为真假出口，\(S.\text{next}\) 为后继指令标号。fall 标号避免多余 goto。
    • 回填技术：makelist/merge/backpatch 三函数，一趟扫描生成代码。\(B.\text{truelist}\)/\(B.\text{falselist}\) 记录待填跳转。\(S.\text{nextlist}\) 记录跳出语句的跳转。break/continue 放入外围循环的 nextlist。
    • switch：测试在末端便于识别多路分支；case t V L 指令；值-标号队列。
    • 过程调用：param + call p, n，\(n\) 为实参个数。

    口诀：DAG 查重靠值编码，三地址右侧一运算符；四元式有 result 可移动，三元式靠位置省临时；回填三函数：建表 makelist、合并 merge、填目标 backpatch；短路代码真假出口，fall 标号穿越省 goto；switch 测试放末端，case 指令易识别。
