    词法分析¶

    对应教材：第 3 章「词法分析」（PDF p84–p136）。术语沿用笔记原文：正则表达式、正则定义、状态转换图、NFA/DFA、有穷自动机。

    核心缩写¶

    缩写 全称 中文 作用
    RE Regular Expression 正则表达式 描述单词模式，如 [0-9]+ 匹配数字串
    RA Regular Automaton 有穷自动机 词法分析的理论模型，处理字符流
    NFA Nondeterministic Finite Automaton 不确定有穷自动机 边上标号无限制（可 \(\epsilon\)），通过子集构造法转为 DFA
    DFA Deterministic Finite Automaton 确定有穷自动机 每状态每符号恰一条出边、无 \(\epsilon\) 转换，可进行最小化

    词法分析阶段的作用¶

    词法分析是编译的第一阶段。词法分析器的主要任务是读入源程序的输入字符、将它们组成词素，生成并输出一个词法单元序列，每个词法单元对应于一个词素。这个词法单元序列被输出到语法分析器进行语法分析。词法分析器通常还要和符号表进行交互。

    词法单元、模式和词素¶

    • 词法单元 (token)：由一个词法单元名和一个可选的属性值组成。词法单元名是一个表示某种词法单位的抽象符号。
    • 模式 (pattern)：描述了一个词法单元的词素可能具有的形式。
    • 词素 (lexeme)：源程序中的一个字符序列，它和某个词法单元的模式匹配，并被词法分析器识别为该词法单元的一个实例。

    词法分析器的其他任务¶

    • 过滤掉源程序中的注释和空白字符
    • 将编译器生成的错误消息与源程序的位置联系起来
    • 记录遇到的换行符的个数，以便给每个出错消息赋予一个行号

    词法单元的属性¶

    如果有多个词素可以和一个模式匹配，那么词法分析器必须向编译器的后续阶段提供有关被匹配词素的附加信息。例如，0 和 1 都能和词法单元 number 的模式匹配，但是对于代码生成器而言，至关重要的是要知道在源程序中找到了哪个词素。因此，在很多情况下，词法分析器不仅向语法分析器返回一个词法单元名字，还会返回一个描述该词法单元的词素的属性值。

    最重要的例子是词法单元 id，我们通常会将很多信息和它关联。一般来说，和一个标识符有关的信息——例如它的词素、类型、它第一次出现的位置——都保存在符号表中。因此，一个标识符的属性值是一个指向符号表中该标识符对应条目的指针。

    对于关系运算符，符号常量 LT、LE、EQ、NE、GT、GE 被当作属性值返回，指明发现的是词法单元 relop 的哪个实例——找到的运算符将影响编译器输出的代码。

    输入缓冲¶

    为了判断下一个词素在何处结束，常常需要预先扫描输入字符，因此词法分析器往往需要对输入字符进行缓冲。两项加速技术：

    • 缓冲区对：两个缓冲区循环使用，一个填满时另一个被填满并用于输入。
    • 哨兵标记：在每个缓冲区末尾放置一个特殊字符（如 \0）。这样检查缓冲区末尾只需比较字符是否等于哨兵，不必维护缓冲区长度变量。
    // 图 3-3 缓冲区对 + 哨兵
advance() {
    if (forward == endbuffer1) {
        backbuffer = endbuffer1;   // 当前缓冲区已满
        forward = nextbuffer1;     // 切换到另一缓冲区
        if (forward != nextbuffer2) {
            nextbuffer1 = nextbuffer2;
            nextbuffer2 = backbuffer;
            backbuffer = nextbuffer1;
        }
        fillbuffer();
        endbuffer1 = forward + buffersize - 1;
        *endbuffer1 = '\0';
    }
    return *forward++;
}

    3.3.2 语言上的运算（图 3-6）¶

    运算 定义
    \(L\) 和 \(M\) 的并 \(L \cup M = \{s \mid s \in L \ \text{或} \ s \in M\}\)
    \(L\) 和 \(M\) 的连接 \(LM = \{st \mid s \in L \ \text{且} \ t \in M\}\)
    Kleene 闭包 \(L^* = \bigcup_{i=0}^{\infty} L^i\)
    正闭包 \(L^+ = \bigcup_{i=1}^{\infty} L^i\)

    \(L^0 \equiv \{\epsilon\}\)，\(L^i\) 归纳定义为 \(L^{i-1}L\)。\(L^*\) 与 \(L^+\) 的唯一区别是是否包含 \(L^0\)；除非 \(\epsilon \in L\)，否则 \(\epsilon \notin L^+\)。

    例 3.3 令 \(L\) = 字母集、\(D\) = 数位集（均视为长度为 1 的语言）：

    1. \(L \cup D\) —— 62 个长度为 1 的串
    2. \(LD\) —— 520 个长度为 2 的串（字母后跟数位）
    3. \(L^4\) —— 所有 4 字母串
    4. \(L^*\) —— 所有由字母构成的串（含 \(\epsilon\)）
    5. \(L(L \cup D)^*\) —— 以字母开头、由字母和数位组成（C 标识符，C 还允许下划线）
    6. \(D^+\) —— 一个或多个数位

    3.3.3 正则表达式（归纳定义）¶

    对 \(\Sigma\) 上的正则表达式 \(r\)，其语言 \(L(r)\) 递归定义：

    归纳基础 1. \(\epsilon\) 是正则表达式，\(L(\epsilon) = \{\epsilon\}\) 2. 若 \(a \in \Sigma\)，则 \(\mathbf{a}\) 是正则表达式，\(L(\mathbf{a}) = \{a\}\)

    惯例：斜体表示符号，粗体表示它所对应的正则表达式。

    归纳步骤（\(r, s\) 为正则表达式时） 1. \((r) \mid (s)\) —— 语言 \(L(r) \cup L(s)\) 2. \((r)(s)\) —— 语言 \(L(r)L(s)\) 3. \((r)^*\) —— 语言 \((L(r))^*\) 4. \((r)\) —— 语言 \(L(r)\)（加括号不改变语言）

    优先级约定（可省略不必要括号）

    1. 一元运算符 \(*\) 优先级最高，左结合
    2. 连接次高，左结合
    3. \(\mid\) 最低，左结合

    例：\((\mathbf{a}) \mid ((\mathbf{b})^*(\mathbf{c}))\) 可写作 \(\mathbf{a} \mid \mathbf{b}^* \mathbf{c}\)。

    例 3.4 \(\Sigma = \{a, b\}\)

    1. \(\mathbf{a} \mid \mathbf{b}\) → \(\{a, b\}\)
    2. \((\mathbf{a} \mid \mathbf{b})(\mathbf{a} \mid \mathbf{b})\) → \(\{aa, ab, ba, bb\}\)
    3. \(\mathbf{a}^*\) → \(\{\epsilon, a, aa, aaa, \cdots\}\)
    4. \((\mathbf{a} \mid \mathbf{b})^*\) → 所有由 \(a, b\) 构成的串；等价表达式 \((\mathbf{a}^* \mathbf{b}^*)^*\)
    5. \(\mathbf{a} \mid \mathbf{a}^* \mathbf{b}\) → \(\{a, b, ab, aab, aaab, \cdots\}\)

    能用正则表达式定义的语言称为正则集合（regular set）。两个正则表达式表示同一语言则称等价，记 \(r = s\)。

    图 3-7 正则表达式的代数定律

    定律 描述
    \(r \mid s = s \mid r\) \(\mid\) 可交换
    \(r \mid (s \mid t) = (r \mid s) \mid t\) \(\mid\) 可结合
    \(r(st) = (rs)t\) 连接可结合
    \(r(s \mid t) = rs \mid rt\)；\((s \mid t)r = sr \mid tr\) 连接对 \(\mid\) 可分配
    \(\epsilon r = r \epsilon = r\) \(\epsilon\) 是连接的单位元
    \(r^* = (r \mid \epsilon)^*\) 闭包中一定包含 \(\epsilon\)
    \(r^{**} = r^*\) \(*\) 幂等

    3.3.4 正则定义¶

    正则定义（regular definition）是形如 d → r 的定义序列，d 表示正则表达式的名字（变量），可用已定义过的变量：

    digit  → [0-9]
digits → digit+
number → digits ( "." digits )? ( E [ + | - ]? digits )?
letter → [A-Za-z]
id     → letter ( letter | digit )*
ws     → ( blank | tab | newline )+
    • 正则定义 vs 上下文无关文法：文法的右端可包含非终结符出现在任意位置；正则定义的限制是右端只能是终结符与"名字"的串接，且名字只能出现在右端。
    • 正则定义的变量必须在使用前定义，且不能循环引用。
    • 字符类写法：[a-z]、[^-]（补集）、[a-zA-Z]。

    状态转换图¶

    状态转换图（transition diagram）是构造词法分析器的中间步骤：把模式转成特定风格的流图，结点为状态、边为转换。与 NFA 转换图的区别：有穷自动机是识别器（对每个输入串只回答是/否），而状态转换图带动作。

    图 3-14 是 C 风格输入的状态转换图（12 个状态），要点： - 状态 0：起始，识别 0x 前缀 - 状态 10：字母状态（可能读到关键字或标识符前缀） - 状态 11：已确定是标识符 - 状态 12：关键字 if，需向前看下一个字符是否为字母（否则回退）

    3.6 有穷自动机¶

    有穷自动机与状态转换图类似，但有区别： 1. 是识别器，只能回答"是/否" 2. 分两类： - NFA：边上的标号无限制；同一状态的多条边可用同一符号标号；\(\epsilon\) 也可作标号 - DFA：对每个状态及输入字母表中每个符号，有且只有一条离开该状态、以该符号为标号的边

    核心结论：确定和不确定的有穷自动机识别的语言集合相同，且正好是能用正则表达式描述的语言集合，即正则语言（regular language）。

    NFA 的五元组¶

    1. 有穷状态集 \(S\)
    2. 输入符号集 \(\Sigma\)（\(\epsilon \notin \Sigma\)）
    3. 转换函数：为每个状态和 \(\Sigma \cup \{\epsilon\}\) 中每个符号给出后继状态集合
    4. 开始状态 \(s_0 \in S\)
    5. 接受状态集 \(F \subseteq S\)

    接受：NFA 接受串 \(x\)，当且仅当存在一条从开始状态到某接受状态的路径，使路径上各边标号组成串 \(x\)（\(\epsilon\) 标号在连接时"消失"）。只要存在一条到达接受状态的路径即接受——存在到达非接受状态的路径不影响结论。

    \(L(A)\) 表示自动机 \(A\) 接受的语言。

    例 3.14 \((a|b)^*abb\) 的 NFA（状态 0–3，状态 3 为双圈接受态）：从状态 0 到达接受状态的所有路径都先在 0 上运行一段时间，再读 \(abb\) 依次进入 1、2、3，故所有接受串都以 \(abb\) 结尾。

    3.6.4 DFA 与算法 3.18¶

    DFA 是 NFA 的特例：① 无 \(\epsilon\) 转换；② 每状态每符号恰一条出边。用转换表表示时每个表项就是一个状态（不必写花括号）。

    算法 3.18 模拟一个 DFA（输入：以 eof 结尾的串 \(x\)）

    s = s0;
c = nextChar();
while (c != eof) {
    s = move(s, c);
    c = nextChar();
}
return s in F;

    3.7 NFA 的等价转换¶

    算法 3.20 子集构造法（NFA → DFA）¶

    输入：NFA \(N\)（开始状态 \(s_0\)，接受态集 \(F\)，转换函数 \(move\)） 输出：DFA \(D\)，接受同一语言

    1) Dstates = { ε-closure(s0) }   // D 的状态就是 N 状态的集合
2) 标记 Dstates 中各状态
3) while ( Dstates 中存在未标记状态 T ) {
4)     标记 T;
5)     for (每个输入符号 a) {
6)         let U = ε-closure(move(T, a));
7)         if (U 不在 Dstates 中) 将 U 作为未标记状态加入 Dstates;
8)         Dtran[T, a] = U;
9)     }
10) }
11) D 的开始状态是 ε-closure(s0)，接受态是包含 N 中接受态的状态
    • \(\varepsilon\text{-closure}(s)\)：从 \(s\) 出发只经 \(\epsilon\) 边可达的状态集（含 \(s\) 自身）
    • \(\varepsilon\text{-closure}(T) = \bigcup_{s \in T} \varepsilon\text{-closure}(s)\)
    • \(move(T, a)\)：从 \(T\) 中各状态在输入 \(a\) 上可达的状态集（忽略 \(\epsilon\) 转换）

    例 3.21 对 \((a|b)^*abb\)（图 3-34，11 个 NFA 状态）：开始状态 \(A = \varepsilon\text{-closure}(0) = \{0,1,2,4,7\}\)，共构造出 5 个 DFA 状态。

    NFA 状态 DFA \(a\) \(b\)
    \(\{0,1,2,4,7\}\) \(A\) \(B\) \(C\)
    \(\{1,2,3,4,6,7,8\}\) \(B\) \(B\) \(D\)
    \(\{1,2,4,5,6,7\}\) \(C\) \(B\) \(C\)
    \(\{1,2,4,5,6,7,9\}\) \(D\) \(B\) \(E\)
    \(\{1,2,4,5,6,7,10\}\) \(E\) \(B\) \(C\)

    \(E\) 是唯二接受态。注意 \(A\) 与 \(C\) 转换函数相同，可合并（见 3.9.6 最小化）。最坏情况下状态数指数增长为 \(2^n\)，但常见程序设计语言中尚未碰到这种情况。

    算法 3.22 模拟 NFA¶

    不必真的构造 DFA，可直接模拟状态集：

    1) S = ε-closure(s0);
2) c = nextChar();
3) while (c != eof) {
4)     S = ε-closure(move(S, c));
5)     c = nextChar();
6) }
7) if (S ∩ F ≠ ∅) return "yes";  else return "no";

    NFA 模拟的效率（3.7.3）¶

    数据结构：① 两个栈 oldStates/newStates（分别存当前与下一个状态集）；② 布尔数组 alreadyOn[s]（同栈信息，但查询远快于栈）；③ 二维数组 move[s,a]，表项用链表表示。

    // 图 3-38 加入一个不在 newStates 中的新状态 s
addState(s) {
    将 s 压入栈 newStates;
    alreadyOn[s] = TRUE;
    for (t on move[s, ε])
        if (!alreadyOn[t]) addState(t);
}

    复杂度：一次 addState 调用对每个状态最多发生一次（alreadyOn 保证），addState 的总代价 \(O(n + m)\)（\(n\) = 状态数，\(m\) = 转换数）。故算法 3.22 第 4 行为 \(O(n+m)\)，若输入长 \(k\)，总时间 \(O(k(n+m))\)。

    大 O 表示法：\(O(n)\) 表示"最多某个常数乘以 \(n\)"；\(O(1)\) 表示"某个常量"。

    3.7.4 算法 3.23：正则表达式 → NFA（McNaughton–Yamada–Thompson）¶

    对 \(r\) 进行语法分析，沿抽象语法树自底向上递归构造；每个子表达式构造只有单个接受状态的 NFA。

    基本规则 - \(\epsilon\)：\(\text{start} \to i \xrightarrow{\epsilon} f\) - \(a\)：\(\text{start} \to i \xrightarrow{a} f\)

    归纳规则（\(N(s)\)、\(N(t)\) 已构造） 1. \(r = s \mid t\)：新增 \(i, f\)；从 \(i\) 到 \(N(s)\)、\(N(t)\) 的开始态各一 \(\epsilon\) 边，两者接受态各连一 \(\epsilon\) 边到 \(f\) 2. \(r = st\)：\(N(s)\) 的开始态成为 \(N(r)\) 的开始态；\(N(t)\) 的接受态成为 \(N(r)\) 的唯一接受态；\(N(s)\) 的接受态与 \(N(t)\) 的开始态合并为一个状态 3. \(r = s^*\)：新增 \(i, f\)；\(i \xrightarrow{\epsilon}\) 到 \(N(s)\) 开始态，\(N(s)\) 接受态 \(\xrightarrow{\epsilon}\) 回 \(N(s)\) 开始态并到 \(f\)；\(i \xrightarrow{\epsilon}\) 直达 \(f\) 4. \(r = (s)\)：直接用 \(N(s)\)

    构造所得 NFA 的性质： 1. 状态数 ≤ 2 ×（运算符 + 运算分量总数）——每步最多引入 2 个新状态 2. 有且只有一个开始状态和一个接受状态；接受态无出边，开始态无入边 3. 除接受态外每个状态要么有一条标号为 \(\Sigma\) 中符号的出边，要么有两条标号为 \(\epsilon\) 的出边

    例 3.24：为 \((a|b)^*abb\) 构造 NFA。

    3.8.2 基于 NFA 的模式匹配¶

    对应多个模式 \(p_1, p_2, \dots, p_n\)（各带动作 \(A_i\)）构造单个 NFA：新增开始态 0 与接受态 11，从 0 到各 \(N(p_i)\) 开始态、各接受态到 11 均为 \(\epsilon\) 边。处理流程： 1. 从 lexemeBegin 开始读入，按算法 3.22 维护状态集 2. 到达没有后续状态的输入点时（此后状态集一直为空），判定最长前缀 3. 沿状态集序列向后找第一个含接受状态的集合；若有多个接受状态，选与位置最靠前的模式相关联的那个，把 forward 移回词素末尾并执行对应动作

    例 3.27（模式 a、abb、a*b+，输入 aaba）：状态集序列为 \(\{0,1,3,7\} \to \{2,4,7\} \to \{7\} \to \{8\} \to\) 空。读入 a 后状态集含 2（匹配 a）；读入 aab 后到 8（匹配 a*b+），aab 是最长前缀，故选它并执行 \(A_3\)。

    3.8.3 词法分析器用的 DFA：改用子集构造法生成 DFA，若某 DFA 状态含多个模式的接受态，取先列出的那个模式作为该状态的输出。

    DFA 中的死状态：从技术讲，省略了到达死状态 \(\emptyset\) 的转换的自动机并非真正的 DFA。但词法分析器必须知道"什么时候已不可能识别更长的词素"，故建议省略到达死状态的转换并消除死状态本身；消失的转换作为"结束词素识别"的信号。若用算法 3.20 + 3.23 构造 DFA，除 \(\emptyset\) 外所有状态都能到达某个接受态。

    3.8.4 向前看运算符 r₁/r₂：把 / 视为 \(\epsilon\)，实际上不在输入中查找 /。词素末尾是最后一次进入满足如下条件的状态 \(s\) 之处：① \(s\) 在假想的 / 上有 \(\epsilon\) 转换；② 从开始态到 \(s\) 的路径标号为 \(x\)；③ 从 \(s\) 到接受态的路径标号为 \(y\)；④ 在所有满足 ①–③ 的 \(xy\) 中 \(x\) 尽可能长。若 NFA 只有一个这样的状态，则词素末尾就在最后一次进入该状态之处（例 3.30：关键字 IF，状态 6 表明 IF 出现，但需回扫到最晚出现的状态 2 才是词素起点）。

    3.9 DFA 模式匹配器的优化¶

    三个算法：① 由正则表达式直接构造 DFA（不经 NFA，且状态更少）；② 合并具有相同未来行为的状态使 DFA 状态数最少，时间 \(O(n \log n)\)；③ 生成比二维表更紧凑的转换表表示。

    3.9.1 NFA 的重要状态¶

    若 NFA 状态有一个标号非 \(\epsilon\) 的离开转换，则称它是重要状态（important state）。子集构造法计算 \(\varepsilon\text{-closure}(move(T,a))\) 时只使用 \(T\) 中的重要状态——只有 \(s\) 重要时 \(move(s,a)\) 才可能非空。两个 NFA 状态集可视为一致，当且仅当： 1. 具有相同的重要状态，且 2. 要么都包含接受状态，要么都不包含

    对算法 3.23 生成的 NFA，重要状态只包括基础规则为某符号位置引入的初始状态——每个重要状态对应正则表达式中的某个运算分量。可以在 \(r\) 右端连接独特结束标记 \(\#\)（扩展正则式 \((r)\#\)），使接受状态增加一条标号为 \(\#\) 的出边，从而变为重要状态。

    3.9.2–3.9.4 四个函数（基于 \((r)\#\) 的抽象语法树）¶

    函数 含义
    nullable(n) 结点 \(n\) 代表的子表达式语言是否含 \(\epsilon\)
    firstpos(n) 以 \(n\) 为根的子表达式语言中某个串的第一个符号对应的位置集合
    lastpos(n) 同上，但为最后一个符号
    followpos(p) 位置 \(p\) 之后可能紧跟的位置集合：存在 \(x = a_1\cdots a_n \in L((r)\#)\)，可把某 \(a_i\) 匹配到 \(p\)、\(a_{i+1}\) 匹配到 \(q\)

    图 3-58 计算 nullable 和 firstpos 的规则

    结点 \(n\) nullable(n) firstpos(n)
    标号为 \(\epsilon\) 的叶子 true \(\emptyset\)
    位置为 \(i\) 的叶子 false \(\{i\}\)
    or 结点 \(n = c_1 \mid c_2\) nullable(c₁) or nullable(c₂) firstpos(c₁) ∪ firstpos(c₂)
    cat 结点 \(n = c_1 c_2\) nullable(c₁) and nullable(c₂) 若 nullable(c₁)：firstpos(c₁) ∪ firstpos(c₂)；否则 firstpos(c₁)
    star 结点 \(n = c_1^*\) true firstpos(c₁)

    lastpos 的规则与 firstpos 相同，但 cat 结点中子结点角标对调。

    followpos 的两条规则： 1. \(n\) 是 cat 结点，子结点 \(c_1, c_2\)：对 lastpos(c₁) 中每个位置 \(i\)，firstpos(c₂) 中所有位置都在 followpos(i) 中 2. \(n\) 是 star 结点，\(i \in\) lastpos(n)：firstpos(n) 中所有位置都在 followpos(i) 中

    例：\((a|b)^*abb\#\) 的 followpos 为 1→\(\{1,2,3\}\)、2→\(\{1,2,3\}\)、3→\(\{4\}\)、4→\(\{5\}\)、5→\(\{6\}\)、6→\(\emptyset\)。

    表示 followpos 的有向图（\(j \in\) followpos(i) ⟺ 边 \(i \to j\)）几乎就是相应的不含 \(\epsilon\) 转换的 NFA：① 根结点的 firstpos 设为开始状态；② 边 \(i \to j\) 上标注位置 \(i\) 的符号；③ 与结束标记 \(\#\) 相关的位置作为唯一接受态。

    3.9.5 算法 3.36：正则表达式 → DFA（直接构造）¶

    初始化 Dstates 只包含未标记状态 firstpos(n₀)，n₀ 为 (r)# 的根结点；
while ( Dstates 中存在未标记状态 S ) {
    标记 S;
    for (每个输入符号 a) {
        令 U 为 S 中和 a 对应的所有位置 p 的 followpos(p) 的并集;
        if (U 不在 Dstates 中) 将 U 作为未标记状态加入 Dstates;
        Dtran[S, a] = U;
    }
}

    \(D\) 的状态就是 \(T\) 中的位置集合；开始状态 \(\text{firstpos}(n_0)\)；接受态是包含 \(\#\) 位置的状态。

    例 3.37：\(r = (a|b)^*abb\)。根 firstpos = \(\{1,2,3\}\) 为开始态 \(A\)；其中 1、3 对应 \(a\)，2 对应 \(b\)： - \(Dtran[A,a] = \text{followpos}(1) \cup \text{followpos}(3) = \{1,2,3,4\}\) - \(Dtran[A,b] = \text{followpos}(2) = \{1,2,3\} = A\)（无需新增）

    所得 4 状态 DFA 即图 3-65 的最少状态 DFA。

    3.9.6 算法 3.39：DFA 最小化¶

    同构：仅改状态名字即可互相转换。

    区分：若从 \(s\)、\(t\) 出发沿标号 \(x\) 的路径到达的两个状态中只有一个是接受状态，则串 \(x\) 区分 \(s\) 与 \(t\)。存在这样的串则称两状态可区分。

    例 3.38：空串 \(\epsilon\) 可区分任何接受态与非接受态；在图 3-36 中串 \(bb\) 区分 \(A\) 与 \(B\)（\(A \xrightarrow{bb} C\) 非接受，\(B \xrightarrow{bb} E\) 接受）。

    重要结论：任何正则语言都有一个唯一（不计同构）的状态数最少的 DFA。 可从任意接受同语言的 DFA 出发，通过分组合并等价状态构造得到它。

    算法 3.39 最小化一个 DFA 的状态数量

    1. 构造初始划分 \(\Pi = \{F,\ S-F\}\)（接受组 / 非接受组）
    2. 构造新划分 \(\Pi_{new}\)：
    最初，令 Π_new = Π;
for (Π 中的每个组 G) {
    将 G 划分为更小的组，使得两个状态 s 和 t 在同一小组中
    当且仅当对于所有输入符号 a，s 和 t 在 a 上的转换都到达 Π 中的同一小组;
    /* 最坏情况：每个状态自成一组 */
    在 Π_new 中将 G 替换为划分得到的小组;
}
    1. 若 \(\Pi_{new} = \Pi\) 则 \(\Pi_{final} = \Pi\)，转步骤 4；否则用 \(\Pi_{new}\) 替换 \(\Pi\)，重复步骤 2
    2. 在 \(\Pi_{final}\) 每个组中取一个代表，代表们构成最少 DFA \(D'\) 的状态：
    3. ④ \(D'\) 的开始态是包含 \(D\) 开始态的组的代表
    4. ⑤ \(D'\) 的接受态是包含 \(D\) 接受态的组的代表（每组内同性质，因初始就分开了且后续只做分解）
    5. ⑥ 设 \(s\) 是组 \(G\) 的代表，\(D\) 中 \(s\) 在 \(a\) 上到达 \(t\)，\(r\) 为 \(t\) 所在组 \(H\) 的代表，则 \(D'\) 中有 \(s \xrightarrow{a} r\)

    例 3.40 逐步划分（图 3-36，5 状态）：

    轮次 划分 原因
    初始 \(\{A,B,C,D\} \| \{E\}\) 非接受 / 接受
    1 \(\{A,B,C\} \| \{D\} \| \{E\}\) \(b\)：\(D \to E\)（另一组），其余 \(\to\) 组内
    2 \(\{A,C\} \| \{B\} \| \{D\} \| \{E\}\) \(b\)：\(B \to D\)（另一组），\(A,C \to\) 组内
    3（收敛） \(\{A,C\} \| \{B\} \| \{D\} \| \{E\}\) \(A,C\) 在所有输入上进入同一状态

    取代表 \(A, B, D, E\)（\(A\) 开始，\(E\) 唯一接受）：

    状态 \(a\) \(b\)
    \(A\) \(B\) \(A\)
    \(B\) \(B\) \(D\)
    \(D\) \(B\) \(E\)
    \(E\) \(B\) \(A\)

    例 3.38 中 \(\epsilon\) 区分接受/非接受，\(bb\) 区分 \(A,B\) —— 这就是划分的第一刀和第二刀的依据。

    3.9.7 词法分析器的状态最小化¶

    必须用不同的初始划分：把识别某个特定词法单元的所有状态放入对应词法单元的一组，所有不识别任何词法单元的状态放入另一组。

    例 3.41（图 3-54，三个词法单元）：初始划分 $\(\{0137,\ 7\}\ \ \{247\}\ \ \{8,\ 58\}\ \ \{68\}\ \ \{\varnothing\}\)$ - 0137 与 7 同组：都不识别任何词法单元 - 8 与 58 同组：都识别 \(a^*b^+\) - 特意添加死状态 \(\varnothing\)（在 \(a, b\) 上转到自身），它是 8、58、68 在 \(a\) 上的目标

    0137 与 7 在 \(a\) 上转到不同组 → 分开；8 与 58 在 \(b\) 上转到不同组 → 分开。所有状态自成一组，故图 3-54 已是状态最少 DFA。

    3.9.8 DFA 模拟中的时间和空间权衡¶

    • 二维数组（状态 × 字符）最简单最快：数百状态 × 128 字符 < 1 MB
    • 转换链表：每状态一个字符-状态对链表，末尾放默认状态（链表未出现的字符都去这里）——省空间
    • base/next/check/default 四数组（图 3-66，兼具两者优点）：
    int nextState(int s, int a) {
    if (check[base[s] + a] == s) return next[base[s] + a];
    else return nextState(default[s], a);
}

    利用状态之间的相似性缩短 next-check 数组。例：状态 \(s\)（读到字母 th 后，可能是关键字 then 前缀也可能是标识符前缀）的默认状态 \(t\) 是"正在处理一个标识符"的状态；只有当输入 e 时 \(s\) 才需去一个特殊状态（记住已看到 the）。赋值 check[base[s]+e] = s（确认条目有效）、next[base[s]+e] = 特殊状态、default[s] = t。

    base 值的经验策略：按顺序把 base 值赋给各状态，base[s] 取最小的、能使状态 \(s\) 所有特殊条目位置都尚未被占用的值。所需空间只比最小可能值多一点点。

    3.10 第 3 章总结¶

    • 词法单元 / 词素：词法分析器扫描源程序输出词法单元序列，逐个传给语法分析器。有些词法单元只有名字，其他还有关联的词法值。每次返回词法单元时都有关联词素。
    • 缓冲技术：循环缓冲区对 + 哨兵标记。
    • 模式 / 正则表达式 / 正则定义：正则表达式由单字符经并、连接、Kleene 闭包构造；正则定义是变量序列，定义变量时可引用已定义变量。
    • 扩展正则表达式：\(+\)（一个或多个）、\(?\)（零个或一个）、字符类 []。
    • 状态转换图 / 有穷自动机：自动机是状态转换图的形式化表示，指明开始状态、接受状态、状态集、输入字符集、转换集合。自动机既可以在输入字符上转换，也可以在空输入上转换（状态转换图不行）。
    • DFA / NFA：DFA 每状态每符号恰一个转换、不允许空输入转换，模拟容易，适合作实现基础。NFA 通常更易设计；另一体系架构为每模式各配 NFA，用表格记录扫描输入时可能进入的所有状态。
    • 模式表示方法间的转换：任意正则表达式 ↔ 大小基本相同的 NFA；任意 NFA → DFA（最坏指数增长，但常见语言中未遇到）；任意自动机 → 正则表达式。
    • Lex / Flex：用扩展正则表达式描述模式，生成器实质是识别所有模式的 DFA。
    • 最小化：每个 DFA 都有接受同语言的最少状态 DFA；给定语言的最少状态 DFA（不计同构）唯一。
